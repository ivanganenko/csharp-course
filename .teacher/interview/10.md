# Interview: модуль 10 — Делегаты, события, лямбды

### 1. Что такое делегат?
**Уровень:** junior
**Хороший ответ:** Типобезопасная ссылка на метод. Объявление `delegate` создаёт класс-наследник `MulticastDelegate`; экземпляр хранит `Target` (объект, у которого вызывается метод, или null для static) и `Method`. Позволяет передать поведение как параметр: callbacks, стратегии, LINQ-предикаты, события. Компилятор проверяет совместимость сигнатуры.
**Глубже (для junior+):** делегаты immutable; `+=` создаёт новый объект. Вызов — через сгенерированный метод `Invoke`. Есть ковариантность возвращаемого типа и контравариантность параметров при преобразовании method group.
**Follow-up:**
- «Чем делегат отличается от интерфейса с одним методом?» — легче (не нужен класс), multicast, но не может иметь состояние/несколько методов и хуже документирует намерение.
- «Чем отличается от указателя на функцию в C?» — типобезопасность, хранит target, multicast.
**Красные флаги:** «делегат — это то же, что событие»; не знает, что делегат хранит ссылку на объект.

### 2. Func, Action, Predicate — разница?
**Уровень:** junior
**Хороший ответ:** Готовые generic-делегаты. `Action<T…>` — без результата, `Func<T…, TResult>` — с результатом, который указывается последним параметром типа, `Predicate<T>` — `T → bool`. Используются, чтобы не объявлять свой тип делегата. Свой делегат нужен для `ref/out`-параметров или выразительного имени (`RequestHandler`).
**Follow-up:**
- «Можно ли `Func<int, bool>` присвоить `Predicate<int>`?» — нет, разные типы; обернуть лямбдой.
- «Сколько параметров у `Func` максимум?» — 16 входных.
**Красные флаги:** путает порядок параметров типа `Func`.

### 3. Что такое multicast-делегат? Что вернёт его вызов?
**Уровень:** junior
**Хороший ответ:** Делегат со списком методов (`+=`/`-=`). Вызываются по порядку, синхронно. Возвращается результат последнего метода. Исключение в одном методе прерывает вызов остальных. Чтобы получить все результаты или изолировать исключения, перебирают `GetInvocationList()`.
**Follow-up:**
- «Как сделать, чтобы падение одного подписчика не мешало остальным?» — перебрать invocation list с try/catch на каждый.
**Красные флаги:** «вернёт массив результатов».

### 4. Чем event отличается от делегата?
**Уровень:** junior
**Хороший ответ:** Event — член класса поверх поля-делегата, который снаружи даёт только `+=` и `-=` (аксессоры `add`/`remove`). Вызвать событие или присвоить ему значение может только класс-владелец. С публичным полем-делегатом любой код может сделать `= null` (стереть всех подписчиков) или вызвать его. Event — это инкапсуляция.
**Глубже (для junior+):** можно объявить свои `add`/`remove` (например, хранить подписчиков в `EventHandlerList` или weak references). Field-like event в C# генерирует потокобезопасные add/remove через `Interlocked.CompareExchange`.
**Follow-up:**
- «Какой стандартный паттерн событий?» — `EventHandler<TEventArgs>`, `(object? sender, TEventArgs e)`, `protected virtual OnXxx`.
- «Почему `?.Invoke`?» — нет подписчиков → null; читается один раз — без гонки.
**Красные флаги:** «event — это просто делегат с другим синтаксисом»; не знает про ограничение доступа.

### 5. Что такое замыкание? Как оно реализовано?
**Уровень:** junior / junior+
**Хороший ответ:** Лямбда, использующая переменные внешней области видимости. Захватывается переменная, а не значение. Компилятор создаёт скрытый класс (display class), переносит туда захваченные переменные как поля, а лямбду делает его методом. Переменная живёт столько, сколько делегат.
**Глубже (для junior+):** замыкание = аллокация display class + делегата; `static`-лямбды запрещают захват. Захват `this` в лямбде продлевает жизнь всего объекта (утечки в событиях и кэшах).
**Follow-up:**
- «Где живёт захваченная локальная переменная — на стеке или в куче?» — в куче, в поле display class.
**Красные флаги:** «лямбда копирует значения переменных».

### 6. Что выведет код?
```csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
    actions.Add(() => Console.Write(i));
foreach (var item in new[] { 10, 20 })
    actions.Add(() => Console.Write(item));
foreach (var a in actions) a();
```
**Уровень:** junior
**Хороший ответ:** `3331020`. В `for` переменная `i` одна на весь цикл, после него равна 3 — три лямбды печатают 3. В `foreach` с C# 5 переменная своя на каждой итерации — печатаются 10 и 20.
**Follow-up:**
- «Как исправить `for`?» — `int copy = i;` в теле цикла.
- «Почему для foreach поменяли поведение в C# 5?» — все ошибались; breaking change признан оправданным.
**Красные флаги:** `012...` без объяснения или неуверенность в разнице for/foreach.

### 7. Как события приводят к утечкам памяти? Как избежать?
**Уровень:** junior+
**Хороший ответ:** Подписка `publisher.E += subscriber.Handler` кладёт в publisher делегат со ссылкой на subscriber. Пока publisher достижим (singleton, static, долгоживущий сервис), subscriber не будет собран GC. Решение — отписка: «подписался в конструкторе — отписался в Dispose»; для отписки нужен тот же делегат (method group или сохранённая лямбда). Специальные случаи — weak event pattern.
**Follow-up:**
- «А если subscriber живёт дольше publisher-а — есть утечка?» — нет: ссылка идёт от publisher к subscriber.
- «Сработает ли `-= (s, e) => ...`?» — нет, это другой делегат.
**Красные флаги:** «GC сам всё уберёт»; думает, что ссылка идёт от subscriber к publisher.

### 8. Почему события возвращают void? Как подписчику «ответить»?
**Уровень:** junior+
**Хороший ответ:** Подписчиков много, а multicast вернул бы только последний результат — это неоднозначно. Поэтому по соглашению void. Ответ передают через изменяемые EventArgs: `CancelEventArgs.Cancel = true`, `HandledEventArgs.Handled`.
**Красные флаги:** не знает про multicast-семантику результата.

### 9. Лямбда vs анонимный метод vs method group
**Уровень:** junior
**Хороший ответ:** Анонимный метод — синтаксис C# 2 (`delegate (int x) { return x * 2; }`); лямбда — C# 3, короче (`x => x * 2`), может стать expression tree (`Expression<Func<...>>` — используется в EF Core, модуль 16). Method group — имя существующего метода (`list.ForEach(Console.WriteLine)`). Все превращаются в делегат.
**Follow-up:**
- «Чем `Func<int, int>` отличается от `Expression<Func<int, int>>`?» — первое — исполняемый код, второе — дерево выражения (данные), которое можно разобрать и перевести в SQL.
**Красные флаги:** не знает, что лямбда превращается в метод.

### 10. Как реализовать observer pattern в C#?
**Уровень:** junior
**Хороший ответ:** Встроенно — через события: subject объявляет `event EventHandler<TArgs>`, observers подписываются. Альтернативы — `IObservable<T>/IObserver<T>` (Rx), свой event bus. Важны: отписка, порядок вызова, обработка исключений подписчиков, потокобезопасность.
**Follow-up:**
- «Чем event bus отличается от событий?» — издатель и подписчик не знают друг о друге, только тип сообщения.
**Красные флаги:** не может связать события с паттерном observer.

### 11. Live coding: напиши свой Where
```csharp
// Реализуй extension-метод MyWhere, аналог LINQ Where.
```
**Уровень:** junior
**Хороший ответ:**
```csharp
public static IEnumerable<T> MyWhere<T>(this IEnumerable<T> source, Func<T, bool> predicate)
{
    ArgumentNullException.ThrowIfNull(source);
    ArgumentNullException.ThrowIfNull(predicate);
    return Iterator(source, predicate);

    static IEnumerable<T> Iterator(IEnumerable<T> s, Func<T, bool> p)
    {
        foreach (var item in s)
            if (p(item)) yield return item;
    }
}
```
Обсуждение: ленивость через `yield`, жадная проверка аргументов, extension method.
**Follow-up:**
- «Что будет, если проверки поставить в итератор?» — исключение при переборе, а не при вызове.
- «Как добавить индекс, как у `Where((x, i) => ...)`?» — `Func<T, int, bool>` и счётчик.
**Красные флаги:** возвращает `List<T>` и не видит разницы; не знает `yield`.

### 12. Live coding: middleware-конвейер (junior+)
```csharp
// Дан delegate void Handler(Context c). Напиши функцию Compose(IList<Func<Handler, Handler>> middlewares, Handler terminal),
// возвращающую обработчик, в котором первый middleware — внешний.
```
**Уровень:** junior+
**Хороший ответ:**
```csharp
static Handler Compose(IList<Func<Handler, Handler>> middlewares, Handler terminal)
{
    Handler app = terminal;
    for (int i = middlewares.Count - 1; i >= 0; i--)
        app = middlewares[i](app);
    return app;
}
```
Обсуждение: сборка с конца, замыкание на `next`, short-circuit, аналогия с ASP.NET Core и Decorator.
**Follow-up:**
- «Где разместить middleware обработки ошибок?» — первым (внешним), чтобы ловить исключения всех последующих.
**Красные флаги:** сборка с начала без понимания порядка.
