# Интервью: модуль 06 — struct, record и равенство

### 1. Чем struct отличается от class?
**Уровень:** junior
**Хороший ответ:** Struct — value type: переменная содержит данные, при присваивании и передаче копируется целиком; не может быть null (кроме `Nullable<T>`); не наследуется (только интерфейсы); всегда есть `default` со всеми нулями. Class — reference type: объект в куче, переменная хранит ссылку. Struct не создаёт нагрузки на GC, если не упакован. Используют для маленьких неизменяемых значений.
**Глубже (для junior+):** где реально живёт struct (стек / внутри объекта / в массиве); boxing при приведении к object/интерфейсу; `ref struct` (`Span<T>`) — только на стеке.
**Follow-up:**
- «Можно ли в struct объявить конструктор без параметров?» → с C# 10 да, но `default(S)` и `new S[10]` его не вызывают.
- «Struct может реализовать интерфейс?» → да, но приведение к интерфейсу упаковывает.
**Красные флаги:** «struct всегда на стеке, class всегда в куче» без оговорок; «struct быстрее всегда».

### 2. Когда выбрать struct, а когда class?
**Уровень:** junior
**Хороший ответ:** Struct — если тип маленький (до ~16 байт), логически одно значение (координата, деньги, цвет), неизменяемый и не будет часто упаковываться. Иначе class. Выигрыш struct — меньше аллокаций (массив struct — один объект), проигрыш — копирование при каждой передаче и риски mutable struct.
**Follow-up:**
- «Почему `DateTime` — struct, а `string` — class?» → DateTime маленький (8 байт); строка переменной длины и может быть большой.
**Красные флаги:** «struct для всех DTO ради скорости».

### 3. Что выведет код?
```csharp
var points = new List<P> { new P { X = 1 } };
foreach (var p in points) p.Move();
points[0].Move();
Console.WriteLine(points[0].X);

struct P { public int X; public void Move() => X++; }
```
**Уровень:** junior+
**Хороший ответ:** `1`. Переменная `foreach` — копия элемента; индексатор `List<T>` возвращает копию. Оба `Move()` меняют копии. Компилятор пропускает вызов методов на копиях, но запретил бы `points[0].X = 5` (CS1612). Лечение — immutable struct (`readonly struct`) или «копия → изменение → запись обратно».
**Follow-up:**
- «А с массивом `P[]`?» → `arr[0].Move()` изменит элемент (элемент массива — переменная); `foreach` — всё равно нет.
**Красные флаги:** `3`, «будет ошибка компиляции».

### 4. Зачем нужен GetHashCode? Какой у него контракт?
**Уровень:** junior
**Хороший ответ:** Хэш используется хэш-таблицами (`Dictionary`, `HashSet`, LINQ `GroupBy`/`Distinct`) для выбора бакета; внутри бакета сравнение идёт через `Equals`. Контракт: если `a.Equals(b)`, то хэши равны; хэш стабилен, пока объект не меняется; разные объекты могут иметь одинаковый хэш (коллизии), но хороший хэш их минимизирует. Переопределяешь Equals — переопредели GetHashCode на тех же полях.
**Глубже (для junior+):** рандомизация хэша строк между запусками процесса (нельзя хранить string.GetHashCode в БД); `HashCode.Combine`; деградация до O(n) при плохом хэше.
**Follow-up:**
- «Что будет, если GetHashCode всегда возвращает 0?» → корректно по контракту, но все элементы в одном бакете — поиск O(n).
- «А если возвращает случайное число?» → нарушение контракта, словарь не находит элементы.
**Красные флаги:** «GetHashCode — уникальный идентификатор объекта».

### 5. Что будет, если переопределить Equals без GetHashCode?
**Уровень:** junior
**Хороший ответ:** Компилятор выдаст warning CS0659. Остальной код будет работать, но в хэш-коллекциях равные объекты будут иметь разные хэши (по умолчанию — от «идентичности» объекта), попадать в разные бакеты, и `Contains`/`ContainsKey` вернут false, `Distinct` не удалит дубликаты.
**Follow-up:**
- «А наоборот — GetHashCode без Equals?» → хэши равны, но Equals по ссылке → тоже не найдёт.
**Красные флаги:** «ничего страшного, это только warning».

### 6. Чем `==` отличается от `Equals`?
**Уровень:** junior
**Хороший ответ:** `Equals` — виртуальный метод, выбирается в runtime по типу объекта. `==` — статический оператор, перегрузка выбирается компилятором по статическим типам. Для классов без перегрузки `==` сравнивает ссылки; для struct `==` не определён; string и records перегружают `==` для сравнения значений. В generic-коде `==` для `T` без ограничений недоступен, используют `EqualityComparer<T>.Default.Equals`.
**Follow-up:**
- «`object a = "x"; object b = new string('x', 1); a == b`?» → false: для object выбран ссылочный `==`.
**Красные флаги:** «это одно и то же».

### 7. Что такое record? Что генерирует компилятор?
**Уровень:** junior
**Хороший ответ:** Record — тип для данных. Компилятор генерирует: `Equals(object)`, `Equals(R)` (`IEquatable<R>`), `GetHashCode`, `==`/`!=` по значениям всех полей, `ToString` с именами свойств (через `PrintMembers`), `Deconstruct` для positional records, конструктор копирования для `with`, свойство `EqualityContract` (для учёта типа при наследовании). Positional record class даёт `init`-свойства.
**Глубже (для junior+):** records могут наследоваться только от records; `EqualityContract` делает `Base` и `Derived` с одинаковыми полями неравными.
**Follow-up:**
- «Record — immutable?» → по умолчанию свойства positional record class — `init`, но можно объявить `set`, а внутри могут быть изменяемые коллекции. Неглубокая неизменяемость.
**Красные флаги:** «record — это struct».

### 8. record class vs record struct vs readonly record struct
**Уровень:** junior+
**Хороший ответ:** `record class` — reference type, positional-свойства `init`. `record struct` — value type, positional-свойства `get; set;` (изменяемые!). `readonly record struct` — value type с `init`-свойствами, неизменяемый. Для маленьких value objects (Money, Point) — `readonly record struct`; для DTO — `record class`.
**Follow-up:**
- «Почему record struct изменяемый по умолчанию?» → для согласованности с tuples и обычными struct; неизменяемость включается `readonly`.
**Красные флаги:** не знает о `record struct`.

### 9. Что делает `with`? Что выведет код?
```csharp
var a = new Order(1, new List<string> { "pen" });
var b = a with { Id = 2 };
b.Items.Add("book");
Console.WriteLine($"{a.Items.Count} {a == b}");
record Order(int Id, List<string> Items);
```
**Уровень:** junior+
**Хороший ответ:** `2 False`. `with` делает поверхностную копию: `Items` — тот же список, поэтому добавление через `b` видно в `a`. Записи не равны, потому что `Id` разный. Для независимой копии нужно `a with { Items = new List<string>(a.Items) }`; лучше хранить `IReadOnlyList` / immutable коллекцию.
**Красные флаги:** `1 False` (думает, что with копирует глубоко).

### 10. Почему ключ словаря должен быть неизменяемым?
**Уровень:** junior
**Хороший ответ:** Словарь кладёт элемент в бакет по хэшу на момент добавления. Если поле, участвующее в хэше, изменится, поиск пойдёт в другой бакет — элемент станет недоступен по ключу, хотя остаётся в словаре. Поэтому ключи — неизменяемые: string, числа, records с init, readonly struct.
**Красные флаги:** «словарь пересчитает хэш автоматически».

### 11. Что такое `IEquatable<T>` и зачем он struct?
**Уровень:** junior+
**Хороший ответ:** Интерфейс со строго типизированным `Equals(T)`. Для struct без него коллекции вызывают `Equals(object)` → boxing на каждое сравнение, а `ValueType.Equals` по умолчанию может работать через рефлексию. `EqualityComparer<T>.Default` использует `IEquatable<T>`, если тип его реализует.
**Красные флаги:** не знает про boxing.

### 12. Что такое tuple? Чем ValueTuple отличается от Tuple?
**Уровень:** junior
**Хороший ответ:** `ValueTuple` (`(int, string)`) — value type с изменяемыми полями, поддерживает имена элементов (только на этапе компиляции), деконструкцию и `==`. `System.Tuple<T1,T2>` — старый reference type, неизменяемый, с `Item1`/`Item2`, без синтаксиса. Используют `ValueTuple` для возврата нескольких значений из приватных методов; для публичных контрактов — record.
**Красные флаги:** путает с анонимными типами без объяснения разницы.

### 13. Live coding: реализуйте равенство для `DateRange`
**Уровень:** junior
**Задание интервьюера:** «Класс `DateRange` (Start, End — `DateOnly`, Start ≤ End). Сделайте так, чтобы он корректно работал как ключ `Dictionary` и в `HashSet`. Добавьте метод `Overlaps(DateRange other)`».
**Хороший ответ:**
```csharp
public sealed class DateRange : IEquatable<DateRange>
{
    public DateRange(DateOnly start, DateOnly end)
    {
        if (end < start) throw new ArgumentException("End must not be before start.", nameof(end));
        Start = start; End = end;
    }

    public DateOnly Start { get; }
    public DateOnly End { get; }

    public bool Overlaps(DateRange other) => Start <= other.End && other.Start <= End;

    public bool Equals(DateRange? other) => other is not null && Start == other.Start && End == other.End;
    public override bool Equals(object? obj) => obj is DateRange r && Equals(r);
    public override int GetHashCode() => HashCode.Combine(Start, End);
    public static bool operator ==(DateRange? a, DateRange? b) => a is null ? b is null : a.Equals(b);
    public static bool operator !=(DateRange? a, DateRange? b) => !(a == b);
}
```
Интервьюер смотрит: неизменяемость, валидация в конструкторе, полный набор равенства, `is null` в операторе. Отличный ответ: «а проще — `public sealed record DateRange(DateOnly Start, DateOnly End)` с валидацией» или `readonly record struct`.
**Follow-up:**
- «Почему sealed?» → равенство с наследниками нарушает симметричность.
- «Как бы вы сделали это record'ом с валидацией?»
**Красные флаги:** изменяемые свойства; `GetHashCode` не переопределён.

### 14. Что такое defensive copy и `readonly struct`?
**Уровень:** junior+
**Хороший ответ:** Когда метод вызывается на readonly-переменной обычной struct (readonly-поле, `in`-параметр), компилятор не знает, изменит ли метод состояние, и вызывает метод на скрытой копии — defensive copy. Это и лишняя работа, и сюрприз (изменения теряются). `readonly struct` гарантирует неизменяемость, поэтому копия не нужна. Можно также помечать отдельные методы `readonly`.
**Красные флаги:** «readonly struct — то же, что const».
