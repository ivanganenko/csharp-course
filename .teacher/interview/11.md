# Interview: модуль 11 — LINQ

### 1. Что такое LINQ и как он устроен?
**Уровень:** junior
**Хороший ответ:** Language Integrated Query — набор extension methods (`System.Linq.Enumerable` для `IEnumerable<T>`, `Queryable` для `IQueryable<T>`) и синтаксис запросов в языке. Операторы принимают последовательность и делегаты (лямбды) и возвращают новую последовательность или значение. Большинство реализовано через итераторы (`yield`), поэтому выполняются лениво. Query syntax компилируется в вызовы тех же методов.
**Follow-up:**
- «Что нужно, чтобы query syntax заработал с твоим типом?» — методы с именами `Where`, `Select`, `SelectMany`… (паттерн, не интерфейс).
**Красные флаги:** «LINQ — это для баз данных»; не знает, что это extension methods.

### 2. Deferred vs immediate execution
**Уровень:** junior
**Хороший ответ:** Отложенные операторы (`Where`, `Select`, `OrderBy`, `GroupBy`, `Skip/Take`) возвращают описание запроса; выполнение — при переборе, каждый раз заново и с текущими данными. Немедленные — те, что возвращают не последовательность или материализуют её: `ToList`, `ToArray`, `ToDictionary`, `ToLookup`, `Count`, `Sum`, `First`, `Any`. Нужен снимок или многократный перебор — материализуй.
**Глубже (для junior+):** streaming (`Where`, `Select`) vs non-streaming (`OrderBy`, `GroupBy` читают весь источник при первом `MoveNext`). Захваченные переменные читаются в момент выполнения.
**Follow-up:**
- «Когда выполнится `OrderBy`?» — при первом `MoveNext`, и прочитает весь источник.
- «Какие баги вызывает ленивость?» — «живой» снимок, изменение коллекции во время перебора, позднее исключение, изменённая захваченная переменная.
**Красные флаги:** «LINQ выполняется в момент вызова `Where`».

### 3. Что выведет код?
```csharp
var numbers = new List<int> { 1, 2, 3 };
int factor = 10;
var query = numbers.Select(n => n * factor);
factor = 100;
numbers.Add(4);
Console.WriteLine(string.Join(",", query));
```
**Уровень:** junior
**Хороший ответ:** `100,200,300,400`. Запрос выполняется при `string.Join`: к этому моменту `factor` = 100 (захвачена переменная, не значение), и в списке уже 4 элемента.
**Follow-up:**
- «Как зафиксировать результат на момент создания?» — `.ToList()` сразу.
**Красные флаги:** `10,20,30`.

### 4. IEnumerable vs IQueryable
**Уровень:** junior / junior+
**Хороший ответ:** `IEnumerable<T>` — LINQ to Objects, всё выполняется в памяти, лямбды — делегаты. `IQueryable<T>` — запрос к провайдеру: лямбды становятся expression trees, провайдер (EF Core) переводит их в SQL и выполняет в базе. Методы выбираются по статическому типу: если `IQueryable` присвоить `IEnumerable` или вызвать `AsEnumerable`/`ToList`, дальнейшие операторы выполнятся в памяти — из БД загрузится всё.
**Глубже (для junior+):** `IQueryable` наследует `IEnumerable`; у него есть `Expression` и `Provider`. В лямбде `IQueryable` нельзя вызывать произвольные C#-методы — провайдер не переведёт их в SQL (исключение в runtime или client evaluation).
**Follow-up:**
- «Почему `Expression<Func<T, bool>>`, а не `Func`?» — делегат нельзя разобрать, дерево — можно.
- «Что будет с `db.Orders.ToList().Where(...)`?» — загрузка всей таблицы.
**Красные флаги:** «IQueryable быстрее, потому что ленивый»; путает их с IList.

### 5. Что такое multiple enumeration? Как избежать?
**Уровень:** junior
**Хороший ответ:** Повторный перебор одной ленивой последовательности — запрос каждый раз выполняется заново. Последствия: лишняя работа, повторные запросы к БД, разные результаты, падение на одноразовых источниках. Избежать — материализовать один раз (`ToList`) или перебирать параметр-`IEnumerable` ровно один раз. IDE подсвечивает «Possible multiple enumeration».
**Follow-up:**
- «Если метод принимает `IEnumerable<T>`, а тебе нужно `Count` и перебор?» — материализовать в начале или принимать `IReadOnlyCollection<T>`.
**Красные флаги:** не видит проблемы в `if (items.Any()) foreach (var x in items)` для ленивого источника.

### 6. First / FirstOrDefault / Single / SingleOrDefault
**Уровень:** junior
**Хороший ответ:** `First` — первый, исключение если пусто; `FirstOrDefault` — default если пусто; `Single` — ровно один, исключение если 0 или больше 1; `SingleOrDefault` — default если пусто, исключение если больше 1. `Single` — когда уникальность — инвариант (id, email), `First` — когда нужен любой первый (обычно после сортировки).
**Follow-up:**
- «Что быстрее, `First` или `Single`?» — `First` может остановиться раньше; `Single` проверяет, что второго нет.
- «Что вернёт `FirstOrDefault` для `List<int>`?» — 0, не null; это может маскировать «не найдено».
**Красные флаги:** «Single — это то же самое, что First».

### 7. GroupBy vs ToLookup vs ToDictionary
**Уровень:** junior+
**Хороший ответ:** `GroupBy` — отложенный, возвращает группы (`IGrouping<K, T>`), выполняется при переборе. `ToLookup` — немедленный, «словарь последовательностей», отсутствующий ключ → пустая последовательность. `ToDictionary` — немедленный, одно значение на ключ, дубликат ключа → `ArgumentException`, отсутствующий ключ → `KeyNotFoundException`.
**Follow-up:**
- «Как сгруппировать по двум полям?» — анонимный тип или кортеж как ключ.
**Красные флаги:** пытается `ToDictionary` по неуникальному ключу.

### 8. Как сделать left join в LINQ?
**Уровень:** junior+
**Хороший ответ:** `GroupJoin` + `SelectMany` + `DefaultIfEmpty`:
```csharp
from e in employees
join d in departments on e.DepartmentId equals d.Id into g
from d in g.DefaultIfEmpty()
select new { e.Name, Dept = d?.Name };
```
Для сотрудников без пары `d == null`. В .NET 10 есть готовый `LeftJoin`.
**Follow-up:**
- «Какая сложность у `Join`?» — O(n + m): строится хэш-таблица по ключам внутренней последовательности.
**Красные флаги:** делает left join через `FirstOrDefault` в `Select` и не видит O(n × m).

### 9. Почему Any() лучше Count() > 0?
**Уровень:** junior
**Хороший ответ:** `Any()` останавливается на первом элементе (O(1)), `Count()` для ленивой последовательности перебирает всё (O(n)); для `IQueryable` — `EXISTS` против `COUNT(*)`. Для коллекций с `Count` разница мала, но `Any()` яснее выражает намерение.
**Красные флаги:** не знает, что `Count()` может перебирать всю последовательность.

### 10. SelectMany — зачем?
**Уровень:** junior
**Хороший ответ:** «Расплющивает» последовательность последовательностей: `orders.SelectMany(o => o.Lines)` — все строки всех заказов. Аналог вложенного `foreach` или двух `from` в query syntax. Используется также для декартова произведения и left join.
**Красные флаги:** путает с `Select`.

### 11. Что выведет код?
```csharp
var words = new[] { "apple", "avocado", "banana", "blueberry", "cherry" };
var result = words
    .GroupBy(w => w[0])
    .Where(g => g.Count() > 1)
    .Select(g => $"{g.Key}:{string.Join("|", g)}");
Console.WriteLine(string.Join(", ", result));
```
**Уровень:** junior
**Хороший ответ:** `a:apple|avocado, b:banana|blueberry`. Группы по первой букве; `c` отфильтрована (одно слово). `GroupBy` сохраняет порядок появления ключей и элементов внутри группы.
**Красные флаги:** не может проследить конвейер.

### 12. Live coding: топ-3 покупателя по сумме заказов
```csharp
record Order(string Customer, decimal Total, bool IsCancelled);
// Верни имена трёх покупателей с наибольшей суммой не отменённых заказов.
```
**Уровень:** junior
**Хороший ответ:**
```csharp
var top = orders
    .Where(o => !o.IsCancelled)
    .GroupBy(o => o.Customer)
    .Select(g => new { Customer = g.Key, Sum = g.Sum(o => o.Total) })
    .OrderByDescending(x => x.Sum)
    .ThenBy(x => x.Customer)
    .Take(3)
    .Select(x => x.Customer)
    .ToList();
```
Обсуждение: фильтр до группировки, `ThenBy` для детерминированности при равенстве, `ToList` для материализации; сложность O(n + g log g), где g — число покупателей (группировка за проход + сортировка групп).
**Follow-up:**
- «Что если это `IQueryable` из EF Core?» — запрос целиком переведётся в SQL (GROUP BY, ORDER BY, TOP 3).
- «А если нужны ещё и покупатели без заказов?» — left join с таблицей покупателей.
**Красные флаги:** сортирует до группировки; использует `First` вместо `Take`.

### 13. Live coding: напиши свой Batch/Chunk (junior+)
**Уровень:** junior+
**Хороший ответ:**
```csharp
public static IEnumerable<List<T>> Batch<T>(this IEnumerable<T> source, int size)
{
    ArgumentNullException.ThrowIfNull(source);
    ArgumentOutOfRangeException.ThrowIfNegativeOrZero(size);
    return Iterator(source, size);

    static IEnumerable<List<T>> Iterator(IEnumerable<T> items, int size)
    {
        var batch = new List<T>(size);
        foreach (var item in items)
        {
            batch.Add(item);
            if (batch.Count == size) { yield return batch; batch = new List<T>(size); }
        }
        if (batch.Count > 0) yield return batch;
    }
}
```
Обсуждение: ленивость, жадная валидация, новый список на пакет, хвост без пустого пакета, работа с бесконечным источником.
**Follow-up:**
- «Почему не `Clear()`?» — вызывающий может хранить ссылки на прошлые пакеты.
- «Что есть в BCL?» — `Chunk` (.NET 6), возвращает массивы.
**Красные флаги:** `source.ToList()` в начале; проверки внутри итератора.
