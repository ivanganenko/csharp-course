# Интервью: модуль 02 — Типы данных и переменные

### 1. Чем value type отличается от reference type?
**Уровень:** junior
**Хороший ответ:** value type хранит само значение, при присваивании и передаче в метод копируется; reference type хранит ссылку на объект в managed heap, при присваивании копируется ссылка, и две переменные указывают на один объект. Value types — примитивы, `struct`, `enum`; reference types — `class`, `string`, массивы, делегаты, `record`. Value types наследуются от `System.ValueType` и не могут быть `null` (кроме `Nullable<T>`). Хорошо, если кандидат сам приведёт пример с массивом/объектом.
**Глубже (для junior+):** семантика копирования для struct при передаче в метод и возврате из свойства; `ref`-возвраты; `record struct`; `readonly struct`.
**Follow-up:**
- «Если передать объект класса в метод и в методе присвоить параметру `null` — что будет с исходной переменной?» → ничего: копируется ссылка, присваивание меняет локальную копию ссылки (если не `ref`).
- «А если в методе изменить поле объекта?» → изменение видно снаружи — объект один.
**Красные флаги:** «reference type передаётся по ссылке» (без уточнения, что передаётся копия ссылки); «string — value type».

### 2. Где хранятся value types? Правда ли, что в стеке?
**Уровень:** junior / junior+
**Хороший ответ:** «В стеке» — упрощение. Value type хранится там, где объявлен: локальная переменная — на стеке (или в регистре), поле класса — в heap внутри объекта, элемент массива — в heap. Захваченные замыканием переменные и локальные переменные async/iterator-методов поднимаются в объект в heap. Объекты reference types — в heap.
**Глубже (для junior+):** Эрик Липперт: «stack — это деталь реализации»; `stackalloc`, `Span<T>`, `ref struct` — типы, которые обязаны жить на стеке.
**Follow-up:**
- «Где будет `int` поле внутри `class Order`?» → в heap, в объекте Order.
- «А где `int` в `List<int>`?» → в heap, во внутреннем массиве списка.
**Красные флаги:** уверенное «value types всегда в стеке, reference — всегда в куче» без оговорок.

### 3. Что такое boxing и unboxing?
**Уровень:** junior
**Хороший ответ:** boxing — упаковка value type в объект в heap при приведении к `object` или к интерфейсу: выделяется память, значение копируется. Unboxing — проверка типа и копирование значения обратно. Распаковать можно только в точно тот же тип, иначе `InvalidCastException`. Минусы: аллокации и нагрузка на GC; избегают с помощью generics.
**Глубже (для junior+):** IL-инструкции `box`/`unbox.any`; boxing при вызове методов интерфейса на struct; `Equals(object)` у struct без `IEquatable<T>`; интерполяция строк в .NET 6+ без boxing.
**Follow-up:**
- «Где boxing происходит неявно?» → `ArrayList`, `object` параметры, `string.Format` с value types, приведение struct к интерфейсу, `Enum.HasFlag` в старых версиях.
- «Как избежать?» → generics, перегрузки под конкретные типы, `IEquatable<T>`.
**Красные флаги:** «boxing — это когда int превращается в string»; не знает про аллокацию.

### 4. Что выведет этот код?
```csharp
int n = 10;
object o = n;
n = 20;
Console.WriteLine(o);
Console.WriteLine((int)o + n);
object s = "abc";
Console.WriteLine(s == "abc");
```
**Уровень:** junior
**Хороший ответ:** `10`, `30`, `True` (с оговоркой). При boxing создаётся копия — изменение `n` не влияет на `o`. Последняя строка: `object == string` сравнивает ссылки, но оба литерала `"abc"` интернированы — одна ссылка, поэтому `True`; компилятор при этом выдаёт warning CS0252 о возможном непреднамеренном сравнении ссылок.
**Глубже (для junior+):** почему `==` на `object` — это reference equality, а на `string` — value; перегрузка операторов статическая (выбирается по типу переменной при компиляции).
**Follow-up:**
- «А если бы вторая строка была создана в runtime?» → `False`.
- «Как сравнить надёжно?» → `Equals` или `string.Equals`.
**Красные флаги:** отвечает `20` на первую строку.

### 5. Почему string — reference type, но ведёт себя как value type? Почему он immutable?
**Уровень:** junior
**Хороший ответ:** string — reference type (размер заранее неизвестен, живёт в heap), но immutable, а `==`/`Equals` перегружены для сравнения содержимого — поэтому ощущается как значение. Immutability даёт: потокобезопасность, интернирование литералов, безопасные ключи словарей (хэш не меняется), защиту от изменения после проверки (например, путь к файлу). Цена — каждое изменение создаёт новую строку.
**Глубже (для junior+):** `string.Create`, `Span<char>`, пул интернирования, `ReadOnlySpan<char>` для разбора без аллокаций.
**Follow-up:**
- «Что произойдёт при `s += "x"` в цикле 10 000 раз?» → 10 000 новых строк, O(n²) копирования; использовать `StringBuilder`.
- «Как поменять один символ строки?» → никак напрямую: `ToCharArray` → изменить → `new string(...)`, или `StringBuilder`.
**Красные флаги:** «string — value type»; «Replace меняет исходную строку».

### 6. Когда использовать StringBuilder?
**Уровень:** junior
**Хороший ответ:** когда строка собирается в цикле или из неизвестного заранее количества кусков: `StringBuilder` хранит изменяемый буфер, который растёт с запасом, итоговая строка создаётся один раз — O(n) вместо O(n²). Для нескольких частей в одном выражении достаточно `+` или интерполяции (компилятор сделает один `string.Concat`), для коллекции — `string.Join`.
**Глубже (для junior+):** начальная capacity; chunk-структура StringBuilder; `StringBuilder` не потокобезопасен; `string.Create` и `ArrayPool` для горячих путей.
**Follow-up:**
- «Всегда ли StringBuilder быстрее?» → нет, для 2–3 склеек он медленнее из-за накладных расходов.
- «Потокобезопасен ли StringBuilder?» → нет.
**Красные флаги:** «StringBuilder всегда быстрее», «используют везде для любой склейки».

### 7. Почему нельзя хранить деньги в double?
**Уровень:** junior
**Хороший ответ:** double — двоичная плавающая точка (IEEE 754); многие десятичные дроби (0.1) в двоичной системе бесконечны и хранятся приближённо, поэтому `0.1 + 0.2 != 0.3`, и при суммировании/округлении копейки теряются. decimal — 128-битное десятичное число (мантисса + степень 10), хранит десятичные дроби точно, 28–29 значащих цифр. Альтернатива — `long` в минимальных единицах (копейках).
**Глубже (для junior+):** decimal тоже не бесконечно точен (1m/3m * 3m != 1m); банковское округление; хранение в БД `decimal(18,2)`; Money value object с валютой.
**Follow-up:**
- «Что такое banker's rounding?» → к ближайшему чётному на середине (2.5 → 2, 3.5 → 4); по умолчанию в `Math.Round`; снижает систематическую ошибку при массовом округлении.
- «Когда double — правильный выбор?» → физика, графика, научные вычисления, где важна скорость и диапазон, а погрешность допустима.
**Красные флаги:** «double точнее, он же 64-битный»; «decimal для денег, потому что так принято» без объяснения.

### 8. Что будет при `int.MaxValue + 1`? Что такое checked?
**Уровень:** junior
**Хороший ответ:** по умолчанию unchecked — переполнение заворачивает значение в `int.MinValue` без исключения. В `checked` контексте (выражение, блок или `<CheckForOverflowUnderflow>`) — `OverflowException`. Константные выражения проверяются компилятором (ошибка CS0220). Unchecked по умолчанию ради производительности.
**Глубже (для junior+):** `checked` не влияет на вызываемые методы; LINQ `Sum` для `int` всегда checked; приведение `(int)longValue` тоже зависит от контекста; double при переполнении даёт Infinity.
**Follow-up:**
- «`long r = a + b;` где `a`, `b` — int; переполнение возможно?» → да: сложение выполняется в int до присваивания.
- «Как безопасно найти середину двух индексов?» → `low + (high - low) / 2`.
**Красные флаги:** «будет исключение всегда»; «C# автоматически расширит до long».

### 9. Чем `int?` отличается от `string?`? Что такое nullable reference types?
**Уровень:** junior
**Хороший ответ:** `int?` — синтаксис для `Nullable<int>`, отдельного struct с `HasValue` и `Value`; это реальный другой тип в runtime. `string?` — аннотация NRT (C# 8+): в runtime тип тот же, `?` лишь говорит компилятору, что null допустим; компилятор делает flow analysis и выдаёт предупреждения о возможном разыменовании null. Включается `<Nullable>enable</Nullable>`.
**Глубже (для junior+):** атрибуты `[NotNullWhen(true)]`, `[MaybeNull]`; null-forgiving `!` и почему им не злоупотребляют; NRT — только warnings, их можно сделать ошибками через `TreatWarningsAsErrors` / `WarningsAsErrors=nullable`.
**Follow-up:**
- «Что делает `??=`?» → присваивает, только если слева null.
- «Защищает ли NRT от NullReferenceException на 100%?» → нет: это статический анализ, данные извне (десериализация, reflection, `!`) могут принести null.
**Красные флаги:** «`string?` — это `Nullable<string>`».

### 10. Parse vs TryParse vs Convert — в чём разница?
**Уровень:** junior
**Хороший ответ:** `Parse` бросает `FormatException`/`OverflowException`/`ArgumentNullException` — для данных, корректность которых гарантирована. `TryParse` возвращает `bool` и значение через `out`, без исключений — для пользовательского ввода (Try-pattern). `Convert.ToXxx` — универсальные преобразования из `object`/разных типов; `Convert.ToInt32(null)` → 0, а для double — банковское округление. Для машинных данных — `CultureInfo.InvariantCulture`.
**Глубже (для junior+):** `NumberStyles`; `IParsable<T>`/`ISpanParsable<T>` (.NET 7) и парсинг из `ReadOnlySpan<char>` без аллокаций.
**Follow-up:**
- «Что вернёт `double.Parse("12.5")` на русской Windows?» → исключение FormatException (в ru-RU разделитель — запятая; точка трактуется как недопустимый символ) — правильно указывать культуру.
- «Почему исключения — плохой способ проверки ввода?» → дорогие (stack trace), неявный control flow.
**Красные флаги:** не знает про культуру; всегда `Convert.ToInt32(Console.ReadLine())`.

### 11. Как правильно сравнивать строки?
**Уровень:** junior
**Хороший ответ:** явно указывать `StringComparison`. Для идентификаторов, ключей, путей, протоколов — `Ordinal`/`OrdinalIgnoreCase` (быстро, не зависит от культуры). Для текста, который сортируется и показывается пользователю, — `CurrentCulture`. Статический `string.Equals(a, b, ...)` безопасен для null. `ToLower() == ToLower()` — антипаттерн.
**Глубже (для junior+):** турецкая «i»; `StringComparer.OrdinalIgnoreCase` для `Dictionary`/`HashSet`; нормализация Unicode (`é` как один символ или как `e` + комбинирующий знак).
**Follow-up:**
- «Как сделать словарь с ключами без учёта регистра?» → `new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase)`.
- «Что сравнивает `==` для строк?» → содержимое (ordinal, с учётом регистра).
**Красные флаги:** «`==` сравнивает ссылки у строк»; не знает про StringComparison.

### 12. Что такое `var`? Это как `dynamic` или `object`?
**Уровень:** junior
**Хороший ответ:** нет: `var` — вывод типа при компиляции; переменная статически типизирована, тип нельзя поменять. `object` — переменная базового типа (value types при присваивании боксятся). `dynamic` — проверка членов откладывается до runtime (через DLR), ошибки — во время выполнения.
**Глубже (для junior+):** анонимные типы требуют `var`; target-typed `new()` как альтернатива; стайл-гайды команды.
**Follow-up:**
- «Когда var плох?» → когда тип неочевиден из правой части (`var result = Process();`).
**Красные флаги:** «var — это динамический тип как в JavaScript».

### 13. Live coding: «Проверьте, является ли строка палиндромом, игнорируя регистр и всё, кроме букв и цифр»
**Уровень:** junior
**Хороший ответ:** уточняющие вопросы (null? пустая строка? Unicode?), два указателя с краёв, пропуск не-буквенных символов, сравнение через `char.ToLowerInvariant`, O(n) время и O(1) память; тесты на "", "a", "A man, a plan, a canal: Panama", "ab".
```csharp
public static bool IsPalindrome(string text)
{
    ArgumentNullException.ThrowIfNull(text);
    int left = 0, right = text.Length - 1;
    while (left < right)
    {
        if (!char.IsLetterOrDigit(text[left])) { left++; continue; }
        if (!char.IsLetterOrDigit(text[right])) { right--; continue; }
        if (char.ToLowerInvariant(text[left]) != char.ToLowerInvariant(text[right])) return false;
        left++;
        right--;
    }
    return true;
}
```
**Глубже (для junior+):** surrogate pairs (эмодзи из двух `char`) и `Rune`/`StringInfo`; сравнение с LINQ-версией по аллокациям.
**Follow-up:**
- «Сложность?» → O(n) время, O(1) память.
- «А с LINQ (`Reverse`)?» → проще писать, но O(n) памяти и несколько аллокаций.
**Красные флаги:** не задаёт вопросов про регистр/пробелы; `ToLower()` всей строки + `Reverse` без понимания цены; выход за границы при пропуске символов.
