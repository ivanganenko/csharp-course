# Интервью: модуль 03 — Управляющие конструкции и методы

### 1. Чем отличаются `ref`, `out` и `in`?
**Уровень:** junior
**Хороший ответ:** все три передают аргумент по ссылке — метод работает с переменной вызывающего. `ref`: переменная должна быть инициализирована, метод может читать и менять. `out`: инициализация не нужна, метод обязан присвоить значение на каждом пути выхода — используется для дополнительных результатов (Try-паттерн). `in`: readonly-ссылка, чтобы передать большой struct без копирования. Модификатор пишется и при объявлении, и при вызове (`in` при вызове можно опустить).
**Глубже (для junior+):** `ref` locals и `ref` returns; defensive copy при вызове методов не-readonly struct через `in`; `ref readonly` параметры (C# 12); ограничения: нельзя в async-методах и итераторах.
**Follow-up:**
- «Можно ли перегрузить метод только по `ref` vs `out`?» → нет, для CLR это одинаковые сигнатуры; по `ref` vs без модификатора — можно.
- «Почему `out` не может быть в async-методе?» → состояние async-метода живёт в heap-объекте state machine, а ссылка на стековую переменную может стать недействительной.
**Красные флаги:** «out — это когда возвращаем, ref — когда передаём» без понимания инициализации и гарантий.

### 2. Reference types передаются в метод по ссылке?
**Уровень:** junior
**Хороший ответ:** нет, по умолчанию всё передаётся по значению. Для reference type по значению копируется ссылка: метод видит тот же объект и может изменить его состояние, но присваивание параметру нового объекта не влияет на переменную вызывающего. С `ref` передаётся сама переменная, и замену объекта видно снаружи.
**Глубже (для junior+):** `ref` для reference type — «ссылка на ссылку»; immutable типы (string) и почему для них поведение «как у значения».
**Follow-up:**
- «Метод получил `string s` и сделал `s += "!"`. Изменится ли строка у вызывающего?» → нет: новая строка, присвоена локальной копии ссылки.
- «Как метод может заменить список вызывающего на новый?» → `ref List<T>` или вернуть новый список.
**Красные флаги:** «классы передаются по ссылке, структуры по значению» как окончательный ответ.

### 3. Что выведет этот код?
```csharp
void Modify(int[] numbers, int count, ref int total)
{
    numbers[0] = 42;
    numbers = new[] { 0, 0, 0 };
    count = 10;
    total = 100;
}
int[] data = { 1, 2 };
int count = 1, total = 1;
Modify(data, count, ref total);
Console.WriteLine($"{data[0]} {data.Length} {count} {total}");
```
**Уровень:** junior
**Хороший ответ:** `42 2 1 100`. Элемент изменён через копию ссылки — видно; новый массив присвоен копии ссылки — не видно; `count` скопирован; `total` передан по `ref` — изменение видно.
**Глубже (для junior+):** как это выглядит в IL (`ldarg` vs `ldarga`/`stind`).
**Follow-up:**
- «Как сделать, чтобы `data` стал новым массивом?» → `ref int[] numbers`.
**Красные флаги:** путает `data.Length` (ожидает 3).

### 4. Что такое pattern matching? Какие паттерны вы знаете?
**Уровень:** junior
**Хороший ответ:** проверка значения на соответствие образцу с извлечением данных, в `is`, `switch` statement и switch expression. Паттерны: constant, type/declaration (`is string s`), relational (`> 0`), logical (`and`, `or`, `not`), property (`{ Status: Paid }`), positional (через `Deconstruct`), list (`[first, .., last]`), `var`, discard `_`; плюс case guard `when`. Плюсы: декларативность, меньше приведений типов, компилятор проверяет полноту и недостижимые ветки.
**Глубже (для junior+):** exhaustiveness для enum (компилятор не считает enum закрытым — нужен `_`); `is not null` vs `!= null` (перегруженный оператор); паттерны и nullable flow analysis.
**Follow-up:**
- «Почему `x is not null` лучше `x != null`?» → `!=` можно перегрузить, паттерн всегда проверяет ссылку на null.
- «Когда switch по типу — плохой дизайн?» → когда это иерархия ваших классов: лучше полиморфизм (модуль 05).
**Красные флаги:** знает только `is` для проверки типа.

### 5. Чем switch expression отличается от switch statement?
**Уровень:** junior
**Хороший ответ:** statement — набор инструкций: `case`, обязательный `break`/`return`/`throw`, ничего не возвращает. Expression — выражение, возвращающее значение: `pattern => результат`, компактнее, поддерживает все паттерны, `throw` как выражение, компилятор проверяет полноту (CS8509) и при непокрытом значении в runtime — `SwitchExpressionException`. Неявного fall-through нет ни там, ни там.
**Глубже (для junior+):** switch по кортежам; target-typed switch; как компилятор строит decision tree.
**Follow-up:**
- «Можно ли в C# провалиться из одного case в другой?» → нет, только явно `goto case` или пустые case подряд.
**Красные флаги:** не знает, что switch expression возвращает значение.

### 6. Что такое перегрузка метода? Чем она отличается от переопределения?
**Уровень:** junior
**Хороший ответ:** overloading — методы с одним именем и разными параметрами (количество, типы, порядок, `ref`/`out`), выбор на этапе компиляции по статическим типам аргументов. Overriding — замена реализации `virtual`/`abstract` метода в наследнике с той же сигнатурой, выбор в runtime по реальному типу объекта. Только по возвращаемому типу перегрузить нельзя.
**Глубже (для junior+):** правила «better conversion»; неоднозначности с `null` и optional параметрами; перегрузка + наследование: метод базового класса может проиграть методу наследника с менее точным типом параметра.
**Follow-up:**
- «`Print(object)` и `Print(long)`, вызов `Print(5)` — что выберется?» → `Print(long)`: implicit numeric conversion лучше boxing.
- «`Print(string)` и `Print(object)`, вызов `Print(null)`?» → `Print(string)`, более конкретный тип.
**Красные флаги:** путает overloading и overriding.

### 7. Что такое `params`? Optional и named параметры — какие подводные камни?
**Уровень:** junior
**Хороший ответ:** `params` — переменное число аргументов, компилятор собирает их в массив; только один и последним. Optional параметры имеют значение по умолчанию — константу, которая вшивается в место вызова: при изменении значения в библиотеке старые клиенты продолжат передавать старое до перекомпиляции. Named arguments позволяют передавать параметры в любом порядке и пропускать optional.
**Глубже (для junior+):** params collections (C# 13: `params ReadOnlySpan<T>`) — без аллокации; optional параметры в интерфейсах и наследовании — значение берётся по статическому типу переменной.
**Follow-up:**
- «Сколько аллокаций при `Sum(1, 2, 3)` с `params int[]`?» → один массив на каждый вызов.
**Красные флаги:** не знает, что default значения должны быть константами.

### 8. Что такое рекурсия? Что произойдёт при слишком глубокой рекурсии?
**Уровень:** junior
**Хороший ответ:** метод вызывает сам себя; нужны базовый случай и шаг к нему. Каждый вызов кладёт кадр в stack потока (параметры, локальные переменные, адрес возврата). Стек ограничен (~1 МБ), при переполнении — `StackOverflowException`, который нельзя поймать: процесс завершается. Глубокую рекурсию заменяют циклом или явным `Stack<T>`; C# не гарантирует tail call optimization.
**Глубже (для junior+):** размер стека потока можно задать в конструкторе `Thread`; мемоизация; рекурсивный обход деревьев vs итеративный с явным стеком.
**Follow-up:**
- «Почему наивный Фибоначчи медленный?» → O(2ⁿ): одни и те же подзадачи вычисляются много раз; решение — цикл или мемоизация, O(n).
- «Когда рекурсия уместна?» → деревья, «разделяй и властвуй», перебор.
**Красные флаги:** «поймаю StackOverflowException в try/catch».

### 9. Чем `int[,]` отличается от `int[][]`?
**Уровень:** junior
**Хороший ответ:** `int[,]` — прямоугольный многомерный массив: один непрерывный блок, все строки одной длины, `a[i, j]`, `GetLength(d)`. `int[][]` — jagged: массив ссылок на отдельные одномерные массивы, строки разной длины (могут быть `null`), `a[i][j]`. Jagged обычно быстрее за счёт оптимизаций JIT для одномерных массивов.
**Глубже (для junior+):** память: jagged — несколько объектов в heap и заголовков; кэш-локальность прямоугольного массива.
**Follow-up:**
- «Какой будет `Length` у `new int[3, 4]`?» → 12.
**Красные флаги:** считает их одним и тем же.

### 10. Когда `for`, а когда `foreach`? Можно ли менять коллекцию в `foreach`?
**Уровень:** junior
**Хороший ответ:** `foreach` — перебор всех элементов без индекса: читаемо, нет off-by-one. `for` — когда нужен индекс, шаг, обратный порядок или изменение элементов массива по индексу. Добавлять/удалять элементы коллекции во время `foreach` нельзя — `InvalidOperationException` (для `List<T>`); переменная цикла readonly.
**Глубже (для junior+):** `foreach` над массивом компилируется в `for`; над `List<T>` — struct-энумератор без аллокации; duck typing (`GetEnumerator`).
**Follow-up:**
- «Как удалить элементы из списка по условию?» → `RemoveAll`, обратный `for`, или новый список.
**Красные флаги:** удаляет из списка в `foreach`.

### 11. Что такое local function и зачем она нужна?
**Уровень:** junior / junior+
**Хороший ответ:** метод внутри метода, виден только там. Не засоряет класс, явно показывает вспомогательный характер, может захватывать переменные внешнего метода. По сравнению с лямбдой: может быть рекурсивной, generic, иметь `ref/out/params`, обычно без аллокации делегата. `static` local function не захватывает переменные.
**Глубже (для junior+):** паттерн «валидация аргументов в итераторе/async-методе + локальная функция с реализацией», чтобы исключения бросались сразу, а не при первой итерации.
**Follow-up:**
- «Зачем `static` у локальной функции?» → защита от случайного захвата, гарантия отсутствия замыкания.
**Красные флаги:** не слышал о локальных функциях — не критично, но для junior+ минус.

### 12. Live coding: «Реализуйте бинарный поиск»
**Уровень:** junior
**Хороший ответ:** уточнить: массив отсортирован? дубликаты? что возвращать, если не найден? Итеративная реализация, проговорённый инвариант, проверка граничных случаев (пустой массив, один элемент, первый/последний, отсутствующий).
```csharp
public static int IndexOf(int[] sorted, int target)
{
    ArgumentNullException.ThrowIfNull(sorted);
    int low = 0, high = sorted.Length - 1;      // инвариант: target, если есть, в [low, high]
    while (low <= high)
    {
        var mid = low + (high - low) / 2;       // без переполнения
        if (sorted[mid] == target) return mid;
        if (sorted[mid] < target) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}
```
**Глубже (для junior+):** lower/upper bound; поиск «по ответу» (integer sqrt, минимальная скорость и т.п.); `Array.BinarySearch` возвращает побитовое дополнение индекса вставки (`~index`), если элемент не найден.
**Follow-up:**
- «Сложность?» → O(log n) времени, O(1) памяти; миллион элементов — ~20 шагов.
- «Как найти первое вхождение при дубликатах?» → не останавливаться при совпадении, сдвигать `high = mid` (lower bound).
- «Почему не `(low + high) / 2`?» → переполнение int на больших массивах.
**Красные флаги:** линейный поиск; `low = mid` с бесконечным циклом; не проверяет пустой массив; не может объяснить, почему цикл завершится.

### 13. Что выведет этот код?
```csharp
static string Check(object o) => o switch
{
    int i when i > 10 => "big int",
    int => "int",
    string { Length: > 0 } s => $"text:{s}",
    null => "null",
    _ => "other",
};
Console.WriteLine(Check(42));
Console.WriteLine(Check(7.0));
Console.WriteLine(Check(""));
Console.WriteLine(Check(5));
```
**Уровень:** junior
**Хороший ответ:** `big int`, `other` (7.0 — double, не int), `other` (пустая строка не проходит `Length: > 0`), `int`.
**Глубже (для junior+):** почему `null` можно ставить после type patterns (type pattern никогда не совпадает с null) и почему компилятор не считает это недостижимым.
**Follow-up:**
- «Что если убрать `_`?» → предупреждение CS8509 о неполноте и `SwitchExpressionException` для double.
**Красные флаги:** думает, что `7.0` совпадёт с `int`.
