# Интервью: модуль 01 — Платформа .NET и инструменты

### 1. Что такое CLR и что он делает?
**Уровень:** junior
**Хороший ответ:** CLR (Common Language Runtime) — среда выполнения .NET. Загружает сборки, проверяет и JIT-компилирует IL в машинный код, управляет памятью через Garbage Collector, обеспечивает type safety, обработку исключений, работу с потоками. Код под управлением CLR называется managed. Хорошо, если кандидат перечислит 3–4 обязанности, а не только «запускает программы».
**Глубже (для junior+):** CLR — реализация стандарта CLI (ECMA-335). В современном .NET это CoreCLR; есть и другие рантаймы (Mono — для мобильных/WASM). Tiered compilation, OSR (on-stack replacement), Dynamic PGO.
**Follow-up:**
- «Что такое managed code?» → код, выполняемый под CLR, с GC и проверками; противоположность — unmanaged (C/C++, WinAPI).
- «Может ли C# вызвать неуправляемый код?» → да, через P/Invoke (`[DllImport]`/`[LibraryImport]`).
**Красные флаги:** «CLR — это компилятор C#»; путает CLR с BCL; не может назвать GC как часть рантайма.

### 2. Опишите путь кода от `.cs` файла до выполнения процессором.
**Уровень:** junior
**Хороший ответ:** Roslyn компилирует C# в IL и метаданные, записывает их в сборку (.dll). При запуске CLR загружает сборку; при первом вызове метода JIT компилирует его IL в машинный код под текущий процессор, код кэшируется в памяти процесса. Следующие вызовы идут сразу в машинный код. При tiered compilation «горячие» методы перекомпилируются с оптимизациями.
**Глубже (для junior+):** ReadyToRun (предкомпилированный код + IL), Native AOT (без JIT, ограничения reflection/генерации кода), Dynamic PGO.
**Follow-up:**
- «Сохраняется ли машинный код после завершения процесса?» → нет (в обычном JIT), при следующем запуске JIT снова; ReadyToRun решает это частично.
- «Зачем tiered compilation?» → быстрый старт (Tier 0 без оптимизаций) + быстрая работа горячего кода (Tier 1).
**Красные флаги:** «C# компилируется в машинный код»; «JIT компилирует всю программу при запуске».

### 3. Зачем нужен IL, если можно компилировать сразу в машинный код?
**Уровень:** junior
**Хороший ответ:** переносимость (одна сборка — любая ОС/архитектура), независимость от языка (C#, F#, VB используют друг друга через общий IL и CTS), JIT может оптимизировать под конкретный CPU и реальную нагрузку, метаданные дают reflection и проверку типов. Минус — время на JIT при старте.
**Глубже (для junior+):** IL — стековая машина; верифицируемость IL; компромисс Native AOT.
**Follow-up:**
- «Когда выбирают Native AOT?» → CLI-утилиты, serverless, контейнеры с быстрым стартом и малым размером.
- «Чем это похоже на Java?» → та же идея (байткод + JVM с JIT).
**Красные флаги:** не может назвать ни одной причины, кроме «так исторически».

### 4. .NET Framework vs .NET (Core) vs .NET Standard?
**Уровень:** junior
**Хороший ответ:** .NET Framework — Windows-only, устанавливается в систему, только исправления (4.8.1 — последняя). .NET (Core) — кроссплатформенный, open source, производительный, side-by-side установка; с версии 5 называется просто .NET; выходит ежегодно, чётные версии — LTS. .NET Standard — спецификация API для библиотек, совместимых с обеими платформами.
**Глубже (для junior+):** почему не было .NET 4 «Core» (путаница с Framework 4.x); миграция с Framework: несовместимые технологии (WebForms, WCF server, AppDomain, Remoting).
**Follow-up:**
- «Под что таргетить новую библиотеку?» → под современный `net8.0`/`net10.0`; `netstandard2.0` — только если нужна поддержка .NET Framework.
- «Что такое LTS?» → Long-Term Support, 3 года поддержки.
**Красные флаги:** «.NET Standard — это стандартная версия .NET»; «.NET Core — урезанный .NET Framework».

### 5. Чем SDK отличается от Runtime?
**Уровень:** junior
**Хороший ответ:** Runtime — для запуска приложений (CLR + библиотеки, варианты для ASP.NET Core и Desktop). SDK — для разработки: компилятор, MSBuild, dotnet CLI, шаблоны; SDK включает runtime. На проде ставят runtime или публикуют self-contained.
**Глубже (для junior+):** `global.json` фиксирует версию SDK для репозитория; framework-dependent vs self-contained; roll-forward политики runtime.
**Follow-up:**
- «Как зафиксировать версию SDK в проекте?» → `global.json`.
- «Что такое self-contained?» → приложение с собственным runtime; не зависит от установленного .NET, но больше по размеру.
**Красные флаги:** не знает, зачем на сервере что-то устанавливать; путает SDK с IDE.

### 6. Assembly и namespace — в чём разница?
**Уровень:** junior
**Хороший ответ:** Assembly — физическая единица развёртывания и версионирования (.dll/.exe с IL, метаданными, manifest). Namespace — логическая группировка имён. Они ортогональны: сборка может содержать несколько namespace, namespace может быть распределён по сборкам. `using` не подключает сборку — для этого нужна ссылка на проект/пакет.
**Глубже (для junior+):** `internal` видимость ограничена сборкой (а не namespace!), `InternalsVisibleTo` для тестов; strong naming.
**Follow-up:**
- «Где действует модификатор `internal`?» → в пределах сборки.
- «Что в manifest?» → имя, версия, культура, список зависимостей.
**Красные флаги:** «namespace — это папка»; «`using` подключает библиотеку».

### 7. Что такое JIT? Плюсы и минусы.
**Уровень:** junior
**Хороший ответ:** Just-In-Time компилятор переводит IL метода в машинный код при первом вызове. Плюсы: переносимость, оптимизации под конкретный CPU, профилирование в runtime (tiered/PGO). Минусы: задержка старта, память на компилятор, «прогрев» приложения.
**Глубже (для junior+):** Tier 0/Tier 1, OSR для долгих циклов, Dynamic PGO включён по умолчанию с .NET 8.
**Follow-up:**
- «Почему первый запрос к веб-API медленнее следующих?» → JIT, прогрев, инициализация.
- «Как ускорить холодный старт?» → ReadyToRun, Native AOT.
**Красные флаги:** «JIT интерпретирует код построчно».

### 8. Что такое NuGet? Как подключить и обновить пакет?
**Уровень:** junior
**Хороший ответ:** NuGet — менеджер пакетов .NET. Пакет — архив со сборками под разные target frameworks и описанием зависимостей. `dotnet add package <Id>` добавляет `PackageReference` в `.csproj`; `dotnet restore` скачивает пакеты (неявно при build); `dotnet list package --outdated` показывает обновления. Пакеты не хранят в git.
**Глубже (для junior+):** транзитивные зависимости и конфликты версий; Central Package Management (`Directory.Packages.props`); приватные фиды; уязвимости (`dotnet list package --vulnerable`).
**Follow-up:**
- «Где лежат скачанные пакеты?» → глобальный кэш `~/.nuget/packages`.
- «Пакет A требует B 1.x, пакет C — B 2.x. Что будет?» → NuGet выберет минимальную подходящую версию для всех ограничений или выдаст предупреждение о конфликте (NU1608/NU1107).
**Красные флаги:** «скачиваю dll и кладу в папку проекта».

### 9. Что такое top-level statements? Куда делся `Main`?
**Уровень:** junior
**Хороший ответ:** C# 9 позволяет писать инструкции прямо в файле, без класса и `Main`. Компилятор генерирует класс `Program` и метод точки входа; `args` доступны как переменная; `return int` задаёт код возврата; `await` делает Main асинхронным. Только один файл в проекте может иметь top-level statements.
**Глубже (для junior+):** сгенерированное имя метода `<Main>$`; `public partial class Program { }` для доступа к Program из тестов (WebApplicationFactory в модуле 15).
**Follow-up:**
- «Можно ли объявить метод в top-level файле?» → да, локальную функцию; типы — после инструкций.
- «Зачем `int Main`?» → код возврата для скриптов/CI: 0 — успех.
**Красные флаги:** «в .NET 6+ больше нет Main».

### 10. Что выведет этот код (запуск на машине с русской локалью)?
```csharp
double price = 12.5;
Console.WriteLine(price);
Console.WriteLine(price.ToString(CultureInfo.InvariantCulture));
Console.WriteLine(7 / 2);
```
**Уровень:** junior
**Хороший ответ:** `12,5`, `12.5`, `3`. Форматирование чисел по умолчанию использует `CurrentCulture` — в русской культуре разделитель запятая. `InvariantCulture` даёт точку — так нужно для файлов, логов, API. `7 / 2` — целочисленное деление.
**Глубже (для junior+):** `CurrentCulture` vs `CurrentUICulture`; `string.Create(CultureInfo.InvariantCulture, $"...")`; парсинг CSV с разными культурами.
**Follow-up:**
- «Как сделать, чтобы `$"{price}"` всегда давал точку?» → `string.Create(CultureInfo.InvariantCulture, $"{price}")` или `FormattableString.Invariant`.
- «Как получить 3.5?» → `7 / 2.0` или `(double)7 / 2`.
**Красные флаги:** уверенно отвечает `12.5` для первой строки и не знает про культуру.

### 11. Чем solution отличается от project? Что такое .csproj?
**Уровень:** junior
**Хороший ответ:** проект (`.csproj`) — описание одной сборки для MSBuild: target framework, тип выхода, пакеты, ссылки на проекты; в SDK-style проектах файлы включаются автоматически. Solution (`.sln`/`.slnx`) — группа проектов для IDE и для общей сборки/тестов одной командой. Сам solution не превращается в отдельный артефакт.
**Глубже (для junior+):** `Directory.Build.props`/`.targets`; `.slnx` — новый XML-формат, по умолчанию в .NET 10 SDK; multi-targeting (`<TargetFrameworks>`).
**Follow-up:**
- «Как поделить настройки между 20 проектами?» → `Directory.Build.props`.
- «Что лежит в bin и obj?» → результат сборки и промежуточные файлы; не коммитим.
**Красные флаги:** не открывал `.csproj` ни разу; «solution — это папка».

### 12. Debug vs Release?
**Уровень:** junior
**Хороший ответ:** Debug — без оптимизаций, удобно отлаживать; Release — с оптимизациями, для продакшена и замеров производительности. В Release отладчик может не показывать некоторые переменные, а порядок шагов может «прыгать».
**Глубже (для junior+):** `#if DEBUG`, `[Conditional("DEBUG")]`, `Debug.Assert`; JIT-оптимизации и время жизни объектов для GC (в Release объект может быть собран раньше конца метода).
**Follow-up:**
- «Где мерить производительность?» → в Release, BenchmarkDotNet.
- «Что делает `Debug.Assert` в Release?» → вызов удаляется компилятором.
**Красные флаги:** «Release — это то же самое, только без отладочных символов».

### 13. Live coding: «Напишите консольную программу, которая читает числа построчно до пустой строки и печатает их сумму и среднее»
**Уровень:** junior
**Хороший ответ:** цикл `while`, `Console.ReadLine()` с проверкой на `null`/пустую строку, `TryParse` с `InvariantCulture`, пропуск/сообщение о некорректных строках, деление на количество только если оно > 0, `decimal` или `double` с обоснованием. Пример:
```csharp
using System.Globalization;

decimal sum = 0;
var count = 0;
while (Console.ReadLine() is { Length: > 0 } line)   // null или "" — конец ввода
{
    if (decimal.TryParse(line, NumberStyles.Number, CultureInfo.InvariantCulture, out var value))
    {
        sum += value;
        count++;
    }
    else
    {
        Console.Error.WriteLine($"Пропускаю: '{line}'");
    }
}
Console.WriteLine(count == 0 ? "Нет чисел" : $"Сумма: {sum}, среднее: {sum / count}");
```
**Глубже (для junior+):** выделить логику в тестируемый метод, принимающий `IEnumerable<string>`/`TextReader`; обработка культуры вывода.
**Follow-up:**
- «Что будет при пустом вводе?» → деления на ноль нет, выводим «Нет чисел».
- «Как это протестировать?» → вынести логику в метод, передавать строки, а не читать консоль.
**Красные флаги:** `int.Parse` без обработки; деление на 0; бесконечный цикл при `null` (конец ввода).
