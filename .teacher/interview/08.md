# Interview: модуль 08 — Generics

### 1. Зачем нужны generics?
**Уровень:** junior
**Хороший ответ:** Generics позволяют писать код, параметризованный типом: один `List<T>` для любых элементов. Главные плюсы: типобезопасность на этапе компиляции (нельзя положить строку в `List<int>`), отсутствие boxing для value types (`List<int>` хранит `int[]`), отсутствие ручных кастов и переиспользование алгоритмов. До .NET 2.0 использовали `ArrayList` с `object` — ошибки ловились в runtime, а каждое число упаковывалось.
**Глубже (для junior+):** JIT генерирует отдельный машинный код для каждого value type и общий для всех reference types — поэтому нет boxing и нет «раздувания» кода для классов.
**Follow-up:**
- «Чем плох `ArrayList` сегодня?» — boxing, касты, `InvalidCastException` в runtime, нет проверки компилятора.
- «Где в .NET ты встречал generics, кроме коллекций?» — `Task<T>`, `Nullable<T>`, `Func<T>`, `IEnumerable<T>`/LINQ, `ILogger<T>`, `DbSet<T>`.
**Красные флаги:** «generics — чтобы код был короче»; не может назвать boxing; путает generics с `dynamic`/`object`.

### 2. Какие constraints ты знаешь? Зачем они?
**Уровень:** junior
**Хороший ответ:** `where T : class`, `struct`, `notnull`, `unmanaged`, `new()`, базовый класс, интерфейс, `where T : U`. Constraint даёт компилятору знание о `T`: можно вызвать `CompareTo` при `IComparable<T>`, создать `new T()` при `new()`, вернуть `null` при `class`. Заодно пользователь получит ошибку компиляции, если передаст неподходящий тип. Пример: `Max<T>(IEnumerable<T>) where T : IComparable<T>`.
**Глубже (для junior+):** порядок: `class`/`struct`/`notnull`/`unmanaged` → базовый класс → интерфейсы → `new()`. Constraints не участвуют в выборе перегрузки (сигнатуры, отличающиеся только constraints, — конфликт). С C# 11 — static abstract members (`INumber<T>`).
**Follow-up:**
- «Что значит `T?` при `where T : struct` и при `where T : class`?» — `Nullable<T>` vs nullable reference annotation.
- «Можно ли через `new()` передать аргументы в конструктор?» — нет, используют фабрику `Func<T>` или DI.
**Красные флаги:** знает только `where T : class`; не может объяснить, зачем constraint вообще нужен.

### 3. Что такое default(T)? Как сравнить значение T с default?
**Уровень:** junior
**Хороший ответ:** Значение по умолчанию: 0, false, null, struct с нулевыми полями. Используется в generic-коде, когда нужно «пустое» значение, не зная вид типа (out-параметр Try-метода). `value == default` для неограниченного T не компилируется, поэтому сравнивают через `EqualityComparer<T>.Default.Equals(value, default)` — он ещё и не делает boxing для value types, реализующих `IEquatable<T>`.
**Глубже (для junior+):** `default` литерал (C# 7.1) выводит тип из контекста. `[MaybeNullWhen(false)]` подсказывает nullable-анализу контракт Try-метода.
**Follow-up:**
- «Чему равен default для `DateTime`? Для `int?`?» — `0001-01-01 00:00:00`; `null`.
**Красные флаги:** «default(T) — это всегда null».

### 4. Чем generics в C# отличаются от Java?
**Уровень:** junior+
**Хороший ответ:** В .NET generics реифицированы — информация о типе есть в runtime: `typeof(T)`, `List<int>` и `List<string>` — разные типы, можно `new T()`. Для value types JIT создаёт специализированный код без boxing. В Java — type erasure: в runtime остаётся сырой `List`, примитивы упаковываются (`List<Integer>`), нельзя узнать `T` в runtime.
**Глубже (для junior+):** .NET 2.0 изменил формат метаданных и CLR; Java сохранила совместимость байткода.
**Follow-up:**
- «Что выведет `typeof(List<int>) == typeof(List<string>)`?» — False.
**Красные флаги:** «одно и то же»; не слышал о boxing в контексте коллекций.

### 5. Что такое covariance и contravariance?
**Уровень:** junior / junior+
**Хороший ответ:** Covariance (`out T`) — можно использовать более производный тип вместо базового: `IEnumerable<string>` присвоить `IEnumerable<object>`. Безопасно, когда `T` только возвращается. Contravariance (`in T`) — наоборот: `Action<object>` как `Action<string>`, `IComparer<Animal>` как `IComparer<Cat>`; безопасно, когда `T` только принимается. Объявляется только у интерфейсов и делегатов, работает только для reference types.
**Глубже (для junior+):** ковариантность массивов (`object[] a = new string[1]`) небезопасна и проверяется в runtime (`ArrayTypeMismatchException`). `Func<in T, out TResult>` — оба вида сразу.
**Follow-up:**
- «Почему `List<T>` не ковариантен?» — он и принимает T (`Add`), и отдаёт; иначе можно было бы положить int в список строк.
- «Почему `IEnumerable<int>` нельзя присвоить `IEnumerable<object>`?» — потребовался бы boxing каждого элемента, вариантность работает только через reference conversion.
- «Можно ли сделать вариантный класс?» — нет.
**Красные флаги:** путает `in`/`out` с параметрами методов `in`/`out`; «covariance — это наследование».

### 6. Что выведет код?
```csharp
class Registry<T>
{
    public static List<string> Items = new();
    static Registry() => Console.WriteLine($"init {typeof(T).Name}");
}

Registry<int>.Items.Add("a");
Registry<string>.Items.Add("b");
Registry<int>.Items.Add("c");
Console.WriteLine(Registry<int>.Items.Count);
Console.WriteLine(Registry<string>.Items.Count);
```
**Уровень:** junior+
**Хороший ответ:** `init Int32`, `init String`, `2`, `1`. Каждый закрытый generic-тип имеет свои static-поля и свой static-конструктор, который вызывается один раз перед первым обращением к типу.
**Глубже (для junior+):** этот приём — «generic static cache» (по-типовой кэш без словаря), так устроен `EqualityComparer<T>.Default`.
**Follow-up:**
- «Как сделать один общий список для всех T?» — вынести в необобщённый базовый класс или отдельный static-класс.
**Красные флаги:** ответ «3 и 3» или «init один раз».

### 7. Почему нельзя написать `T Add<T>(T a, T b) => a + b;`?
**Уровень:** junior
**Хороший ответ:** Компилятор ничего не знает о `T` — у него может не быть оператора `+`. Операторы — static-методы, а обычные интерфейсы до C# 11 не могли их требовать. Раньше писали перегрузки для каждого числового типа (как LINQ `Sum`). С .NET 7 есть generic math: `where T : INumber<T>` (или `IAdditionOperators<T, T, T>`) — тогда `a + b` компилируется.
**Follow-up:**
- «Что такое static abstract members в интерфейсах?» — интерфейс требует от типа static-член (оператор, `T.Zero`), вызов через параметр типа.
**Красные флаги:** «надо привести к dynamic» как основной ответ (работает, но медленно и без проверки компилятора).

### 8. Как устроен List<T> внутри и что такое capacity?
**Уровень:** junior
**Хороший ответ:** Внутри массив `T[]` и счётчик `Count`. `Capacity` — размер массива. Когда место заканчивается, создаётся новый массив вдвое больше и элементы копируются. Поэтому `Add` — амортизированная O(1), а в худшем случае O(n). Если размер известен заранее — передай capacity в конструктор, чтобы избежать перевыделений.
**Follow-up:**
- «Почему удвоение, а не +10?» — суммарная стоимость копирований при удвоении O(n), при фиксированном шаге — O(n²).
- «Уменьшается ли capacity при Remove?» — нет; есть `TrimExcess`.
**Красные флаги:** «List — это связный список».

### 9. Где пригодится `where T : class, IEntity` и чем это лучше, чем принимать IEntity?
**Уровень:** junior+
**Хороший ответ:** В generic-репозитории: constraint на интерфейс даёт доступ к `Id`, `class` — возможность вернуть `null`. Преимущество перед параметром `IEntity`: метод `T? GetById(int id)` возвращает конкретный тип (`Book`), а не интерфейс — вызывающему не нужно делать cast. Для value types generic ещё и избегает boxing при передаче как интерфейса.
**Follow-up:**
- «Что вернёт `GetById`, если убрать `class`?» — `T?` станет просто «maybe default», для struct — нулевой экземпляр, а не null.
**Красные флаги:** не видит разницы между `void Save(IEntity e)` и `void Save<T>(T e) where T : IEntity`.

### 10. Что такое Try-pattern и как его реализовать в generic-коде?
**Уровень:** junior
**Хороший ответ:** Метод `bool TryXxx(..., out T result)`: возвращает успех, результат — через `out`, исключение не бросает. Применяется, когда неудача — ожидаемый сценарий (`int.TryParse`, `Dictionary.TryGetValue`). В generic-коде при неудаче `result = default`, а атрибут `[MaybeNullWhen(false)]` говорит nullable-анализу, что при `false` значение может быть null.
**Follow-up:**
- «Почему не бросать исключение?» — исключения дорогие (stack trace) и превращают нормальный поток в обработку ошибок.
**Красные флаги:** не знает про `out`; использует Try-методы, но игнорирует возвращаемое значение.

### 11. Можно ли перегрузить методы, отличающиеся только constraints?
**Уровень:** junior+
**Хороший ответ:** Нет. `void M<T>(T x) where T : class` и `void M<T>(T x) where T : struct` — одинаковые сигнатуры, ошибка CS0111. Constraints не являются частью сигнатуры. Обходят разными именами или разными параметрами.
**Follow-up:**
- «А `Foo<T>()` и `Foo<T1, T2>()`?» — можно, различается arity (число параметров типа).
**Красные флаги:** уверенно «да, компилятор выберет по constraint».

### 12. Live coding: напиши generic-метод `Swap` и метод `FirstOrFallback`
```csharp
// Поменять местами две переменные любого типа.
// Вернуть первый элемент последовательности или fallback, если она пуста.
```
**Уровень:** junior
**Хороший ответ:**
```csharp
static void Swap<T>(ref T a, ref T b) => (a, b) = (b, a);

static T FirstOrFallback<T>(IEnumerable<T> items, T fallback)
{
    ArgumentNullException.ThrowIfNull(items);
    foreach (T item in items) return item;
    return fallback;
}
```
Обсуждение: `ref` нужен, иначе меняются копии; `foreach` с ранним `return` перебирает максимум один элемент и работает с ленивыми последовательностями; проверка аргумента.
**Follow-up:**
- «Почему не `items.Count() > 0 ? items.First() : fallback`?» — двойное перечисление, `Count()` перебирает всё.
**Красные флаги:** `Swap` без `ref`; `FirstOrFallback` через `ToList()` всей последовательности.
