# Интервью: модуль 04 — ООП, классы и инкапсуляция

### 1. Что такое класс и объект? Чем класс отличается от структуры (кратко)?
**Уровень:** junior
**Хороший ответ:** Класс — тип, описывающий данные (поля, свойства) и поведение (методы). Объект — экземпляр класса, создаётся через `new` и живёт в managed heap. Класс — reference type: переменная хранит ссылку, при присваивании копируется ссылка, оба имени указывают на один объект. Структура (`struct`) — value type: копируется целиком, обычно живёт там, где объявлена (в стеке или внутри другого объекта). Классы поддерживают наследование, структуры — нет.
**Глубже (для junior+):** у объекта класса есть заголовок (object header, sync block) и указатель на method table — ~16 байт overhead на 64-бит; у struct этого нет. Из-за копирования большие struct'ы невыгодны.
**Follow-up:**
- «Где хранится поле `int` у объекта класса?» → в куче, внутри объекта; «value types в стеке» — упрощение.
- «Что будет при передаче объекта класса в метод?» → копируется ссылка (by value), метод может изменить объект, но не может подменить ссылку у вызывающего без `ref`.
**Красные флаги:** «объект и класс — одно и то же»; «класс копируется при присваивании».

### 2. Чем поле отличается от свойства? Почему публичные поля не используют?
**Уровень:** junior
**Хороший ответ:** Поле — переменная в объекте. Свойство — пара методов get/set (`get_Name`, `set_Name` в IL), выглядит как поле. В свойство можно добавить валидацию, вычисление, разные уровни доступа (`private set`), его можно объявить в интерфейсе. Публичное поле нарушает инкапсуляцию; переход с поля на свойство — binary breaking change (клиенты надо пересобрать). Сериализаторы и binding работают со свойствами.
**Глубже (для junior+):** auto-property компилируется в private-поле `<Name>k__BackingField` и два метода; JIT обычно инлайнит простые get/set, так что по производительности разницы почти нет. C# 14 — ключевое слово `field`.
**Follow-up:**
- «Можно ли передать свойство как `ref`/`out`?» → нет, это не переменная, а методы (поле — можно).
- «Что такое auto-property?» → свойство, для которого компилятор сам генерирует backing field.
**Красные флаги:** «свойства медленнее, поэтому лучше поля»; не знает о `private set`.

### 3. Что такое инкапсуляция? Как её обеспечить в C#?
**Уровень:** junior
**Хороший ответ:** Сокрытие внутреннего состояния и предоставление контролируемого API, через который объект сам поддерживает свои инварианты. Инструменты: модификаторы доступа (`private` поля), свойства с ограниченным setter'ом, валидация в конструкторе и методах, возврат read-only обёрток/копий вместо внутренних коллекций, неизменяемость. Пример: `BankAccount` с `Balance { get; private set; }` и методами `Deposit`/`Withdraw`.
**Глубже (для junior+):** «Tell, don't ask»; anemic model vs rich domain model; инкапсуляция ≠ «геттер и сеттер на каждое поле» — публичный get/set для всего это та же открытость, только многословнее.
**Follow-up:**
- «Если я верну `List<T>` как `IReadOnlyList<T>` — это инкапсуляция?» → нет, можно привести обратно; нужен `AsReadOnly()` или копия.
- «Что такое инвариант?» → условие, истинное для объекта всегда между вызовами методов.
**Красные флаги:** путает инкапсуляцию с «просто private»; не может привести пример инварианта.

### 4. `const` vs `readonly` vs `static readonly`
**Уровень:** junior
**Хороший ответ:** `const` — compile-time константа (примитивы, string, enum), неявно static, значение вшивается в IL вызывающего кода. `readonly` — поле экземпляра, присваивается при объявлении или в конструкторе, вычисляется в runtime, любой тип. `static readonly` — одно на тип, присваивается при объявлении или в static-конструкторе. `readonly` защищает ссылку, а не объект.
**Глубже (для junior+):** проблема версионирования `const` между сборками; `readonly struct`, `readonly`-методы структур (модуль 06); `in`-параметры.
**Follow-up:**
- «Можно ли сделать `const` массив / DateTime?» → нет, только `static readonly`.
- «Почему публичные `const` в библиотеках опасны?» → клиент не увидит новое значение без перекомпиляции.
**Красные флаги:** «readonly — значит объект нельзя изменить»; не знает, что const вшивается.

### 5. Какие модификаторы доступа есть в C#? Что по умолчанию?
**Уровень:** junior
**Хороший ответ:** `public`, `private`, `protected`, `internal`, `protected internal` (наследники ИЛИ сборка), `private protected` (наследники И сборка), плюс `file` для типов. По умолчанию: члены класса и структуры — `private`, типы верхнего уровня — `internal`, члены интерфейса — `public`. Принцип наименьших привилегий.
**Глубже (для junior+):** `[InternalsVisibleTo]` для тестов; `internal` по умолчанию у типов защищает от случайного расширения публичного API.
**Follow-up:**
- «Разница `protected internal` и `private protected`?» → объединение vs пересечение.
- «Как протестировать internal-класс?» → `InternalsVisibleTo("Tests")`.
**Красные флаги:** путает «по умолчанию» (говорит, что члены по умолчанию public).

### 6. Что такое `static`? Static-класс, static-конструктор
**Уровень:** junior
**Хороший ответ:** Static-член принадлежит типу, а не экземпляру — одна копия на приложение; вызывается через имя типа, внутри нет `this`. Static-класс: только static-члены, нельзя создать и наследовать (`Math`, классы extension methods). Static-конструктор: без параметров и модификаторов, вызывается CLR один раз, потокобезопасно, перед первым обращением к типу. Минусы static-состояния: глобальность, сложно тестировать, нужна потокобезопасность.
**Глубже (для junior+):** `beforefieldinit` и момент вызова static-конструктора; исключение в static-конструкторе → `TypeInitializationException`, и тип становится непригодным до конца жизни процесса.
**Follow-up:**
- «Чем static-класс отличается от Singleton?» → Singleton — объект: может реализовывать интерфейс, передаваться как зависимость, подменяться в тестах (через DI).
- «Когда вызывается static-конструктор?» → один раз до первого обращения к static-члену или создания экземпляра.
**Красные флаги:** «static — быстрее, поэтому делаю всё static»; static-поле для данных конкретного пользователя в веб-приложении.

### 7. Какие бывают конструкторы? Что такое цепочка конструкторов?
**Уровень:** junior
**Хороший ответ:** Instance-конструкторы (с параметрами и без), static-конструктор, private-конструктор (запрет создания извне — для фабрик/Singleton). Если не объявлен ни один — компилятор создаёт конструктор по умолчанию. Цепочка `: this(...)` — вызов другого конструктора того же класса до тела текущего, чтобы логика инициализации была в одном месте. `: base(...)` — вызов конструктора базового класса.
**Глубже (для junior+):** primary constructors для классов (C# 12) — параметры доступны во всём теле класса, но это не свойства; порядок инициализации: инициализаторы полей → base-конструктор → тело.
**Follow-up:**
- «Можно ли вызвать виртуальный метод из конструктора?» → можно, но опасно (модуль 05).
- «В каком порядке выполняются конструктор и object initializer?» → сначала конструктор, потом присваивания initializer'а.
**Красные флаги:** не знает, что дефолтный конструктор исчезает, если объявлен свой.

### 8. `set`, `init`, get-only и `required`
**Уровень:** junior
**Хороший ответ:** get-only — присвоение только в конструкторе; `init` — в конструкторе и object initializer (а также в `with` для records); `set` — всегда. `required` — компилятор требует задать член при создании объекта. Вместе дают неизменяемые объекты с читаемым созданием.
**Глубже (для junior+):** `[SetsRequiredMembers]` на конструкторе, который сам задаёт все required-члены; `init` можно обойти рефлексией — это проверка компилятора, а не runtime.
**Follow-up:**
- «Почему не просто конструктор?» → конструктор с 8 параметрами нечитаем и хрупок при добавлении полей.
**Красные флаги:** «init — то же, что readonly-поле».

### 9. Что такое extension method и как он работает?
**Уровень:** junior
**Хороший ответ:** Static-метод в static (не generic, не nested) классе, первый параметр с `this`. Компилятор переписывает `x.Foo()` в `Ext.Foo(x)`. Не видит private-члены, проигрывает методу экземпляра с той же сигнатурой, требует `using` namespace, может быть вызван на null. LINQ построен на extension methods.
**Глубже (для junior+):** C# 14 extension members (`extension(T x) { ... }`) — можно объявлять extension-свойства и static-члены; extension methods на интерфейсах дают «методы по умолчанию» без изменения интерфейса.
**Follow-up:**
- «Можно ли через extension method переопределить метод класса?» → нет, метод экземпляра всегда побеждает.
- «Почему LINQ — extension, а не методы `IEnumerable<T>`?» → добавление методов в интерфейс сломало бы все реализации; так можно расширить любой существующий тип.
**Красные флаги:** «extension method добавляет метод в класс» (буквально).

### 10. Что выведет код?
```csharp
var t1 = new Ticket(); var t2 = new Ticket();
Console.WriteLine($"{t1.Id} {t2.Id} {Ticket.Count}");
class Ticket
{
    public static int Count;
    public int Id { get; } = ++Count;
}
```
**Уровень:** junior
**Хороший ответ:** `1 2 2`. Инициализатор свойства выполняется для каждого экземпляра при создании, `Count` общий для всех. Первый объект: Count=1, Id=1; второй: Count=2, Id=2.
**Follow-up:**
- «Что будет, если Ticket создают из 10 потоков?» → возможны одинаковые Id: `++Count` не атомарен, нужен `Interlocked.Increment`.
**Красные флаги:** `1 1 2` (думает, что Count у каждого свой) или `0 0 2`.

### 11. Что выведет код?
```csharp
var list = new Holder();
var items = (List<int>)list.Items;
items.Add(42);
Console.WriteLine(list.Items.Count);
class Holder
{
    private readonly List<int> _items = new();
    public IReadOnlyList<int> Items => _items;
}
```
**Уровень:** junior+
**Хороший ответ:** `1`. `IReadOnlyList<int>` — лишь интерфейс над тем же `List<int>`; приведение возвращает оригинал, и инкапсуляция нарушена. Решение — `_items.AsReadOnly()` (тогда приведение к `List<int>` бросит `InvalidCastException`) или копия.
**Follow-up:**
- «Чем `AsReadOnly()` отличается от `ToList()`?» → обёртка видит дальнейшие изменения оригинала и не копирует данные; `ToList()` — снимок, O(n) памяти.
**Красные флаги:** «будет ошибка компиляции, список же read-only».

### 12. Live coding: класс `Stopwatch`-подобный таймер / счётчик посещений
**Уровень:** junior
**Задание интервьюера:** «Напишите класс `VisitCounter`: метод `Visit(string page)`, свойство `TotalVisits`, метод `GetVisits(string page)` (0 для неизвестной страницы), `TopPage` — самая посещаемая страница или null. Страницы без учёта регистра. Внешний код не должен иметь возможность изменить статистику напрямую».
**Хороший ответ:**
```csharp
public sealed class VisitCounter
{
    private readonly Dictionary<string, int> _visits = new(StringComparer.OrdinalIgnoreCase);

    public int TotalVisits { get; private set; }

    public void Visit(string page)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(page);
        _visits[page] = _visits.GetValueOrDefault(page) + 1;
        TotalVisits++;
    }

    public int GetVisits(string page) => _visits.GetValueOrDefault(page);

    public string? TopPage => _visits.Count == 0 ? null : _visits.MaxBy(p => p.Value).Key;
}
```
Интервьюер смотрит: `private readonly` словарь, `private set`, guard clause, `StringComparer.OrdinalIgnoreCase` вместо `ToLower()`, не отдаёт словарь наружу.
**Follow-up:**
- «Как сделать потокобезопасным?» → `lock` или `ConcurrentDictionary` + `Interlocked` (модуль 13).
- «Почему `StringComparer`, а не `page.ToLower()`?» → не создаёт новых строк, корректен для культур.
**Красные флаги:** публичный словарь; `static` всё; нет проверки входных данных.

### 13. Что такое `partial` class и nested type? Когда их использовать?
**Уровень:** junior
**Хороший ответ:** `partial` разделяет тип на несколько файлов, компилятор склеивает их; основное применение — сгенерированный код (WinForms/WPF, source generators, EF scaffold). Nested type — тип внутри другого; имеет доступ к private-членам внешнего; используют для деталей реализации (узел списка, enumerator).
**Follow-up:**
- «Можно ли partial-части объявить в разных сборках?» → нет, только в одной.
**Красные флаги:** «partial — чтобы класс можно было дописать из другого проекта».

### 14. Что такое value object? Пример.
**Уровень:** junior+
**Хороший ответ:** Объект, определяемый значениями, без идентичности: Money, Email, DateRange. Неизменяемый, самовалидирующийся, равенство по значению. Операции возвращают новый объект. В C# удобно реализовать через `record`/`readonly record struct` (модуль 06) или класс с переопределёнными `Equals`/`GetHashCode`.
**Глубже (для junior+):** DDD: entity (идентичность через Id, изменяемая) vs value object; «primitive obsession» — строки и decimal вместо Email/Money.
**Follow-up:**
- «Почему `string` в .NET immutable?» → безопасность, интернирование, потокобезопасность, использование как ключа.
**Красные флаги:** не может объяснить, зачем неизменяемость.
