## Задача 1. Shapes

**Обязательно:**
- Все тесты `ShapeTests` зелёные; все наследники — `override` abstract-членов.
- Валидация в конструкторах; в `Triangle` сначала проверка положительности, потом неравенства треугольника.
- `Describe` в базовом классе с `InvariantCulture`.
- `ShapeStats` работает через `Shape`, без проверок типа.

**Хорошо бы:**
- Get-only свойства (неизменяемые фигуры).
- `Largest` считает `Area()` один раз на фигуру.
- `string.Create(CultureInfo.InvariantCulture, $"...")` или `ToString("0.00", CultureInfo.InvariantCulture)`.

**Частые ошибки** → реакция и **почему**:
- `Describe` сделан `virtual` и переопределён в каждом наследнике → дублирование; в базе можно вызвать виртуальные `Name/Area/Perimeter`.
- `if (shape is Circle c) ... else if (shape is Rectangle r)` в `TotalArea` → нарушение OCP, полиморфизм не использован.
- `Square : Rectangle` → спроси про LSP (задача 6).
- `Math.Pow(r, 2)` — не ошибка, но `r * r` проще и быстрее.

## Задача 3. Output predictions

**Обязательно:** все 4 строки точные (`"Derived field | Base ctor | Derived.Init a=set b=null | Derived ctor"`, `"B B C"`, `"object string Meow"`, `"True True False True"`) **и** устное объяснение каждой.
**Частые ошибки:**
- ConstructorOrder: ставят `Base ctor` первым (не знают, что инициализаторы полей наследника идут до base-конструктора) или пишут `Base.Init` (не понимают, что объект уже Derived). Объясни: тип объекта фиксируется при выделении памяти.
- NewVsOverride: `"A B C"` или `"C C C"` → разобрать цепочку override.
- OverloadVsOverride: `"string string Meow"` → перегрузка выбирается по статическому типу при компиляции.
- Подобрал ответы запуском без объяснения → задача не принята, пока не объяснит.

**Вопросы к студенту при /check:**

2. Чем выбор перегрузки отличается от выбора override?

## Задача 4. Notifications

**Обязательно:**
- Каналы хранят `private readonly List<string>`, наружу — read-only.
- `EmailChannel` вызывает default method через `((INotificationChannel)this).Format(...)`.
- `SmsChannel` реализует `string INotificationChannel.Format(string)` явно.
- `NotificationService` зависит только от интерфейса, копирует коллекцию каналов, валидирует аргументы до цикла.

**Хорошо бы:** `Send` переиспользует `CanSend`; тексты исключений с именем получателя.
**Частые ошибки:**
- Реализовал `Format` в SMS как публичный метод — тесты пройдут; спроси, в чём разница с явной реализацией (видимость через переменную `SmsChannel`).
- `NotificationService` проверяет `channel is EmailChannel` → зачем тогда интерфейс?
- Хранит переданный `IEnumerable` без копирования → если это LINQ-запрос, он будет перевычисляться при каждом `Notify` (modules 11), а изменения внешнего списка влияют на сервис.

## Quiz

1. **Что выведет код?**
   ```csharp
   class A { public virtual string M() => "A"; }
   class B : A { public new string M() => "B"; }
   A x = new B();
   Console.WriteLine(x.M() + ((B)x).M());
   ```
   **Ответ:** `AB`. **Почему:** `new` скрывает, а не переопределяет; вызов через `A` → `A.M`, через `B` → `B.M`.

2. **Что выведет код?**
   ```csharp
   class P { public P() => Console.Write("P"); }
   class C : P { public C() => Console.Write("C"); }
   class G : C { public G() => Console.Write("G"); }
   new G();
   ```
   **Ответ:** `PCG`. **Почему:** тела конструкторов выполняются от базового к наследнику.

3. **Найди ошибку:**
   ```csharp
   abstract class Shape { public abstract double Area(); }
   class Circle : Shape { public double Area() => 3.14; }
   ```
   **Ответ:** CS0534 — `Circle` не реализует abstract `Area` (нужен `override`); плюс CS0114 — метод скрывает член базы. **Почему:** без `override` это новый метод, abstract-слот остаётся пустым.

4. **Выбор варианта.** Что из этого НЕЛЬЗЯ в интерфейсе C# 12? A) свойство B) default-метод C) поле экземпляра D) static-метод.
   **Ответ:** C. **Почему:** интерфейс не хранит состояние экземпляра — иначе вернулась бы проблема ромба для данных.

5. **Что выведет код?**
   ```csharp
   object o = "text";
   Console.WriteLine(Show(o) + " " + Show("text"));
   static string Show(object x) => "obj";
   static string Show(string x) => "str";
   ```
   **Ответ:** `obj str`. **Почему:** перегрузка выбирается компилятором по статическому типу аргумента.

6. **Что выведет код?**
   ```csharp
   object o = 42;
   var s = o as string;
   Console.WriteLine(s is null);
   Console.WriteLine(o is int n && n > 40);
   ```
   **Ответ:** `True`, `True`. **Почему:** `as` не бросает исключение, а возвращает null; `is int n` — type pattern с unboxing в переменную.

7. **Найди ошибку:**
   ```csharp
   interface ILog { void Write(string m); void Error(string m) => Write("ERR " + m); }
   class Log : ILog { public void Write(string m) => Console.WriteLine(m); }
   new Log().Error("x");
   ```
   **Ответ:** CS1061 — у `Log` нет метода `Error`. **Почему:** default interface method доступен только через ссылку `ILog`: `((ILog)new Log()).Error("x")`.

8. **Что выведет код?**
   ```csharp
   class B { public B() { Hello(); } public virtual void Hello() => Console.Write("B"); }
   class D : B { string s = "D"; public override void Hello() => Console.Write(s ?? "null"); }
   new D();
   ```
   **Ответ:** `D`. **Почему:** инициализатор поля `s` выполняется до конструктора `B`, а виртуальный вызов уходит в `D.Hello`. (Если бы `s` присваивалось в теле конструктора `D`, было бы `null`.)
