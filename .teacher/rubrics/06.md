# Рубрика модуля 06

## Задача 1. Point

**Обязательно:**
- `Equals(Point?)` — основная логика с null-проверкой; `Equals(object?)` делегирует через `obj is Point p && Equals(p)`.
- `GetHashCode` на тех же полях (`HashCode.Combine(X, Y)`).
- `==` через `is null`, `!=` через `!(a == b)`.

**Хорошо бы:** `ReferenceEquals(this, other)` как быстрый путь; объяснение, почему класс `sealed` и свойства неизменяемы.
**Частые ошибки** → реакция и **почему**:
- `left == null` внутри `operator ==` → StackOverflow; попроси объяснить, какой оператор вызывается.
- `X ^ Y` в хэше → работает, но коллизии (`(1,2)` и `(2,1)`, все `(n,n)` → 0). Обсуди распределение.
- `Equals(object)` через `(Point)obj` без проверки → `InvalidCastException` на чужом типе.
- `obj.GetType() == GetType()` — допустимо, но для sealed-класса избыточно.
- Хэш через `ToString().GetHashCode()` → аллокация строки на каждый вызов.

**Вопросы к студенту при /check:**
1. Зачем `IEquatable<T>`, если есть `Equals(object)`? (без boxing для struct, строгая типизация, используется `EqualityComparer<T>.Default`)
2. Что будет с Dictionary, если X станет изменяемым?
3. Почему `sealed` важен для корректного равенства?

## Задача 2. Records

**Обязательно:** `with` в обеих операциях; валидация аргументов; округление AwayFromZero; в `ShoppingList` — `Equals` с `SequenceEqual` и согласованный `GetHashCode` по всем элементам.
**Хорошо бы:** `ReferenceEquals` быстрый путь; Ordinal-сравнение владельца.
**Частые ошибки:**
- Создаёт `new ProductDto(product.Sku, ..., newPrice)` вместо `with` → работает, но хрупко при добавлении свойств.
- `GetHashCode` возвращает `Owner.GetHashCode()` только → корректно по контракту (равные → равные хэши), но больше коллизий. Отметить как допустимое, обсудить компромисс.
- `GetHashCode` через `Items.GetHashCode()` → нарушение контракта (хэш ссылки).
- Объявил `public virtual bool Equals` в sealed record → ошибка компиляции; объясни правило.

**Вопросы к студенту при /check:**
1. Что генерирует компилятор для record?
2. Почему `with` — поверхностная копия и чем это опасно?
3. Что такое `EqualityContract` и зачем он record'ам с наследованием? (junior+)

## Задача 3. Statistics

**Обязательно:** один проход в `MinMax`; исключения для null/пустой коллекции; `long` для суммы; деконструкция в `Swap`.
**Частые ошибки:**

## Задача 5. Money (readonly record struct)

**Обязательно:** явное свойство `Currency` с `private readonly` полем, инициализированным параметром, и `init`-аксессором с нормализацией; все операторы с проверкой валюты; `*` с округлением; `ToString` invariant; равенство не написано вручную.
**Хорошо бы:** общий `EnsureSameCurrency`; комментарий про `default(Money)` (Currency == null).
**Частые ошибки:**
- `{ get; init; } = Normalize(Currency)` → тест с `with` падает; хороший момент объяснить, что инициализатор выполняется только при конструировании.
- Переопределил `Equals`/`==` вручную → лишний код, а `==` в record struct вообще нельзя объявить самому (ошибка).
- Объявил только `<` без `>` → ошибка компиляции CS0216.
- Нормализация `ToUpper()` без Invariant.

## Задача 6. SeatKey + BookingService ⭐

**Обязательно:** `IEquatable<SeatKey>`; `Equals` с `StringComparison.OrdinalIgnoreCase`; `GetHashCode` через `StringComparer.OrdinalIgnoreCase.GetHashCode(Hall)` с защитой от null; `==`/`!=`; сервис на `Dictionary` с `TryAdd`/`TryGetValue`/`Remove`; сортировка без учёта регистра.
**Хорошо бы:** сначала сравнение int-полей, потом строки; объяснение альтернатив (нормализация Hall в конструкторе с потерей исходного регистра; `IEqualityComparer<SeatKey>` для словаря).
**Частые ошибки:**
- `Hall.GetHashCode()` при case-insensitive Equals → нарушение контракта; `HashSet` и `TryBook` с "RED" падают. Это главный учебный момент задачи.
- `Hall.ToLower().GetHashCode()` → работает, но аллокация строки на каждый хэш и проблемы культуры (`ToLower` без Invariant).
- `ContainsKey` + `Add` → два поиска вместо `TryAdd`.
- `default(SeatKey).GetHashCode()` бросает `ArgumentNullException` → тест ловит.

**Вопросы к студенту при /check:**

2. Почему нельзя было оставить хэш по умолчанию от `ValueType`?
3. Как сделать то же самое без ручного Equals, через `IEqualityComparer<T>`?

## Quiz

1. **Что выведет код?**
   ```csharp
   var a = new P(1); var b = new P(1);
   Console.WriteLine($"{a == b} {a.Equals(b)}");
   class P { public P(int x) => X = x; public int X { get; } }
   ```
   **Ответ:** `False False`. **Почему:** класс без переопределения — ссылочное равенство и для `==`, и для `Equals`.

2. **Что выведет код?**
   ```csharp
   var a = new R(1); var b = new R(1);
   Console.WriteLine($"{a == b} {ReferenceEquals(a, b)}");
   record R(int X);
   ```
   **Ответ:** `True False`. **Почему:** record генерирует равенство по значению, но это два разных объекта.

3. **Найди ошибку:**
   ```csharp
   struct S { public int X; }
   var a = new S(); var b = new S();
   Console.WriteLine(a == b);
   ```
   **Ответ:** CS0019 — оператор `==` не определён для `S`. **Почему:** для struct компилятор не генерирует `==`; нужно перегрузить или использовать `Equals`/`record struct`.

4. **Что выведет код?**
   ```csharp
   var list = new List<S> { new S { X = 1 } };
   var s = list[0]; s.X = 5;
   Console.WriteLine(list[0].X);
   struct S { public int X; }
   ```
   **Ответ:** `1`. **Почему:** `list[0]` возвращает копию struct.

5. **Выбор варианта.** Переопределили `Equals`, но не `GetHashCode`. Что произойдёт? A) ошибка компиляции B) warning, и `HashSet` может «не находить» равные объекты C) всё работает D) исключение в runtime.
   **Ответ:** B. **Почему:** компилятор лишь предупреждает (CS0659), а хэш по ссылке отправит равные объекты в разные бакеты.

6. **Что выведет код?**
   ```csharp
   var r1 = new Bag(new List<int> { 1 });
   var r2 = new Bag(new List<int> { 1 });
   Console.WriteLine(r1 == r2);
   record Bag(List<int> Items);
   ```
   **Ответ:** `False`. **Почему:** record сравнивает `Items` через `EqualityComparer<List<int>>.Default` — по ссылке.

7. **Что выведет код?**
   ```csharp
   object x = 5, y = 5;
   Console.WriteLine($"{x == y} {x.Equals(y)}");
   ```
   **Ответ:** `False True`. **Почему:** каждое присваивание упаковывает int в новый объект; `==` для `object` сравнивает ссылки, `Equals` виртуальный — вызывается `Int32.Equals`.

8. **Что выведет код?**
   ```csharp
   var p = new Pos { X = 1 };
   var set = new HashSet<Pos> { p };
   p.X = 2;
   Console.WriteLine(set.Contains(p));
   record Pos { public int X { get; set; } }
   ```
   **Ответ:** почти наверняка `False`. **Почему:** хэш record зависит от X; после изменения объект ищется в другом бакете. Мораль: изменяемые ключи ломают хэш-коллекции.
