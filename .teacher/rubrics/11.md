## Задача 1. OrderReports

**Обязательно:**
- `TotalRevenue`: `Where` + `Sum` (без ручного цикла, без проверки на пустоту — `Sum` вернёт 0).
- `LargeOrderIds`: `OrderByDescending(Total).ThenBy(Id)`, `ToList()`.
- `TopProducts`: `SelectMany` → `GroupBy(Product)` → сумма Quantity → `OrderByDescending` → `ThenBy(…, StringComparer.Ordinal)` → `Take`; проверка `count`.
- `FirstOrderOf`: `FirstOrDefault` (не `First`), второй ключ `Id`.
- `IsLoyalCustomer`: проверка аргумента, `Any`/`Count` с условиями.

**Хорошо бы:** хотя бы один метод в query syntax (`let` для Total); материализация заказов покупателя в `IsLoyalCustomer`.

**Частые ошибки** → реакция и **почему**:
- `OrderBy(...).OrderBy(...)` → тест с равными Total упадёт; **почему:** второй `OrderBy` пересортировывает всё, `ThenBy` уточняет.
- `First()` в `FirstOrderOf` → исключение для неизвестного покупателя.
- `Count(...) > 0` вместо `Any(...)` — не баг, но спроси разницу.
- `TopProducts` по сумме денег вместо количества или без фильтра по Completed — внимательность к спецификации.
- `.ThenBy(x => x.Product)` без компаратора → сейчас тесты пройдут (ASCII), но обсуди culture-sensitive сравнение.

## Задача 2. SalesAnalytics

**Обязательно:**
- `RevenueByCategory`: `SelectMany` + `GroupBy` + `ToDictionary(g => g.Key, g => g.Sum(...))`.
- `SalesByMonth`: составной ключ (анонимный тип или кортеж), хронологическая сортировка (год, затем месяц).
- `OrderIdsByCustomer`: `ToLookup(o => o.Customer, o => o.Id)` — все статусы.
- `AverageOrderValueByCustomer`: группировка Completed + `Average`.
- `RevenueChanges`: `Zip` с `Skip(1)`.

**Частые ошибки:**
- Ключ группировки `$"{Year}-{Month}"` и сортировка по строке → `"2024-12"` < `"2024-2"` (лексикографически)! Тест `SortsAcrossYears` упадёт. Отличный учебный момент.
- Сортировка только по месяцу → годы перемешаются.
- `GroupBy` вместо `ToLookup` с ручным словарём — работает, но спроси разницу.
- `RevenueChanges` через `for` с индексами — допустимо, но попроси вариант с `Zip`.
- `ToDictionary(o => o.Customer)` по заказам → `ArgumentException` (дубликат ключа).

## Задача 3. HrQueries

**Обязательно:**
- Inner join через `Join` (или query `join`), совместимые ключи `int?`.
- Left join: `GroupJoin` + `SelectMany`/`from … DefaultIfEmpty()`, `department?.Name`.
- `DepartmentSummaries` через `GroupJoin` от отделов; обработка пустой группы (Average → 0).
- Self-join по `ManagerId`; сортировка ordinal.

**Хорошо бы:** материализация `employees` в self-join; `StringComparer.Ordinal` в сортировках.

**Частые ошибки:**

## Задача 4. Inventory (баги ленивости)

**Обязательно — все три исправления с комментариями «почему»:**
1. `GetLowStockSnapshot` → `.ToList()`. Объяснение: `Where` над живым `_items`, перечисляется позже, видит изменения и падает при модификации во время перебора.
2. `ImportSkus` → материализовать `Select(Normalize)` один раз. Объяснение: `Count()` и `Distinct()` — два перечисления, `Normalize` вызывается 2n раз, одноразовый источник падает.
3. `RemoveEmpty` → `_items.RemoveAll(...)` (или перебор `ToList()`-копии / обратный `for`). Объяснение: изменение коллекции во время ленивого перебора.

**Хорошо бы:** понимание, что `Distinct` формально не гарантирует порядок (эталон — HashSet + List); `RemoveAll` предпочтительнее `ToList()` + `Remove` (O(n) против O(n²)).

**Частые ошибки:**
- Исправление тестов вместо кода → недопустимо; обсуди.
- `GetLowStockSnapshot` → `.ToArray()` — тоже правильно.
- В `RemoveEmpty` перебор `.ToList()` + `_items.Remove(item)` — тесты пройдут, но O(n²) и удаляет первый **равный** элемент (record equality!) — обсуди, почему `RemoveAll` надёжнее.
- Исправление только тех мест, где падают тесты, без понимания — попроси объяснить каждый баг словами.

## Задача 5. Исследование (без тестов)

**Проверь в ответах:**
- `First()` печатает `check 1`, `check 2`, `map 2` и останавливается (streaming); `ToList()` и `Count()` — полный проход каждый (повторное выполнение).
- С `OrderBy` все `check` идут до первого `map`: `OrderBy` — non-streaming, читает весь источник.
- `Expression` выводится как текст дерева; `Func` — «чёрный ящик», `Expression` — данные (`e.Body` = `(n > 2)`).
- `All` → `True`, `Sum` → `0`, `Average` → `InvalidOperationException`.

## Задача 6. ⭐ MyLinqExtensions

**Обязательно:**
- Схема «внешний метод с проверками + итератор» для всех трёх.
- `Batch`: новый список на каждый пакет, отдача сразу при заполнении, хвост без пустого пакета.
- `DistinctByKey`: `HashSet<TKey>(comparer)` внутри итератора, streaming.
- `Pairwise`: ручной enumerator с `using`, один проход.

**Хорошо бы:** capacity для пакета; static local functions.

**Частые ошибки:**
- `batch.Clear()` вместо нового списка → тест `SplitsIntoBatches` упадёт (все пакеты после `ToList()` окажутся одним и тем же пустым/последним списком). Попроси объяснить, почему.
- `Batch` через `source.ToList()` + `GetRange` → тест с бесконечным источником зависнет (OutOfMemory). Предупреди заранее, если видишь такой код.
- `Pairwise` через `Zip(source, source.Skip(1))` → двойное перечисление источника; на бесконечном работает, но обсуди multiple enumeration.
- `HashSet` во внешнем методе → повторный перебор результата даст пустую последовательность.
- Проверки внутри итератора → тесты `ThrowImmediately` упадут.

## Quiz

1. **Что выведет код?**
   ```csharp
   var list = new List<int> { 1, 2, 3 };
   var q = list.Where(x => x > 1);
   list.Add(10);
   Console.WriteLine(q.Count());
   ```
   **Ответ:** `3` (2, 3, 10). **Почему:** deferred execution — запрос выполняется при `Count()`.

2. **Что выведет код?**
   ```csharp
   int calls = 0;
   var q = Enumerable.Range(1, 5).Select(x => { calls++; return x; });
   var a = q.Count();
   var b = q.ToList();
   Console.WriteLine(calls);
   ```
   **Ответ:** `10`. **Почему:** два перечисления — `Select` выполняется дважды (multiple enumeration). (В современных .NET `Count()` по `Select` над `Range` может быть оптимизирован без вызова селектора — тогда `5`; на собеседовании отвечай «10» и упомяни, что от оптимизаций полагаться нельзя.)

3. **Найди ошибку:**
   ```csharp
   var sorted = people.OrderBy(p => p.LastName).OrderBy(p => p.FirstName);
   ```
   **Ответ:** второй `OrderBy` отменяет первый; нужен `ThenBy`. **Почему:** `OrderBy` начинает сортировку заново; стабильность сохранит прежний порядок только среди равных FirstName — то есть получится сортировка по FirstName, затем LastName, а не наоборот.

4. **Что вернёт?** `new List<int>().All(x => x > 0)` и `new List<int>().Any(x => x > 0)`
   **Ответ:** `True` и `False`. **Почему:** vacuous truth для `All`; `Any` ищет хотя бы один.

5. **Выбери оператор:** найти пользователя по уникальному email; если найдено два — это ошибка данных. A) `First` B) `FirstOrDefault` C) `SingleOrDefault` D) `Where(...).ToList()[0]`
   **Ответ:** C. **Почему:** `SingleOrDefault` вернёт null, если нет, и бросит исключение, если больше одного — нарушение инварианта не пройдёт незамеченным.

6. **Что выведет код?**
   ```csharp
   var nums = new[] { 1, 2, 3 };
   var r = nums.Select(n => n * 2).Where(n => n > 2).Sum();
   Console.WriteLine(r);
   ```
   **Ответ:** `10` (4 + 6).

7. **Найди проблему производительности:**
   ```csharp
   var result = orders.Where(o => blockedCustomers.Contains(o.Customer)).ToList(); // blockedCustomers: List<string>
   ```
   **Ответ:** `List.Contains` внутри `Where` — O(n × m). **Почему:** для каждого заказа линейный поиск. Исправление: `var blocked = blockedCustomers.ToHashSet();`.

8. **Где выполнится фильтр?**
   ```csharp
   IEnumerable<Order> orders = db.Orders;
   var big = orders.Where(o => o.Total > 1000).ToList();
   ```
   **Ответ:** в памяти. **Почему:** статический тип — `IEnumerable<Order>`, поэтому вызван `Enumerable.Where` (extension methods выбираются по статическому типу); из БД загрузится вся таблица. Нужно `IQueryable<Order>`.
