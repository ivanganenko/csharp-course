# Рубрика модуля 09

> Общее правило модуля: на каждом /check спрашивай сложность по времени и памяти. Ответ «O(n)» без объяснения — не принимается.

## Задача 1. WordFrequency

**Обязательно:**
- `ThrowIfNull`; один проход (или `Split` с разумным набором разделителей — допустимо, но обсуди аллокации).
- `ToLowerInvariant` (не `ToLower`).
- Счётчик через `TryGetValue` / `GetValueOrDefault` / `CollectionsMarshal`, без `KeyNotFoundException`.
- `Top`: проверка `n`, сортировка по двум ключам (count desc, word ordinal asc), `Math.Min(n, count)`.

**Хорошо бы:**
- `StringComparer.Ordinal` в словаре (ключи уже нормализованы).
- Повторное использование `Count` внутри `Top`.
- Упоминание `PriorityQueue` размера k для top-k (O(m log k)).

**Частые ошибки:**
- `if (dict.ContainsKey(w)) dict[w]++; else dict[w] = 1;` — работает, но три поиска вместо двух; спроси «сколько раз считается хэш?».
- `text.Split(' ')` → пунктуация остаётся в словах (`"world!"`), тесты упадут. Хороший момент обсудить, что «слово» — это спецификация.
- `ToLower()` без культуры → **почему плохо:** в турецкой культуре `"I".ToLower()` = `"ı"`; результат зависит от машины.
- Сортировка `OrderBy(w => w)` без компаратора → culture-sensitive сравнение; для ASCII совпадёт, но нарушает спецификацию (ordinal).
- Забыто последнее слово в тексте без завершающего разделителя.

**Вопросы к студенту при /check:**
1. Какая сложность `Count`? `Top`? Как улучшить `Top` для top-10 из миллиона слов?
2. Почему `TryGetValue` лучше пары `ContainsKey` + индексатор?
3. Что изменится, если создать словарь с `StringComparer.OrdinalIgnoreCase` и не приводить регистр?

## Задача 2. Deduplicator

**Обязательно:**
- `HashSet<T>(comparer)` + `List<T>`; использование результата `HashSet.Add`.
- Передача `comparer` в HashSet (null допустим — HashSet сам возьмёт default).
- `FindDuplicates`: второй HashSet (или Dictionary со счётчиком) для «один раз».

**Хорошо бы:** не дублировать проверку `Contains` + `Add`.

**Частые ошибки:**
- `if (!result.Contains(item))` → O(n²). Тест с 200 000 пройдёт (≈ 2·10⁸ сравнений, доли секунды), **но задача не принимается**: попроси посчитать для 10⁶ различных элементов.
- `items.Distinct().ToList()` → нарушено условие «без LINQ»; плюс обсуди: `Distinct` документирован как неупорядоченный результат (по факту сохраняет порядок, но контракт этого не обещает).
- Игнорирование `comparer` → тест с OrdinalIgnoreCase упадёт.
- В `FindDuplicates` элемент, встреченный 3 раза, добавляется дважды.

**Вопросы к студенту при /check:**
1. Какие методы `IEqualityComparer<T>` вызывает HashSet и в каком порядке?
2. Сколько памяти использует решение? Можно ли за O(1) памяти? (Только с сортировкой и потерей порядка, O(n log n).)

## Задача 3. TwoSum

**Обязательно:**
- Один проход, `Dictionary<int, int>` значение → индекс.
- Поиск партнёра ДО добавления текущего элемента.
- Сохранение первого вхождения (`TryAdd` или проверка `ContainsKey`).
- `null` при отсутствии пары; `ThrowIfNull`.

**Хорошо бы:** учёт переполнения `target - x` (long); capacity словаря = длина массива.

**Частые ошибки:**
- Двойной цикл O(n²) → тесты проходят, но **не принимается**; попроси объяснить, как ускорить, и переписать.
- Сначала заполнить весь словарь, потом искать → элемент может сложиться сам с собой (`[3, 1]`, target 6 → (0, 0)), или индекс перезаписан последним вхождением → тест `UsesFirstOccurrence` упадёт.
- `dict[x] = j` (перезапись) вместо `TryAdd`.
- Возврат `(-1, -1)` вместо `null` → обсуди «магические значения» vs nullable.

**Вопросы к студенту при /check:**
1. Сложность по времени и памяти? Что мы «обменяли» на скорость?
2. Как решить на отсортированном массиве двумя указателями? Почему здесь это не подходит напрямую? (Индексы теряются при сортировке.)
3. Что будет при `target = 0` и `x = int.MinValue`?

## Задача 4. Sequences

**Обязательно:**
- Разделение на внешний метод (валидация) и итератор (локальная функция или приватный метод).
- `ThrowIfNegativeOrZero` / `ThrowIfNull`.
- `Range` без переполнения (`long` или проверка `current > end - step`).
- `EveryNth` без материализации источника.

**Хорошо бы:** static local functions; `Naturals` без переполнения на `int.MaxValue`.

**Частые ошибки:**
- Проверки внутри метода с `yield` → тесты `ThrowImmediately` падают. Это главный учебный момент: попроси объяснить, ПОЧЕМУ так (компилятор переносит всё тело в `MoveNext`).
- `for (int i = from; i < to; i += step)` → переполнение, бесконечный цикл; тест с `Take(10)` покажет «мусор». Обсуди `checked`.
- `EveryNth` через `source.ToList()` и индексы → не работает с бесконечной последовательностью (тест зависнет до OutOfMemory!). Если студент так сделал и тест «висит» — объясни причину.
- `EveryNth` через `ElementAt(i)` в цикле → O(n²) и многократное перечисление.

**Вопросы к студенту при /check:**
1. Что генерирует компилятор для метода с `yield return`?
2. Когда начинает выполняться тело итератора? Что будет, если перебрать результат дважды?
3. Как бы ты проверил ленивость своего метода тестом?

## Задача 5. SupportDesk

**Обязательно:**
- `PriorityQueue` с приоритетом `(priority, sequence)` (или аналог: `SortedSet` с компаратором по (priority, seq)).
- `HashSet<string>` для `Contains`/дубликатов (Ordinal).
- `List<string>` для истории, наружу `IReadOnlyList`.
- Валидация `ArgumentException.ThrowIfNullOrWhiteSpace`, дубликат → `InvalidOperationException` без изменения состояния.
- Комментарии «почему эта коллекция» над полями.

**Хорошо бы:** `TryDequeue`; `Count` из HashSet; порядок «сначала проверка, потом мутация».

**Частые ошибки:**
- `PriorityQueue<string, int>` без порядкового номера → тест FIFO с 20 элементами упадёт (или пройдёт случайно на малых данных — обсуди!). **Почему:** heap не стабилен.
- `Contains` через перебор `_queue.UnorderedItems` → O(n).
- `List` + `Sort` при каждом `Submit` → O(n log n) на операцию.
- Дубликат добавлен в очередь до проверки → состояние «поехало».

**Вопросы к студенту при /check:**
1. Почему одного PriorityQueue недостаточно?
2. Как реализовать `Cancel(id)`? (Ленивое удаление: убрать из HashSet, а в `TakeNext` пропускать id, которых нет среди ожидающих; с повторным Submit того же id — хранить актуальный sequence в Dictionary.)
3. Какая сложность каждого метода?

## Задача 6. Исследование (без тестов)

**Проверь в ответах:**
- `List.Contains` растёт ~в 10 раз при росте N в 10 раз (O(n)); `HashSet.Contains` почти не меняется (O(1)).
- Capacity: 0 → 4 → 8 → 16 …; с начальной capacity 1000 — без перевыделений до 1000.
- Без `GetHashCode` — `Contains` возвращает `false`; с `GetHashCode() => 0` — корректно, но медленно (все в одном бакете, O(n)).
- Запуск в Release (`-c Release`) и прогрев — плюс, если студент об этом подумал. Упомяни BenchmarkDotNet как профессиональный инструмент.

## Задача 7. ⭐ LruCache

**Обязательно:**
- `Dictionary<TKey, LinkedListNode<...>>` + `LinkedList<...>`, ключ хранится в узле.
- `TryGet` переносит узел в начало; `ContainsKey` — нет.
- `Put`: обновление существующего — без вытеснения; новый при `Count == Capacity` — удалить хвост из списка и словаря.
- Валидация capacity.

**Хорошо бы:**
- Перенос того же узла (`Remove(node)` + `AddFirst(node)`) без новой аллокации.
- Проверка `node == First` перед переносом.
- Отдельный класс/запись для элемента.

**Частые ошибки:**
- Порядок в `List<TKey>` с `Remove(key)` → O(n); тесты пройдут, **не принимается**. Попроси оценить сложность.
- `_list.Remove(value)` (по значению) вместо `Remove(node)` → O(n) поиск.
- Вытеснение при обновлении существующего ключа → тест `UpdatesValueWithoutEviction` упадёт.
- Вытеснение после добавления (Count на время становится Capacity + 1) — не баг, но обсуди порядок.
- Забыли удалить ключ из словаря при вытеснении → `Count` растёт, утечка памяти.

**Вопросы к студенту при /check:**
1. Какая сложность каждой операции и почему именно LinkedList?
2. Зачем ключ в узле?
3. Как сделать кэш потокобезопасным? (Простейшее — `lock` на все операции; модуль 13.)

## Quiz

1. **Что выведет код?**
   ```csharp
   var list = new List<int>();
   Console.WriteLine(list.Capacity);
   list.Add(1);
   Console.WriteLine(list.Capacity);
   for (int i = 0; i < 4; i++) list.Add(i);
   Console.WriteLine($"{list.Count} {list.Capacity}");
   ```
   **Ответ:** `0`, `4`, `5 8`. **Почему:** пустой List не выделяет массив; первый Add — capacity 4; при переполнении — удвоение.

2. **Найди ошибку:**
   ```csharp
   foreach (var user in users)
       if (!user.IsActive) users.Remove(user);
   ```
   **Ответ:** `InvalidOperationException: Collection was modified`. **Почему:** enumerator проверяет версию коллекции. Исправление: `users.RemoveAll(u => !u.IsActive)`.

3. **Что выведет код?**
   ```csharp
   public class P { public int X; public override bool Equals(object? o) => o is P p && p.X == X; }
   var set = new HashSet<P> { new P { X = 1 } };
   Console.WriteLine(set.Contains(new P { X = 1 }));
   ```
   **Ответ:** почти наверняка `False`. **Почему:** `GetHashCode` не переопределён — хэш по ссылке, разные объекты попадают в разные бакеты, `Equals` даже не вызывается. (Компилятор ещё и выдаст warning CS0659.)

4. **Выбери коллекцию:** нужно хранить 1 млн id заблокированных пользователей и проверять каждый входящий запрос. A) `List<int>` B) `int[]` C) `HashSet<int>` D) `LinkedList<int>`
   **Ответ:** C. **Почему:** `Contains` за O(1); у остальных — O(n) (у отсортированного массива с `BinarySearch` — O(log n), допустимо, если данные не меняются).

5. **Что выведет код?**
   ```csharp
   static IEnumerable<int> Get() { Console.Write("A "); yield return 1; Console.Write("B "); yield return 2; }
   var seq = Get();
   Console.Write("C ");
   foreach (var x in seq) Console.Write($"{x} ");
   ```
   **Ответ:** `C A 1 B 2 `. **Почему:** тело итератора не выполняется до первого `MoveNext`.

6. **Какая сложность?**
   ```csharp
   for (int i = 0; i < list.Count; i++)
       list.Insert(0, i);   // предположим, цикл по копии длины n
   ```
   **Ответ:** O(n²). **Почему:** `Insert(0, …)` сдвигает все элементы — O(n), повторяется n раз.

7. **Что выведет код?**
   ```csharp
   var pq = new PriorityQueue<string, int>();
   pq.Enqueue("low", 5); pq.Enqueue("high", 1); pq.Enqueue("mid", 3);
   Console.WriteLine(pq.Dequeue() + " " + pq.Count);
   ```
   **Ответ:** `high 2`. **Почему:** PriorityQueue — min-heap, первым выходит минимальный приоритет.

8. **Найди проблему:**
   ```csharp
   var key = new List<int> { 1, 2 };
   var dict = new Dictionary<List<int>, string> { [key] = "a" };
   Console.WriteLine(dict.ContainsKey(new List<int> { 1, 2 }));
   ```
   **Ответ:** `False`. **Почему:** `List<T>` не переопределяет `Equals`/`GetHashCode` — сравнение по ссылке. Для составного ключа используй `record`, кортеж или строку.
