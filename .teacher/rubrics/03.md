# Рубрика модуля 03

## Задача 1. TicketPricing
**Обязательно:** валидация возраста до бизнес-правил; правильный приоритет правил; `GetSeason` с `ArgumentOutOfRangeException` для неверного месяца; все тесты зелёные.
**Хорошо бы:** один switch expression по кортежу `(age, day, isStudent)`; `DayOfWeek.Saturday or DayOfWeek.Sunday`; `12 or 1 or 2`; `_ => throw` внутри switch expression; константа `MaxAge`.

**Частые ошибки**
- Длинная цепочка `if/else` с дублированием условий → принять, но предложить переписать на switch expression и спросить, что читается легче.
- Неверный порядок (выходные раньше детского) → ребёнок в субботу платит 600. Тест поймает; спросить «почему порядок важен?».
- `day == DayOfWeek.Saturday || day == DayOfWeek.Sunday` повторяется в нескольких местах → DRY: вынести `isWeekend` или паттерн.
- Магические числа без пояснения — для цен допустимо, для границ возраста лучше константы.
- `default: return "Winter"` вместо исключения для месяца 13 → **почему плохо:** мусор на входе тихо превращается в правдоподобный ответ.

**Вопросы к студенту при /check**
- Почему порядок веток важен? Что сделает компилятор с недостижимой веткой?
- Чем switch expression отличается от switch statement?

## Задача 2. PatternMatcher
**Обязательно:** один switch expression; правильный порядок (частное выше общего); list patterns для массивов; positional или property pattern для `Point`; property pattern для `DateOnly`; `_ => "unknown"`.
**Хорошо бы:** `int and < 0` или `int n when n < 0` с объяснением разницы; `string { Length: 0 }`; комментарий, почему `5L` — unknown.

**Частые ошибки**
- `int[] []` вместо `int[] and []` → компилятор читает это как тип `int[][]`; объяснить грамматику (type pattern + list pattern соединяются через `and`, либо `int[] { Length: 0 }`).
- `arr.Length == 0` через `when` вместо list pattern — работает, но цель задачи — list patterns.
- `if (value is int) ... else if (value is string) ...` с приведениями `(int)value` → двойная проверка типа, шум.
- Ожидание, что `5L` — это int → объяснить: паттерн проверяет тип упакованного значения, преобразований нет (связь с unboxing из модуля 02).
- `value.ToString()` для `null` → NRE; `null` должен обрабатываться первым.

**Вопросы к студенту при /check**
- Какие виды паттернов вы использовали?
- Почему `Point(0, 0)` работает с record? (Deconstruct)

## Задача 3. DurationParser
**Обязательно:** `totalMinutes = 0` на всех путях с `false`; `NumberStyles.None` + InvariantCulture или ручная проверка цифр; проверка минут < 60 только при наличии часов; защита от переполнения (`long` или `checked` + обработка); все тесты зелёные.
**Хорошо бы:** присвоение `out` в начале метода; вспомогательный `TryParseDigits`; range-синтаксис `[..i]`, `[..^1]`.

**Частые ошибки**
- `int.TryParse(part, out h)` без `NumberStyles.None` → `"-1h"` или `" 1h"` проходят; тест падает.
- `Split('h')` → `"1h2h"` даёт три части, `"30m1h"` — путаница; объяснить необходимость проверять порядок.
- `try { ... int.Parse ... } catch { return false; }` → **почему плохо:** Try-метод, который внутри ловит исключения, теряет главное преимущество — дешевизну; голый `catch` прячет баги.
- `hours * 60` в int → переполнение даёт отрицательное число и `true`; тест `"35791395h"` ловит.
- Regex — допустимо, если корректен; спросить, как он обработает переполнение.

**Вопросы к студенту при /check**
- Чем `out` отличается от `ref`?
- Почему при `false` значение должно быть 0?

## Задача 4. MethodBasics
**Обязательно:** `Swap` через `ref` (кортеж или временная переменная); `Sum` с `ArgumentNullException.ThrowIfNull`; `MinMax` за один проход, `ArgumentException` для пустого и `ArgumentNullException` для null; `FormatPrice` с InvariantCulture и валидацией; две перегрузки `Area` с проверкой отрицательных значений.
**Хорошо бы:** `(a, b) = (b, a)`; стартовые значения min/max из первого элемента; `ArgumentException.ThrowIfNullOrEmpty(currency)`.

**Частые ошибки**
- `numbers.Min()` и `numbers.Max()` → два прохода; задача явно просит один — обсудить.
- Старт `min = 0` → неверный результат для массива из положительных чисел (тест `[5]` может пройти, `[3,-1,7,0]` — тоже; спросить про `[5, 6]`).
- `throw new ArgumentException` для null → тест ждёт именно `ArgumentNullException` (`Assert.Throws` проверяет точный тип); объяснить иерархию.
- `amount.ToString("F" + decimals)` без культуры → `"12,50 EUR"` на русской Windows.
- В `Swap` без `ref` → «ничего не работает»; хороший момент для объяснения передачи по значению.

**Вопросы к студенту при /check**
- Что если убрать `ref` в `Swap`?
- Чем overloading отличается от overriding?
- Почему значения по умолчанию optional параметров опасно менять в публичной библиотеке?

## Задача 5. ArrayTasks
**Обязательно:** `RotateClockwise` создаёт `new int[cols, rows]` и не меняет вход; формула индексов верна для прямоугольных матриц; `TryFind` возвращает первое вхождение построчно и `-1/-1`; `PascalTriangle` — jagged с правильной границей 30; `RotateRight` нормализует `k` (включая отрицательный) и не делит на 0 для пустого массива.
**Хорошо бы:** `return` из вложенных циклов в `TryFind`; один проход в `RotateRight` с `(i + shift) % n`.

**Частые ошибки**
- Поворот только для квадратных матриц (`new int[n, n]`) → тест 2×3 падает.
- `matrix.Length` вместо `GetLength(0)` → путаница «всего элементов» и «строк».
- `break` во внутреннем цикле `TryFind` → внешний цикл продолжается, находит вхождение позже; объяснить, что `break` выходит из одного цикла.
- `k % n` без коррекции отрицательного → `IndexOutOfRangeException`.
- `RotateRight` через `k` раз по одному сдвигу → O(n·k), для `k = 1_000_000` медленно.

## Задача 6. Recursion
**Обязательно:** `Factorial` рекурсивный с базовым случаем и `checked`; `Fibonacci` рекурсивный; `FibonacciIterative` — цикл, O(1) памяти, проверка `n ≤ 92`; `SumDigits` рекурсивный и без `Math.Abs(int.MinValue)`; `Hanoi` с локальной функцией и правильным порядком ходов.
**Хорошо бы:** `(previous, current) = (current, previous + current)`; capacity списка `2^n - 1`; объяснение, почему C# не гарантирует tail call optimization.

**Частые ошибки**
- `Factorial` без `checked` → `21!` даёт мусор; тест ждёт `OverflowException`.
- `FibonacciIterative` вызывает рекурсивный `Fibonacci` → тест на 92 «висит». Остановить, объяснить O(2ⁿ).
- `SumDigits` через `Math.Abs(n)` → `OverflowException` на `int.MinValue`; через `n.ToString()` → не рекурсия, плюс знак `-` и культура.
- `Hanoi` с полем класса для списка ходов (`static List<string> _moves`) → **почему плохо:** общее состояние между вызовами, не потокобезопасно, второй вызов получит старые ходы. Локальная функция или параметр.
- Рекурсия без базового случая для `0` в `Hanoi` → лишние ходы или переполнение стека.

**Вопросы к студенту при /check**

- Что такое stack frame и почему StackOverflowException не ловится?

## Задача 7. ⭐ BinarySearch
**Обязательно:** итеративный `IndexOf` с `low + (high - low) / 2` и корректными границами; `LowerBound` на полуинтервале; `CountOccurrences` за O(log n) без `target + 1`; `IntegerSqrt` с `(long)mid * mid`; null-проверки; все тесты зелёные.
**Хорошо бы:** студент формулирует инвариант цикла; общий helper для lower/upper bound (без дублирования); понимает разницу закрытого `[low, high]` и полуоткрытого `[low, high)` интервалов.

**Частые ошибки**
- `(low + high) / 2` → тесты не поймают на маленьких массивах, но **обязательно** указать (баг из JDK); на интервью это частый follow-up.
- `low = mid` при `while (low < high)` с округлением вниз → бесконечный цикл на двух элементах.
- `CountOccurrences` линейным проходом от найденного индекса → O(n) в худшем случае (все элементы равны); тест пройдёт, но задача про O(log n).
- `LowerBound(target + 1)` → при `int.MaxValue` переполнение до `int.MinValue`, тест `CountOccurrences_MaxValue_DoesNotOverflow` падает.
- `IntegerSqrt` через `mid * mid` в int → переполнение для больших `n`, неверный ответ или зацикливание.
- Рекурсивная версия — допустима для `IndexOf`, но попросить объяснить глубину стека (log n — безопасно).

## Quiz

1. **Что выведет код?**
   ```csharp
   void AddItem(List<int> list) { list.Add(1); list = new List<int> { 99 }; }
   var items = new List<int>();
   AddItem(items);
   Console.WriteLine(items.Count);
   ```
   **Ответ:** `1`. **Почему:** передаётся копия ссылки: `Add` меняет общий объект, присваивание нового списка меняет только локальную копию.

2. **Найди ошибку.**
   ```csharp
   bool TryGetDiscount(string code, out decimal discount)
   {
       if (code == "SALE") { discount = 0.1m; return true; }
       return false;
   }
   ```
   **Ответ:** ошибка компиляции CS0177 — `out`-параметр не присвоен на пути `return false`. **Почему:** контракт `out` гарантирует вызывающему, что значение присвоено. Нужно `discount = 0;`.

3. **Что выведет код?**
   ```csharp
   object o = 5L;
   var result = o switch { int => "int", long l when l > 3 => "big long", long => "long", _ => "other" };
   Console.WriteLine(result);
   ```
   **Ответ:** `big long`. **Почему:** упакован `long`, ветка `int` не подходит (нет преобразований при сопоставлении), `when` выполняется.

4. **Выбор варианта.** Что произойдёт при бесконечной рекурсии? A) `OutOfMemoryException`, можно поймать; B) `StackOverflowException`, можно поймать; C) `StackOverflowException`, процесс завершится; D) компилятор не даст скомпилировать.
   **Ответ:** C. **Почему:** стек потока ограничен; после переполнения CLR завершает процесс, обработчику негде выполниться.

5. **Что выведет код?**
   ```csharp
   int x = 5;
   void M(ref int v) => v *= 2;
   M(ref x);
   M(ref x);
   Console.WriteLine(x);
   ```
   **Ответ:** `20`. **Почему:** `ref` передаёт саму переменную, оба вызова меняют `x`.

6. **Найди ошибку.**
   ```csharp
   string Describe(int n) => n switch
   {
       > 0 => "positive",
       > 100 => "big",
       _ => "other",
   };
   ```
   **Ответ:** ошибка компиляции CS8510 — ветка `> 100` недостижима (уже покрыта `> 0`). **Почему:** switch expression выбирает первую подходящую ветку; частные случаи пишут выше общих.

7. **Что выведет код?**
   ```csharp
   int[][] jagged = new int[2][];
   Console.WriteLine(jagged[0] == null);
   int[,] grid = new int[2, 3];
   Console.WriteLine(grid.Length);
   ```
   **Ответ:** `True` и `6`. **Почему:** элементы jagged — ссылки на массивы, по умолчанию `null`; `Length` многомерного массива — общее число элементов.

8. **Выбор варианта.** Какая перегрузка вызовется: `Print(object o)` и `Print(long l)`, вызов `Print(5)`?
   **Ответ:** `Print(long)`. **Почему:** компилятор выбирает «лучшее» преобразование: `int → long` — implicit numeric conversion, лучше, чем `int → object` (boxing). Выбор — на этапе компиляции.
