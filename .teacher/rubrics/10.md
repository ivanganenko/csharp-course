## Задача 1. MyEnumerable

**Обязательно:**
- `Filter`/`Map`: жадная проверка аргументов + ленивый итератор (локальная функция или приватный метод).
- `Reduce`: обычный цикл, пусто → `seed`, проверки аргументов.
- `CountWhere` с `Predicate<T>`.
- Без LINQ.

**Хорошо бы:** `static` локальные функции; комментарий о разнице immediate/deferred.

**Частые ошибки** → реакция и **почему**:
- `ThrowIfNull` внутри метода с `yield` → тесты `ThrowImmediately` падают; спроси, когда выполняется тело итератора (связь с модулем 09).
- `Filter` возвращает `List<T>` (eager) → тест ленивости падает; **почему плохо:** теряется composability и работа с бесконечными последовательностями, лишняя память.
- `Reduce` через `yield` → не компилируется/не по сигнатуре; обсуди, что значение не последовательность.
- Внутри используется `source.Where(...)` → нарушено условие; задача — понять, что LINQ сам по себе такой же код.

2. Почему `Predicate<T>` и `Func<T, bool>` несовместимы?
3. Как компилятор выводит `TResult` в `numbers.Map(Convert.ToString)`?

## Задача 2. Calculator

**Обязательно:**
- `Dictionary<string, Func<double, double, double>>`, заполнение в конструкторе.
- Деление на 0 → `DivideByZeroException` (явно, т.к. double даёт Infinity).
- Неизвестная операция → `NotSupportedException` через `TryGetValue`.
- `Register`: `ThrowIfNullOrWhiteSpace`, `ThrowIfNull`, дубликат → `ArgumentException`.
- `Evaluate`: `Split` с `RemoveEmptyEntries`, ровно 3 части, `double.Parse/TryParse` с `CultureInfo.InvariantCulture`.

**Хорошо бы:** `TryAdd` + своё сообщение; `SupportedOperations => _operations.Keys` без копии; приватный `ParseNumber`.

**Частые ошибки:**
- `double.Parse(s)` без культуры → **почему плохо:** на машине с ru-RU `"1.5"` не распарсится (или распарсится как 15 в некоторых стилях). Тест упадёт у студента с русской Windows — отличный повод объяснить культуру.
- `switch` вместо словаря в `Calculate` → `Register` не работает; задача именно про делегаты.
- `_operations[operation] = function` в `Register` → перезапись встроенной операции; тест упадёт.
- `Split(' ')` без `RemoveEmptyEntries` → тест с лишними пробелами упадёт.

**Вопросы к студенту при /check:**
1. Какой принцип SOLID иллюстрирует этот дизайн?
2. Как добавить унарные операции (`sqrt 9`)? Что придётся поменять?

## Задача 3. StockTicker / PriceAlert

**Обязательно:**
- Хранение цен в `Dictionary<string, decimal>`; событие только при изменении; цена сохраняется **до** события.
- Вызов `PriceChanged?.Invoke(this, e)`; `sender == this`.
- `SubscriberCount` через `GetInvocationList()`.
- Валидация (`ThrowIfNullOrWhiteSpace`, `ThrowIfNegative`).
- `PriceAlert`: подписка в конструкторе method group-ом, отписка в `Dispose`, флаг `_disposed`.

**Хорошо бы:** `protected virtual void OnPriceChanged`; `IReadOnlyList` наружу; `sealed` для `PriceAlert`.

**Частые ошибки:**
- `PriceChanged(this, e)` без `?.` → NRE без подписчиков (тест `NoSubscribers` упадёт).
- Событие до сохранения цены → тест `PriceIsStoredBeforeEventIsRaised` падает; **почему плохо:** подписчик видит несогласованное состояние объекта.
- Подписка лямбдой `ticker.PriceChanged += (s, e) => ...` и отписка такой же лямбдой → отписка не работает; тест `UnsubscribesOnDispose` упадёт. Попроси объяснить равенство делегатов.
- Повторный `Dispose` без флага — в данном случае безвреден (`-=` отсутствующего делегата — no-op), но обсуди идемпотентность как требование к `Dispose`.

**Вопросы к студенту при /check:**
1. Чем `event` защищает тикер? Что можно было бы сделать с публичным полем?
2. Почему без отписки `PriceAlert` не будет собран GC, пока жив тикер?
3. Что произойдёт, если один из подписчиков бросит исключение?

## Задача 4. ClosureLab

**Обязательно:**
- `CreateCounter`: локальная переменная + лямбда, без static.
- `CreateMultipliers`: локальная копия переменной цикла (или `foreach` по `Enumerable.Range`), проверка `count`.
- `CreateLogger`, `Compose`: проверки аргументов, корректный порядок композиции.
- `Memoize`: `Dictionary` создаётся в `Memoize` (не static, не поле класса), `TryGetValue`.

**Частые ошибки:**
- Ловушка `for` → тест `CreateMultipliers` даёт `[40, 40, 40, 40]`. Не подсказывай сразу — попроси вывести значения и объяснить.
- `static int _count` → счётчики не независимы; **почему плохо:** глобальное состояние, тест `CountersAreIndependent` упадёт.
- `Compose` как `first(second(x))` → порядок перепутан, тест упадёт.
- `Memoize` со static-словарём → кэши разных функций смешиваются (тест `SeparateCaches`).

## Задача 5. EventBus

**Обязательно:**
- `Dictionary<Type, List<Delegate>>` (или аналог), каст к `Action<TEvent>` при вызове.
- Snapshot (`ToArray`) перед перебором.
- `Subscribe` возвращает `IDisposable`, удаляющий именно эту подписку; повторный `Dispose` безопасен.
- Проверки аргументов.

**Хорошо бы:** уникальный делегат на подписку (обёртка), чтобы двойная подписка одного handler-а корректно отписывалась по одной.

**Частые ошибки:**
- Перебор `list` без копии → `InvalidOperationException` в тестах с отпиской/подпиской во время Publish.
- `Dictionary<Type, object>` с `as List<Action<TEvent>>` — работает, допустимо; обсуди альтернативы.
- `Subscription.Dispose` удаляет по `handler` из всех типов или все вхождения.
- `Publish` возвращает число подписчиков после рассылки (с учётом новых) → тест падает.

**Вопросы к студенту при /check:**
1. Зачем snapshot? Как поведёт себя multicast-делегат в той же ситуации?
2. Чем EventBus лучше прямых вызовов `emailService.Send(...)` из сервиса заказов? Чем хуже?

## Задача 7. ⭐ PipelineBuilder

**Обязательно:**
- Список middleware + terminal; `Use`/`Run` возвращают `this`, проверяют null.
- `Build`: сборка с конца (`for` от последнего к первому), default terminal 404/"Not Found".
- Сборка в момент `Build` (snapshot) — не лениво при каждом запросе.

**Хорошо бы:** приватный static-метод `NotFound`; комментарии про ASP.NET Core.

**Частые ошибки:**
- Сборка с начала → порядок `B:before, A:before…`, тест падает. Попроси «нарисовать матрёшку».
- `Build` возвращает лямбду, которая собирает конвейер при каждом вызове из текущего списка → middleware, добавленные после `Build`, попадают в конвейер (тест падает) + лишняя работа на каждый запрос.
- Terminal `null` → NRE при `Build` без `Run`.

## Quiz

1. **Что выведет код?**
   ```csharp
   var actions = new List<Action>();
   for (int i = 0; i < 3; i++) actions.Add(() => Console.Write(i));
   foreach (var a in actions) a();
   ```
   **Ответ:** `333`. **Почему:** одна переменная `i` на весь цикл захвачена всеми лямбдами; после цикла `i == 3`.

2. **Что выведет код?**
   ```csharp
   Func<int> f = () => 1;
   f += () => 2;
   f += () => 3;
   Console.WriteLine(f());
   ```
   **Ответ:** `3`. **Почему:** multicast-делегат возвращает результат последнего метода.

3. **Найди ошибку:**
   ```csharp
   public class Button { public Action? Click; }
   // где-то в другом модуле:
   button.Click = OnMyClick;
   ```
   **Ответ:** поле вместо `event`; `=` затирает всех ранее подписанных. **Почему:** публичное поле-делегат не защищено. С `event` такая строка не скомпилируется (CS0070), нужно `+=`.

4. **Что выведет код?**
   ```csharp
   int x = 10;
   Func<int> getX = () => x;
   x = 20;
   Console.WriteLine(getX());
   ```
   **Ответ:** `20`. **Почему:** захватывается переменная, а не значение.

5. **Сработает ли отписка?**
   ```csharp
   source.Changed += (s, e) => Console.WriteLine("hi");
   source.Changed -= (s, e) => Console.WriteLine("hi");
   ```
   **Ответ:** нет. **Почему:** две лямбды — два разных метода; делегаты не равны. Нужно сохранить делегат в переменную или использовать метод.

6. **Что выведет код?**
   ```csharp
   Action a = () => Console.Write("A");
   a += () => throw new Exception();
   a += () => Console.Write("C");
   try { a(); } catch { Console.Write("!"); }
   ```
   **Ответ:** `A!`. **Почему:** методы вызываются по порядку; исключение прерывает цепочку, `C` не выполняется.

7. **Выбери тип:** нужен параметр «функция, принимающая `Order` и возвращающая `decimal`». A) `Action<Order, decimal>` B) `Func<decimal, Order>` C) `Func<Order, decimal>` D) `Predicate<Order>`
   **Ответ:** C. **Почему:** у `Func` результат — последний параметр типа; `Action` ничего не возвращает.

8. **Что выведет код?**
   ```csharp
   static Func<int> Make() { int n = 0; return () => ++n; }
   var a = Make(); var b = Make();
   a(); a();
   Console.WriteLine($"{a()} {b()}");
   ```
   **Ответ:** `3 1`. **Почему:** каждый вызов `Make` создаёт новый display class со своей `n`.
