# Рубрика модуля 02

## Задача 1. InputParser
**Обязательно:** `TryParse` (не `Parse` в `try/catch`); `CultureInfo.InvariantCulture`; `ParseAge` переиспользует `ParseInt`; `ParseAmount` заменяет `,` на `.` и не допускает разделителей тысяч; `ParseYesNo` — `Trim()` + сравнение без учёта регистра; всё возвращает `null`, а не магические `-1`/`0`.
**Хорошо бы:** `value is >= 0 and <= MaxAge ? value : null`; switch expression с `or` в `ParseYesNo`; константа `MaxAge`; явно перечисленные `NumberStyles`.

**Частые ошибки**
- `try { return int.Parse(input); } catch { return null; }` → **почему плохо:** исключения дороги (stack trace), голый `catch` ловит всё, включая баги; Try-паттерн создан ровно для этого случая.
- `decimal.TryParse(input, out var v)` без культуры → на русской Windows "12.5" не распарсится (или распарсится иначе). Тест может пройти на одной машине и упасть на другой — обсудить.
- `NumberStyles.Number` или `NumberStyles.Any` в `ParseAmount` → "1,2.3" после замены → может пройти как число с разделителем тысяч; тест `1,2.3` падает.
- `input.ToLower()` без Invariant → культурная зависимость (турецкая i).
- Возврат `0` вместо `null` → нельзя отличить «ввели 0» от «ввели мусор». Это ровно та причина, по которой существует `int?`.

**Вопросы к студенту при /check**
- Почему `int?`, а не `-1` как признак ошибки?
- Чем `Parse`, `TryParse`, `Convert.ToInt32` отличаются на `null`?

## Задача 2. SafeMath
**Обязательно:** `checked(a + b)`; `TryAdd` без исключений (через `long` или сравнения с границами) и `result = 0` при неудаче; `Midpoint` через `low + (high - low) / 2` + валидация; `checked((int)value)`; аккумулятор `long` в `SumAsLong`.
**Хорошо бы:** expression-bodied члены для однострочников; `ArgumentOutOfRangeException.ThrowIf…`; комментарий, почему не `values.Sum()`.

**Частые ошибки**
- `TryAdd` через `try { checked } catch (OverflowException)` → работает, но **почему плохо:** Try-паттерн как раз нужен, чтобы не платить за исключение; спросить про стоимость.
- `Midpoint` как `(low + high) / 2` → тест с `int.MaxValue - 1` падает. Рассказать историю бага Java `binarySearch`.
- `(int)value` без `checked` в `ToIntChecked` → молча отбрасывает старшие биты.
- `SumAsLong` через `values.Sum()` → `OverflowException` (LINQ `Sum` для `int` — checked) — хорошая находка для обсуждения; `values.Sum(x => (long)x)` — допустимо.
- `long sum = a + b;` → переполнение происходит ДО расширения (сложение в int). Частая ошибка понимания!

**Вопросы к студенту при /check**
- Почему `long sum = a + b;` не спасает от переполнения?
- Почему C# по умолчанию unchecked?

## Задача 3. MoneyCalculator
**Обязательно:** только `decimal`; `MidpointRounding.AwayFromZero`; `Split` через целые копейки с раздачей остатка первым частям; проверка «долей копейки»; `CompoundInterest` округляет один раз; валидация всех аргументов.
**Хорошо бы:** приватный `RoundToCents`; константы; цикл, а не `Math.Pow` (который работает с `double`!).

**Частые ошибки**
- `Math.Pow((double)(1 + rate / 100), years)` → **почему плохо:** уходим в double и теряем точность; для `decimal` нет `Pow`, нужен цикл.
- `Split`: `Math.Round(total / parts, 2)` для всех частей → `33.33 * 3 = 99.99`, копейка потеряна. Спросить: «кто заплатит недостающую копейку?»
- Округление на каждом шаге в `CompoundInterest` → для 1000/5%/3 года результат тот же, но в общем случае накапливается ошибка; обсудить.
- Деление процентов первым (`discountPercent / 100 * price`) — для decimal ок, но привычка опасна для int.

**Вопросы к студенту при /check**
- Почему нельзя `Math.Round(total / parts, 2)`?
- Что такое банковское округление и почему оно по умолчанию?

## Задача 4. StringTools
**Обязательно:** `IsPalindrome` с `char.IsLetterOrDigit` и `char.ToLowerInvariant`; `CountWords`/`NormalizeSpaces` через `Split((char[]?)null, RemoveEmptyEntries)` или эквивалент; `SameLogin` с `StringComparison.OrdinalIgnoreCase` и корректной обработкой null; `MaskCardNumber` через `char[]`/`StringBuilder`, исходная строка не меняется.
**Хорошо бы:** `IsPalindrome` двумя указателями без аллокаций; `string.Join(' ', words)`; `char.IsAsciiDigit` для номера карты.

**Частые ошибки**
- `new string(text.Where(char.IsLetterOrDigit).Reverse().ToArray())` → работает, но 2–3 аллокации и O(n) памяти; принять, обсудить вариант с двумя индексами.
- `text.Split(' ')` → не учитывает `\t`, `\n` и двойные пробелы; тесты падают.
- `a.ToLower() == b.ToLower()` в `SameLogin` → лишние строки + культура; NRE при `null`.
- `cardNumber.Replace(digit, '*')` → заменит ВСЕ вхождения цифры, включая последние 4 (например, `"1111 2222 3333 4441"`).
- Попытка `cardNumber[i] = '*'` → ошибка компиляции CS0200 — отличный момент объяснить immutability.

**Вопросы к студенту при /check**
- Сколько строк создаёт ваш `IsPalindrome`?
- Почему Ordinal, а не CurrentCulture для логинов?

## Задача 5. ReceiptBuilder
**Обязательно:** `StringBuilder`; `'\n'` вместо `AppendLine`; `ToString("0.00", CultureInfo.InvariantCulture)` и `date.ToString("yyyy-MM-dd", CultureInfo.InvariantCulture)`; валидация с `ArgumentException`/`ArgumentNullException`; сумма в `decimal`.
**Хорошо бы:** чейнинг `Append`; константа формата; понятные сообщения исключений с `nameof`.

**Частые ошибки**
- `AppendLine` → на Windows `"\r\n"`, тест падает. **Почему плохо:** вывод зависит от ОС — сломаются сравнения, хэши, подписи файлов.
- Интерполяция `$"{lineTotal:0.00}"` без культуры → `"5,00"` на ru-RU. Показать `sb.Append(CultureInfo.InvariantCulture, $"...")` как идиоматичную альтернативу (.NET 6+).
- `string receipt = ""; receipt += ...` в цикле → O(n²); тест на 1000 строк пройдёт, но это главный пункт задачи.
- Сумма через `double` → тест на 1000 × 0.1 может не сойтись.

**Вопросы к студенту при /check**
- Почему `'\n'`, а не `AppendLine`?
- Сколько аллокаций при `+=` для 1000 строк?

## Задача 6. Исследование boxing (🧪)
**Обязательно:** предсказания записаны ДО запуска; правильно объяснены: `5 6`, `100`, `42`, `InvalidCastException`, `abc`; замер показал многократную разницу ArrayList vs List<int> (ArrayList: объект-обёртка ~24 байта на каждое число + ссылка 8 байт в массиве; List<int>: 4 байта на число); найдены `box`/`unbox.any`.
**Хорошо бы:** заметил, что `$"{n}"` в современном C# boxing не вызывает (DefaultInterpolatedStringHandler с generic `AppendFormatted<T>`), а `string.Format("{0}", n)` — вызывает.

**Частые ошибки**
- «`o` изменилось, потому что object — reference type» → разобрать: при boxing создаётся КОПИЯ.
- «`s1` должна измениться, string же reference type» → immutability: `+=` создаёт новую строку и меняет ссылку в `s2`.
- Замер в Debug или с `Console.WriteLine` внутри цикла → шум; попросить Release.

**Вопросы к студенту при /check**
- Сколько объектов в heap создаёт `arrayList.Add(5)`?
- Почему `(long)boxed` падает, а `(long)(int)boxed` работает?

## Задача 7. ⭐ Run-Length Encoding
**Обязательно:** `StringBuilder`; обработка последней серии; проверка цифр во входе `Encode`; `Decode` с многозначными числами и всеми ошибками формата; null-проверки; все тесты зелёные.
**Хорошо бы:** `sb.Append(symbol, count)`; `checked` при накоплении счётчика; один проход в обе стороны — O(n).

**Частые ошибки**
- Забыта последняя серия → `"aaab"` кодируется в `"a3"`. Тесты поймают; спросить, как защищаться от таких ошибок (тесты на границы).
- `Decode` читает только одну цифру → `"x12"` превращается в `"x"` + ошибка.
- `int.Parse(encoded[i].ToString())` для каждой цифры → лишняя строка на символ; показать `c - '0'`.
- Использование `Regex` — допустимо, но спросить про сложность и читаемость; на интервью обычно ожидают ручной разбор.
- `+=` строк в `Decode` для `"x99999"` → медленно.

- Что такое `char` и почему `'7' - '0' == 7`?
- Как изменить формат, чтобы цифры во входе стали допустимы? (экранирование или фиксированная ширина счётчика)

## Quiz

1. **Что выведет код?**
   ```csharp
   int[] a = { 1, 2, 3 };
   int[] b = a;
   b[0] = 10;
   int x = 1;
   int y = x;
   y = 10;
   Console.WriteLine($"{a[0]} {x}");
   ```
   **Ответ:** `10 1`. **Почему:** массив — reference type, `b` указывает на тот же объект; `int` — value type, `y` — независимая копия.

2. **Что выведет код?**
   ```csharp
   object o = 42;
   long l = (long)o;
   Console.WriteLine(l);
   ```
   **Ответ:** `InvalidCastException`. **Почему:** unboxing возможен только в точно исходный тип (`int`); правильно `(long)(int)o`.

3. **Выбор варианта.** Какой тип выбрать для суммы заказа в интернет-магазине? A) float; B) double; C) decimal; D) int.
   **Ответ:** C (допустимо также `long` в копейках). **Почему:** double/float — двоичная дробь, 0.1 не представима точно, копейки «плывут».

4. **Что выведет код?**
   ```csharp
   Console.WriteLine(Math.Round(2.5));
   Console.WriteLine((int)2.9);
   Console.WriteLine(Convert.ToInt32(2.5));
   Console.WriteLine(7 / 2);
   ```
   **Ответ:** `2`, `2`, `2`, `3`. **Почему:** `Math.Round` и `Convert.ToInt32` используют банковское округление (к чётному); cast отбрасывает дробную часть; деление int — целочисленное.

5. **Найди ошибку.**
   ```csharp
   string name = "  Anna  ";
   name.Trim();
   if (name == "Anna") Console.WriteLine("OK");
   ```
   **Ответ:** «OK» не выведется. **Почему:** строки immutable, `Trim()` возвращает новую строку, результат выброшен. Нужно `name = name.Trim();`.

6. **Что выведет код?**
   ```csharp
   int max = int.MaxValue;
   long sum = max + 1;
   Console.WriteLine(sum);
   ```
   **Ответ:** `-2147483648`. **Почему:** сложение выполняется в `int` (оба операнда int), переполнение происходит ДО присваивания в `long`. Правильно `(long)max + 1`.

7. **Выбор варианта.** Как сравнить два логина без учёта регистра? A) `a.ToLower() == b.ToLower()`; B) `string.Equals(a, b, StringComparison.OrdinalIgnoreCase)`; C) `a.Equals(b)`; D) `a.CompareTo(b) == 0`.
   **Ответ:** B. **Почему:** без лишних аллокаций, не зависит от культуры, корректно обрабатывает null (статический `string.Equals`). C учитывает регистр, D — культурное сравнение с учётом регистра, A — аллокации и культура.

8. **Что выведет код?**
   ```csharp
   int? a = null;
   int b = a ?? -1;
   Console.WriteLine(b);
   Console.WriteLine(a.HasValue);
   Console.WriteLine(a.Value);
   ```
   **Ответ:** `-1`, `False`, затем `InvalidOperationException`. **Почему:** `??` подставляет значение по умолчанию; обращение к `.Value` у пустого `Nullable<T>` бросает исключение.
