# Рубрика модуля 04

## Задача 1. BankAccount

**Обязательно:**
- Все тесты `BankAccountTests` зелёные.
- `Balance` — `{ get; private set; }` (или private-поле + get-only свойство); `Owner` — get-only.
- Внутренняя история — `private readonly List<Transaction>`; наружу — `AsReadOnly()` или копия.
- Валидация **до** изменения состояния во всех методах.
- `TransferTo` переиспользует `Withdraw`/`Deposit` (а не дублирует логику) и при нехватке денег не меняет ни один счёт.

**Хорошо бы:**
- Guard clauses через `ArgumentException.ThrowIfNullOrWhiteSpace`, `ArgumentOutOfRangeException.ThrowIfNegativeOrZero`.
- Проверка суммы вынесена в один private-метод.
- `ReferenceEquals(target, this)` для проверки «перевод самому себе».
- Осмысленные тексты исключений.

**Частые ошибки** → как реагировать и **почему** это плохо:
- `public decimal Balance { get; set; }` → спроси: «что мешает вызывающему коду написать `Balance = -100`?». Инвариант держится только на дисциплине всех, кто использует класс.
- `public IReadOnlyList<Transaction> History => _history;` → покажи `((List<Transaction>)account.History).Clear()`. Интерфейс — не защита, это «вид» для компилятора.
- `Balance -= amount;` до проверки → после исключения объект в неконсистентном состоянии.
- В `TransferTo` сначала `target.Deposit`, потом `Withdraw` → при нехватке средств деньги «напечатаны» на втором счёте.
- `double` вместо `decimal` в параметрах (не пройдёт сигнатуру, но если студент спросит) → потеря точности (модуль 02).
- Бросает `Exception` вместо конкретного типа → вызывающий код не может различить ошибки (подробно в модуле 07).

**Вопросы к студенту при /check:**
1. Почему `Balance` с `private set`, а не публичное поле? Что такое инвариант для этого класса?
2. Почему `AsReadOnly()`, а не просто вернуть `_history` как `IReadOnlyList`?
3. Что будет при переводе, если поменять местами `Withdraw` и `Deposit`?

## Задача 2. Temperature

**Обязательно:**
- Одно backing field `_celsius`; валидация только в setter'е `Celsius`; конструктор и `Fahrenheit.set` присваивают через свойство.
- Проверка `double.IsNaN`.
- `Kelvin` — вычисляемое, без set.
- `ToString` с `CultureInfo.InvariantCulture`.

**Хорошо бы:**
- Фабрики через `new(...)` (target-typed) или вызов конструктора — без дублирования валидации.
- `ArgumentOutOfRangeException` с `actualValue` (перегрузка с тремя параметрами).

**Частые ошибки:**
- Три поля (`_c`, `_f`, `_k`) → их легко рассинхронизировать; «single source of truth».
- Валидация продублирована в конструкторе, setter'е и фабриках → при изменении правила забудут одно место.
- Забыт `NaN` → `NaN < x == false`, проверка пропускает мусор; дальше все вычисления дают `NaN`.
- `Celsius.ToString("0.0")` без культуры → на русской Windows `"21,5 °C"`, тест упадёт только на машине студента — отличный повод поговорить о культуре.
- Сравнение double через `==` в своём коде → объясни погрешность (модуль 02).

**Вопросы к студенту при /check:**
1. Почему храним только °C?
2. Зачем фабричные методы, если есть конструктор?
3. Почему тесты сравнивают double с точностью (`Assert.Equal(a, b, 6)`)?

## Задача 3. Book

**Обязательно:**
- `private readonly` поля + `init`-аксессоры с валидацией; `required` у `Title`/`Author` сохранён.
- Trim у `Title`/`Author`, нормализация и проверка ISBN, проверка диапазона `Year` только если значение не `null`.
- `Description` — вычисляемое.

**Хорошо бы:**
- Общий private-хелпер для проверки текста (`RequireText`).
- `char.IsAsciiDigit` вместо `char.IsDigit` (последний пропускает «не-латинские» цифры) — бонусное обсуждение.

**Частые ошибки:**
- Убрал `required` или поменял `init` на `set` → тесты пройдут, но смысл задачи потерян: объект становится изменяемым / можно создать без названия. Спроси, зачем это было.
- `{ get; init; }` + валидация в конструкторе → при object initializer конструктор выполняется ДО присваивания свойств — валидировать нечего. Хороший момент объяснить порядок: конструктор → initializer.
- Хранит ISBN «как есть» и нормализует в getter'е → лишняя работа при каждом чтении, и в getter'е бросать исключения — плохая практика.

**Вопросы к студенту при /check:**
1. В каком порядке выполняются конструктор и object initializer?
2. Чем `required` лучше runtime-проверки?
3. Почему getter свойства не должен бросать исключения и делать тяжёлую работу?

## Задача 4. SupportTicket

**Обязательно:**
- `private static int` счётчик; `Id` присваивается в конструкторе **после** валидации.

- `Number` — `Prefix + Id:D4`.

**Хорошо бы:**

## Задача 5. StringExtensions

**Обязательно:**
- Все методы — `public static` с `this` у первого параметра.
- `ArgumentNullException.ThrowIfNull(value)` в `Truncate` и `Mask`.
- `WordCount` корректно обрабатывает несколько пробелов подряд, табы, переводы строк.

**Хорошо бы:**
- `Split((char[]?)null, StringSplitOptions.RemoveEmptyEntries)` или ручной подсчёт без аллокаций (бонус).
- Range-операторы `value[..n]`, `value[^n..]`; `new string(c, count)`.

**Частые ошибки:**
- `Split(' ')` → не учитывает `\t`/`\n` и пустые элементы (тест `"a\tb\nc"`).
- Маска собирается в цикле через `+=` строки → O(n²) аллокаций; есть `new string('*', n)`.
- Нет null-проверки → `NullReferenceException` вместо понятного `ArgumentNullException`.

**Вопросы к студенту при /check:**
1. Во что компилятор превращает `"abc".Truncate(2)`?
2. Почему extension method можно вызвать на null?
3. Когда extension method — плохая идея?

## Задача 7. Money ⭐

**Обязательно:**
- Immutable: только get-свойства, операции возвращают `new Money(...)`.
- Валидация валюты (3 латинские буквы после ToUpperInvariant), округление `MidpointRounding.AwayFromZero`.
- Проверка совпадения валют в одном private-методе.
- `Allocate` через целые центы с распределением остатка.
- `ToString` с InvariantCulture.

**Хорошо бы:**
- `sealed`.
- `ToUpperInvariant` (а не `ToUpper` — турецкая «i»!).
- Понимание, что сейчас равенство ссылочное, и что будет в модуле 06.

**Частые ошибки:**
- `double` где-либо в расчётах → потеря точности.
- `Math.Round(x, 2)` без MidpointRounding → банковское округление (тест `2.345 → 2.35` ловит).
- `Allocate` как `Amount / parts` для всех частей → 99.99 вместо 100.
- Методы меняют `this` (`Amount += other.Amount`) → нарушение value object; спроси: «что увидит другой код, который держит ссылку на тот же объект?».
- Сравнение валют через `ToLower()` в каждом методе вместо нормализации в конструкторе.

**Вопросы к студенту при /check:**
1. Почему `decimal`, а не `double`? Почему `AwayFromZero`?
2. Что вернёт `new Money(1, "USD") == new Money(1, "USD")`? Почему?
3. Почему неизменяемый объект безопасно использовать из нескольких потоков?

## Quiz

1. **Что выведет код?**
   ```csharp
   var a = new Counter(); var b = new Counter();
   a.Inc(); b.Inc(); b.Inc();
   Console.WriteLine($"{a.Mine} {b.Mine} {Counter.Total}");
   class Counter { public static int Total; public int Mine; public void Inc() { Mine++; Total++; } }
   ```
   **Ответ:** `1 2 3`. **Почему:** `Mine` — у каждого экземпляра своё, `Total` — одно на тип.

2. **Найди ошибку:**
   ```csharp
   public static class MathUtils { public int Square(int x) => x * x; }
   ```
   **Ответ:** не скомпилируется (CS0708): в static-классе нельзя объявлять instance-члены. **Почему:** экземпляр static-класса создать нельзя — вызывать instance-метод было бы не на чем.

3. **Что выведет код?**
   ```csharp
   var p = new P { Name = "A" };
   Console.WriteLine(p.Name);
   class P { public P() { Name = "ctor"; } public string Name { get; set; } }
   ```
   **Ответ:** `A`. **Почему:** object initializer выполняется **после** конструктора и перезаписывает значение.

4. **Выбери вариант.** Какой модификатор даёт доступ наследникам **только внутри своей сборки**? A) `protected` B) `protected internal` C) `private protected` D) `internal`.
   **Ответ:** C. **Почему:** `private protected` = наследник И та же сборка; `protected internal` = наследник ИЛИ та же сборка.

5. **Найди ошибку:**
   ```csharp
   public class Order { public const DateTime Created = DateTime.Now; }
   ```
   **Ответ:** не скомпилируется: `const` только для compile-time констант (примитивы, string, enum). **Почему:** значение `const` вшивается в IL при компиляции; `DateTime.Now` известен только в runtime. Нужен `static readonly` (или свойство экземпляра).

6. **Что выведет код?**
   ```csharp
   string? s = null;
   Console.WriteLine(s.IsEmpty());
   static class E { public static bool IsEmpty(this string? x) => x is null || x.Length == 0; }
   ```
   **Ответ:** `True`. **Почему:** вызов extension method компилируется в `E.IsEmpty(s)` — это статический вызов, null передаётся как обычный аргумент.

7. **Найди ошибку:**
   ```csharp
   public class Cart
   {
       private readonly List<string> _items = new();
       public void Reset() => _items = new List<string>();
   }
   ```
   **Ответ:** CS0191 — readonly-поле можно присвоить только в конструкторе/инициализаторе. **Почему:** `readonly` защищает ссылку. Решение — `_items.Clear()`: менять **содержимое** можно.

8. **Что выведет код?**
   ```csharp
   var u = new User { Login = "anna" };
   u.Login = "boris";
   class User { public required string Login { get; init; } }
   ```
   **Ответ:** не скомпилируется (CS8852): `init`-свойство нельзя присвоить после инициализации. **Почему:** `init` разрешает присваивание только в конструкторе и object initializer — это и делает объект неизменяемым.
