## Задача 1. PriceCalculatorTests + баг

**Обязательно:** тест на границу ровно 1000 (ловит `>` вместо `>=`), баг исправлен; `TheoryData`/`MemberData` для decimal; тесты на `null`, пустой список (образец), `Quantity <= 0`, отрицательную цену; несколько строк.

**Частые ошибки:**
- Ожидаемое значение вычисляется в тесте той же формулой (`expected = sum * 0.9m`) → тест повторяет код и его баги. Объяснить: ожидаемые значения — константы, посчитанные «руками».

- Исправили баг, но не написали тест, который его ловит → регрессия вернётся незамеченной.
- `Assert.Throws<Exception>` вместо конкретного типа.

## Quiz

1. **Что не так с тестом?**
   ```csharp
   [Fact]
   public void Total_IsCorrect()
   {
       var lines = new[] { new OrderLine("A", 3, 400m) };
       var expected = 3 * 400m * 0.9m;
       Assert.Equal(PriceCalculator.CalculateTotal(lines), expected);
   }
   ```
   **Ответ:** ожидаемое считается формулой из кода (тест повторяет логику), и expected/actual перепутаны местами. **Почему:** если формула неверна, тест подтвердит ошибку; сообщение при падении будет вводить в заблуждение. Писать `Assert.Equal(1080m, actual)`.

2. **Скомпилируется ли?**
   ```csharp
   [Theory]
   [InlineData(1000.0m, 900.0m)]
   public void Discount(decimal input, decimal expected) { }
   ```
   **Ответ:** нет. **Почему:** `decimal` не может быть аргументом атрибута. Используй `TheoryData<decimal, decimal>` + `[MemberData]`.

3. **Выбор варианта.** Тест проверяет `SendAsync` был вызван с темой "Order confirmed". Какой это дублёр?
   A) stub  B) mock  C) dummy  D) fake
   **Ответ:** B. **Почему:** проверяется взаимодействие (исходящий вызов), а не возвращаемые данные.

4. **Почему тест «мигает»?**
   ```csharp
   [Fact]
   public void IsWorkingHours_AtNoon_ReturnsTrue() => Assert.True(new Schedule().IsWorkingHours());
   // внутри: DateTime.Now.Hour is >= 9 and < 18
   ```
   **Ответ:** зависит от реального времени — днём зелёный, вечером красный. **Почему:** нарушен принцип Repeatable; нужен `IClock`/`TimeProvider`.

5. **Что выведет xUnit?**
   ```csharp
   public class CounterTests
   {
       private int _count;
       [Fact] public void A() { _count++; Assert.Equal(1, _count); }
       [Fact] public void B() { _count++; Assert.Equal(1, _count); }
   }
   ```
   **Ответ:** оба теста зелёные. **Почему:** xUnit создаёт новый экземпляр класса на каждый тест, поле `_count` каждый раз 0. (Со `static` поле было бы общим — один из тестов упал бы.)

6. **Найди ошибку (NSubstitute):**
   ```csharp
   sender.Received(1).SendAsync("a@example.com", Arg.Any<string>(), "body", CancellationToken.None);
   ```
   **Ответ:** смешаны литералы и `Arg.Any` (+ нет `await`, хотя это не ошибка). **Почему:** NSubstitute сопоставляет матчеры по позициям; при смешивании одного типа может бросить `AmbiguousArgumentsException`. Правильно — `Arg.Is(...)` для всех.

7. **Выбор варианта.** Что из этого стоит мокать в unit-тесте `OrderService`?
   A) `PriceCalculator` (статическая чистая логика)  B) `IPaymentGateway`  C) `OrderLine`  D) `decimal`
   **Ответ:** B. **Почему:** это внешняя граница (банк). Чистую логику и value objects используют настоящими.

8. **Что не так?**
   ```csharp
   [Fact]
   public async void PlaceOrder_Works() { await _sut.PlaceOrderAsync(...); Assert.True(...); }
   ```
   **Ответ:** `async void`. **Почему:** xUnit не может нормально дождаться и отследить исключения такого теста (xUnit 2 поддерживает async void через свой контекст, но это анти-паттерн и анализатор ругается). Нужно `async Task`.
