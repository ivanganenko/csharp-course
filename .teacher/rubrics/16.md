# Рубрика модуля 16

> Главный критерий для всех задач: работа выполняется В БАЗЕ (IQueryable до материализации), одним-двумя запросами, без загрузки лишнего. Проси студента показать SQL из лога — это лучший способ ревью EF-кода.

## Задача 1. Конфигурация модели

**Обязательно:** `HasMaxLength` + `IsRequired` для всех строк из спецификации; `HasIndex(...).IsUnique()` для Isbn, Genre.Name, Email; `ToTable(t => t.HasCheckConstraint(...))`; `OnDelete(DeleteBehavior.Restrict)` для трёх связей с правильными `HasOne/WithMany/HasForeignKey`.
**Хорошо бы:** группировка через `modelBuilder.Entity<T>(e => { ... })`; комментарии «почему Restrict»; упоминание `IEntityTypeConfiguration<T>` для больших моделей; индекс под частый запрос (MemberId, ReturnedOn).

**Частые ошибки**
- Атрибуты `[MaxLength]` на сущностях вместо Fluent API — тесты пройдут; обсуди компромисс (схема в одном месте vs рядом с полем), не считать ошибкой.
- Бросают `NotImplementedException`/забывают `base.OnModelCreating` — первое ломает все тесты, второе безвредно, но привычка полезная.
- `WithMany()` без навигации, когда она есть → EF создаст вторую связь (теневой FK `BookId1`). Объясни: одна связь = одна пара навигаций.
- Check constraint в старом стиле `HasCheckConstraint` на EntityTypeBuilder → obsolete warning; покажи `ToTable(t => ...)`.

## Задача 2. Include / ThenInclude

**Обязательно:** `Include(b => b.Author)` + `Include(b => b.Genres.OrderBy(...))` (или сортировка после загрузки); `FirstOrDefaultAsync` с условием; для выдач — `Where` (активные, memberId) + `Include(Book).ThenInclude(Author)` + `OrderBy(DueOn)`; передаётся `cancellationToken`.
**Хорошо бы:** filtered include для сортировки; `ThenBy(Id)` как тай-брейкер; понимание relationship fixup.

**Частые ошибки**
- `FindAsync` + отдельные запросы для навигаций → N+1 в миниатюре, хотя и работает.
- Фильтрация `ReturnedOn == null` в памяти после `ToListAsync` → загрузка всей истории.
- Включили lazy loading «чтобы работало» → объясни, почему это прячет N+1.
- `Include` после `Select` проекции → Include игнорируется (EF предупредит) — проекция уже определяет форму данных.

## Задача 3. Агрегаты

**Обязательно:** один запрос на метод; Count в SQL (подзапросы или GroupBy); фильтр `LoanCount > 0` и сортировка до `Take`; проекция в record — после `ToListAsync` (или так, чтобы EF смог перевести); `top < 1` → `ArgumentOutOfRangeException`; `DueOn < today` строго.
**Хорошо бы:** может написать эквивалентный SQL; сравнивает подход «подзапросы» и «GroupBy».

**Частые ошибки**
- `ToListAsync()` всех выдач + LINQ to Objects → работает на тестах, неприемлемо на реальных объёмах. Спроси: «сколько строк уйдёт по сети при 10 млн выдач?».
- `OrderBy` по свойству record после `Select(a => new AuthorStats(...))` → исключение «could not be translated». Объясни, почему EF не видит связь параметра конструктора и свойства.
- `<=` вместо `<` для просрочки → тест на границу упадёт; обсуди, как формулировать бизнес-правила.
- `DateTime.Today` внутри метода → нетестируемо, зависит от часового пояса сервера.

## Задача 4. Выдача в транзакции

**Обязательно:** проверки в указанном порядке; каждая — запросом в БД (`AnyAsync`/`CountAsync`), без загрузки коллекций; `BeginTransactionAsync` + `await using` + `CommitAsync` после `SaveChangesAsync`; `DueOn = today.AddDays(14)`; при исключении ничего не сохранено; Return — tracking-запрос, проверка «уже возвращена».
**Хорошо бы:** понимание ограничений Read Committed (честная оговорка в комментарии); осмысленные сообщения исключений; константы вместо 14/3.

**Частые ошибки**
- `_db.Loans.Add(loan)` ДО проверок → при исключении объект остаётся в change tracker того же контекста и сохранится при следующем `SaveChanges`! Объясни, почему порядок важен.
- Загрузка `member.Loans` целиком через Include ради подсчёта → лишние данные; `CountAsync` дешевле.
- Нет `CommitAsync` → транзакция откатится при Dispose, тест «создаёт выдачу» упадёт; разбери, почему.
- `try/catch` с `RollbackAsync` вручную — допустимо, но `await using` делает это сам.
- Глотают исключения и возвращают `null` вместо Loan → вызывающий код не узнает причину.

## Задача 5. Tracking vs AsNoTracking

**Обязательно:** `AsNoTracking()` + `OrderBy(Title)` в каталоге; Rename: Trim, `ArgumentException` для пустого/длинного, tracking-запрос, `SaveChangesAsync`, `false` если нет книги.
**Хорошо бы:** `ArgumentException.ThrowIfNullOrWhiteSpace`; валидация до запроса к БД; знает про `ExecuteUpdateAsync`.

**Частые ошибки**
- Rename через `AsNoTracking` + `SaveChanges` → изменения не сохраняются (тест ловит). Самая ценная ошибка модуля — разбери change tracker подробно.
- `_db.Books.Update(book)` после tracking-запроса — лишнее: помечает ВСЕ колонки Modified → UPDATE всех полей.
- Каталог без `AsNoTracking` → тест на пустой change tracker упадёт; объясни стоимость tracking.

## Задача 6 🧪. N+1

**Обязательно:** студент показал лог SQL наивной версии и посчитал команды (1 + N); оптимизированная версия — 1 (или 2 при split query) запрос; авторы без книг присутствуют; сортировка названий ординальная.
**Хорошо бы:** проекция только нужных колонок вместо `Include`; понимает cartesian explosion и `AsSplitQuery`.

**Частые ошибки**
- Загрузить все книги отдельным запросом и сгруппировать в памяти — 2 запроса, тест пройдёт; это валидный вариант (batch), обсуди плюсы/минусы относительно JOIN.
- `INNER JOIN`-подобная логика (`SelectMany`) → теряются авторы без книг.
- Сортировка `OrderBy(t => t)` в SQL → collation БД может отличаться от ординального сравнения; в SQLite совпадёт, в SQL Server — нет.

## Задача 7 ⭐. Поиск на IQueryable

**Обязательно:** валидация пагинации (`ArgumentOutOfRangeException`, null → `ArgumentNullException`); `IQueryable<Book>` с условными `Where`; `CountAsync` до пагинации; `OrderBy(Title).ThenBy(Id)` → `Skip/Take` → `Select` в `BookListItem`; `AvailableCopies` считается в SQL; AsNoTracking или проекция.
**Хорошо бы:** term приводится к нижнему регистру один раз в C#; комментарий про ограничение `lower()` в SQLite; проверка, что SQL содержит WHERE и LIMIT.

**Частые ошибки**
- `IEnumerable<Book> query = _db.Books` → всё фильтруется в памяти; тесты проходят! Это главный пункт ревью — попроси показать SQL.
- `ToListAsync()` → `Count` по списку → загрузка всех строк ради числа.
- `Skip(page * size)` — off-by-one.
- `string.Contains(term, StringComparison.OrdinalIgnoreCase)` в запросе → EF не переведёт (исключение) — объясни, почему перегрузки с `StringComparison` не транслируются.
- Нет `ThenBy(Id)` → недетерминированный порядок одинаковых названий.

## Quiz

1. **Что выведет код?** (в базе 3 книги, Title были "A", "B", "C")
   ```csharp
   var books = await db.Books.AsNoTracking().ToListAsync();
   books[0].Title = "Changed";
   var saved = await db.SaveChangesAsync();
   Console.WriteLine(saved);
   ```
   → `0`. Почему: AsNoTracking-сущности не отслеживаются, change tracker пуст — сохранять нечего.

2. **Найди проблему:**
   ```csharp
   var orders = await db.Orders.ToListAsync();
   foreach (var o in orders)
       o.Customer = await db.Customers.FindAsync(o.CustomerId);
   ```
   → N+1: запрос за каждым заказом. Решение: `Include(o => o.Customer)` или проекция.

3. **Сколько строк загрузится в память?**
   ```csharp
   IEnumerable<Book> q = db.Books;
   var five = q.Where(b => b.Year > 2000).Take(5).ToList();
   ```
   → вся таблица Books. Почему: `Where` вызван на `IEnumerable` → LINQ to Objects; SQL — `SELECT * FROM Books`.

4. **Выбор:** какой lifetime у `DbContext` в ASP.NET Core по умолчанию (`AddDbContext`)? A) Singleton B) Scoped C) Transient → **B**. Почему: unit of work на запрос, не потокобезопасен.

5. **Что будет?** Две книги с одинаковым ISBN при уникальном индексе: `db.AddRange(b1, b2); await db.SaveChangesAsync();` → `DbUpdateException`, ни одна не сохранена. Почему: SaveChanges выполняется в транзакции — всё или ничего.

6. **SQL:** чем отличается результат `SELECT a.Name, COUNT(*) FROM Authors a LEFT JOIN Books b ON b.AuthorId = a.Id GROUP BY a.Name` от того же с `COUNT(b.Id)` для автора без книг? → `COUNT(*)` даст 1 (строка с NULL-ами), `COUNT(b.Id)` — 0. Почему: COUNT(столбец) не считает NULL.

7. **Найди ошибку:**
   ```csharp
   var page = await db.Books.Skip(20).Take(10).ToListAsync();
   ```
   → нет `OrderBy`: порядок строк в SQL не гарантирован, страницы могут пересекаться/терять элементы. EF Core ещё и выдаст предупреждение.

8. **Выбор:** что из этого НЕ переведётся в SQL?
   A) `b.Title.Contains("x")` B) `b.Title.ToLower() == "x"` C) `MyHelper.IsClassic(b)` D) `b.Year >= 2000` → **C**. Почему: EF не знает, что внутри произвольного C#-метода — expression tree содержит только вызов; будет исключение «could not be translated».
