# Рубрика модуля 01

## Задача 1. Консольное приложение с нуля (🧪)
**Обязательно:** проект создан через CLI; программа спрашивает имя и год, обрабатывает пустое имя и не-число (`TryParse`, сообщение в `Console.Error`, код возврата 1); печатает `args`; есть вторая версия с `static int Main(string[] args)`; найден и запущен `Hello.dll` из Release.
**Хорошо бы:** `string.IsNullOrWhiteSpace`, `Trim()`; отдельный метод для вычисления возраста (`CalculateAge(int birthYear, int currentYear)` — тестируемо, текущий год передаётся параметром).

**Частые ошибки**
- `int.Parse(Console.ReadLine())` → падение на «abc» и nullable warning CS8604. Реагировать: попросить ввести «abc» и прочитать stack trace. **Почему плохо:** пользовательский ввод всегда может быть некорректным; исключение для ожидаемой ситуации — неверный инструмент.
- Игнорирование warning `CS8600/CS8604` про `string?` → объяснить, что компилятор предупреждает о реальном `null` при конце ввода.
- `DateTime.Now.Year` внутри логики расчёта → отметить (не критично здесь), что такой код трудно тестировать: «текущее время» лучше передавать параметром (вернёмся в модуле 14).

**Вопросы к студенту при /check**

- Во что компилятор превратил ваши top-level statements?

## Задача 2. FizzBuzzWhizz
**Обязательно:** все тесты зелёные; guard clause для `n ≤ 0` и `count < 0`; нет 8 веток на все комбинации.
**Хорошо бы:** склейка через `+=` или `StringBuilder` + проверка «пусто → число»; `ArgumentOutOfRangeException.ThrowIfNegativeOrZero`; `Sequence` создаёт массив нужного размера сразу.

**Частые ошибки**
- Цепочка `if (n % 105 == 0) … else if (n % 35 == 0) …` → спросить «а если добавить правило 11?». **Почему плохо:** экспоненциальный рост веток, легко пропустить комбинацию (21, 35).
- Off-by-one в `Sequence`: `ForNumber(i)` при `i` от 0 → исключение на 0. Попросить прочитать упавший тест.
- `List<string>` + `ToArray()` при известном размере — не ошибка, но лишняя аллокация; упомянуть мягко.
- Проверка `n % 15 == 0` отдельно — следствие непонимания идеи склейки.

**Вопросы к студенту при /check**
- Что поменяется в коде, если добавить правило 11 → `Bang`?
- Почему исключение, а не пустая строка для `n = 0`?

## Задача 3. Greeter
**Обязательно:** `string.IsNullOrWhiteSpace`; `Trim()`; проверка диапазона часа с `ArgumentOutOfRangeException`.
**Хорошо бы:** switch expression с relational patterns (`>= 5 and <= 11`) — можно показать как альтернативу после принятия, подробно в модуле 03; интерполяция `$"Hello, {name.Trim()}!"`.

**Частые ошибки**
- `name.Trim()` без присваивания результата (`name.Trim(); return $"Hello, {name}!"`) → **почему плохо:** строки immutable, `Trim` возвращает новую строку. Отличный повод для вопроса.
- `if (name == null || name == "")` — пропускает строку из пробелов; тест упадёт.
- Диапазоны с «дырой» или перекрытием (`hour > 5` вместо `>= 5`).
- Возврат «Good night» для часа 25 вместо исключения.

**Вопросы к студенту при /check**
- Изменилась ли исходная строка после `Trim()`?
- Почему `IsNullOrWhiteSpace`, а не `IsNullOrEmpty`?

## Задача 4. Калькулятор чаевых
**Обязательно:** `decimal`; `Math.Round(x, 2, MidpointRounding.AwayFromZero)`; округление вверх в `PerPerson` (`Math.Ceiling(x * 100) / 100`); валидация всех аргументов; `Total` переиспользует `CalculateTip`.
**Хорошо бы:** константы вместо магических `100`, `2`; общий приватный метод валидации; expression-bodied `Total`.

**Частые ошибки**
- `double` и `(decimal)` в конце → **почему плохо:** погрешность уже накоплена до приведения.
- `Math.Round` без `MidpointRounding` → тест 6.825 → 6.82 падает. Объяснить banker's rounding (ToEven) и зачем он (меньше систематическая ошибка при массовом округлении).
- Дублирование формулы чаевых в `Total` и `PerPerson` → DRY: одна формула — одно место.
- Деление на `people` до проверки `people > 0` → `DivideByZeroException` вместо понятного `ArgumentOutOfRangeException`.

**Вопросы к студенту при /check**
- Почему decimal, а не double? Что такое банковское округление?
- Почему `PerPerson` округляет вверх?

## Задача 5. Конвертер единиц
**Обязательно:** формулы; проверка входа против констант абсолютного нуля; `ToString("F1", CultureInfo.InvariantCulture)`; `using System.Globalization;`.
**Хорошо бы:** `ArgumentOutOfRangeException.ThrowIfLessThan`; понимание, почему здесь `double`, а не `decimal`.

**Частые ошибки**
- `$"{celsius:F1} °C"` без культуры → на русской Windows тест падает с `"21,5 °C"`. **Почему плохо:** вывод зависит от машины; классический баг продакшена. Показать `string.Create(CultureInfo.InvariantCulture, $"...")` или `ToString(format, culture)`.
- Проверка результата (`if (result < -459.67)`) вместо входа → погрешность double может дать ложное исключение на границе.
- `9 / 5 * celsius` → при int-типах `1 * celsius`. Здесь double спасает, но обсудить.
- `Replace(',', '.')` после форматирования — «костыль»; объяснить, почему культура — правильное решение.

**Вопросы к студенту при /check**
- Почему double сравнивают с точностью?
- Что такое CultureInfo и почему для логов/файлов нужна InvariantCulture?

## Задача 7. ⭐ Калькулятор выражений
**Обязательно:** `ArgumentNullException.ThrowIfNull`; `Split` с `RemoveEmptyEntries`; проверка структуры (нечётное число токенов, числа и операторы на своих местах); `double.TryParse(..., NumberStyles.Float, CultureInfo.InvariantCulture, out ...)`; приоритет `*`/`/`; явная проверка деления на 0; все тесты зелёные.
**Хорошо бы:** один проход O(n) с «суммой и текущим слагаемым»; выделенный `ParseNumber`; понятные сообщения исключений; `switch` по оператору с `default: throw`.

**Частые ошибки**
- Вычисление строго слева направо без приоритета → `2 + 3 * 4 = 20`. Спросить, как это объяснить пользователю.
- Два прохода с `List` и удалением элементов (`RemoveAt`) — работает, но O(n²) и сложно читать; принять, обсудить сложность.
- `double.Parse` в `try/catch (Exception)` → **почему плохо:** ловит всё подряд (включая баги), исключения для управления потоком — дорого и непрозрачно.
- Нет проверки деления на ноль → тест получает `Infinity`. Объяснить IEEE 754: `1.0 / 0 == double.PositiveInfinity`, а `1 / 0` для int — `DivideByZeroException`.
- `Split(' ')` без `RemoveEmptyEntries` → пустые токены на двойных пробелах.

**Вопросы к студенту при /check**

- Почему `null` → ArgumentNullException, а `""` → FormatException?

## Quiz

1. **Что выведет код?**
   ```csharp
   int a = 9, b = 5;
   Console.WriteLine(a / b);
   Console.WriteLine(a / (double)b);
   ```
   **Ответ:** `1` и `1.8` (на русской Windows — `1,8`). **Почему:** деление двух `int` — целочисленное; приведение одного операнда к `double` делает деление вещественным. Вторая строка зависит от текущей культуры.

2. **Выбор варианта.** Во что компилятор C# превращает исходный код? A) в машинный код x64; B) в IL и метаданные внутри сборки; C) в JavaScript; D) в байткод JVM.
   **Ответ:** B. **Почему:** машинный код создаёт JIT (или AOT) позже, под конкретную платформу.

3. **Найди ошибку.** «Я добавил `using Newtonsoft.Json;`, но компилятор пишет CS0246: тип или namespace не найден».
   **Ответ:** не подключён NuGet-пакет. **Почему:** `using` лишь сокращает имена; сборку нужно добавить через `dotnet add package Newtonsoft.Json`.

4. **Что выведет код?** (запуск: `dotnet run -- one "two three"`)
   ```csharp
   Console.WriteLine(args.Length);
   Console.WriteLine(args[1]);
   ```
   **Ответ:** `2` и `two three`. **Почему:** аргументы после `--` передаются программе; кавычки объединяют слова в один аргумент; имя программы в `args` не входит (в отличие от C).

5. **Выбор варианта.** На сервере нужно только запускать готовое веб-приложение. Что установить? A) .NET SDK; B) ASP.NET Core Runtime; C) Visual Studio; D) ничего, если опубликовать self-contained.
   **Ответ:** B или D. **Почему:** SDK нужен для сборки, на сервере достаточно runtime; self-contained приложение несёт runtime с собой.

6. **Найди ошибку.**
   ```csharp
   string? input = Console.ReadLine();
   int age = int.Parse(input);
   ```
   **Ответ:** nullable warning CS8604 и `FormatException`/`ArgumentNullException` при некорректном вводе. **Почему:** `ReadLine` может вернуть `null`, пользователь может ввести не число. Правильно: `int.TryParse(input, out var age)`.

7. **Что выведет код?**
   ```csharp
   Console.WriteLine(Math.Round(2.5));
   Console.WriteLine(Math.Round(3.5));
   ```
   **Ответ:** `2` и `4`. **Почему:** по умолчанию банковское округление (MidpointRounding.ToEven) — к ближайшему чётному. Для «школьного» нужно `MidpointRounding.AwayFromZero`.

8. **Выбор варианта.** Когда JIT компилирует метод? A) при сборке проекта; B) при загрузке сборки — все методы сразу; C) при первом вызове метода; D) при каждом вызове.
   **Ответ:** C. **Почему:** компилируются только реально вызываемые методы; результат кэшируется. С tiered compilation «горячий» метод может быть перекомпилирован ещё раз с оптимизациями.
