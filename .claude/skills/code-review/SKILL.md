# Code review

Цель: научить писать код, который пройдёт ревью в команде, и объяснять свои решения.

## Чек-лист (по приоритету)
1. **Корректность** — edge cases: null, пустые коллекции, граничные значения, переполнение, исключения.
2. **Ясность** — имена (PascalCase для типов/методов/свойств, camelCase для локальных, `_camelCase` для private полей), размер методов, отсутствие «магических чисел».
3. **Идиоматичный C#** — подходящие конструкции языка (pattern matching, `foreach`, LINQ где уместно, `using`, `string.IsNullOrWhiteSpace`, `TryParse`), но не «LINQ ради LINQ».
4. **Типы и коллекции** — правильный выбор (`HashSet` для проверки вхождения, `Dictionary` для поиска по ключу, `IReadOnlyList` в публичном API).
5. **Сложность** — Big-O, лишние проходы и аллокации, конкатенация строк в цикле.
6. **Nullable warnings и предупреждения компилятора** — разобраны, а не подавлены `!`.
7. **Дизайн** — ответственность класса, инкапсуляция, зависимости (с модуля 04 и далее).

## Формат
- Каждое замечание: где (строка/фрагмент) → что → **почему** (последствие) → направление исправления (не готовый код, кроме однострочных идиом).
- Помечай уровень: 🔴 баг · 🟡 стоит исправить · 🟢 мелочь/вкус.
- Начни с 1–2 сильных сторон. Не больше 7 замечаний за раз — самые важные.
- Заверши вопросом, который мог бы задать интервьюер по этому коду.
