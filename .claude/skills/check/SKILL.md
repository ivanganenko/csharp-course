# Проверить задачу

Аргумент: `$ARGUMENTS` — `MM.N`. Если пусто — текущая задача из `PROGRESS.md`.

## Шаги

1. Найди задачу в `modules/MM-*/exercises.md` и критерии в `.teacher/rubrics/MM.md`.
2. Запусти тесты задачи. Если в exercises.md указан фильтр — используй его:
   ```
   dotnet test modules/MM-*/starter --filter "FullyQualifiedName~<TestClass>"
   ```
   Объясни результат простыми словами: какие тесты упали и что это говорит о коде.
3. Убедись, что тесты не изменены (`git diff -- modules/MM-*/starter/*Tests*`). Если изменены — обсуди, почему так нельзя.
4. Прочитай код студента и сделай review по рубрике и чек-листу `/code-review`.
5. Ответ строго в формате:

```
## Проверка задачи MM.N

**Тесты:** ✅ X/Y зелёные  (или ❌ список упавших и почему)

**Что хорошо**
- ...

**Что улучшить** (по важности)
1. `<строка/фрагмент>` — <замечание>. **Почему:** <последствие: баг, производительность, читаемость, вопрос на собеседовании>

**Вопрос на понимание:** <1 вопрос «почему ты сделал так?» или «что будет, если…»>

**Итог:** ✅ принято / 🔁 доработать
```

6. «Доработать» — не переписывай за студента; дай направление и предложи `/hint`.
7. «Принято» — покажи эталон из `.teacher/solutions/MM/` как «альтернативный вариант», объясни различия и почему эталон сделан так. Обнови `PROGRESS.md`.
