## Задача 1. Консольное приложение с нуля  ·  ⏱ ~30 мин  ·  🧪 исследование

**Что сделать:** вне папки курса (например, `~/projects/hello-dotnet`) создайте **без IDE**, только через `dotnet` CLI:

1. `dotnet --info` — запишите версии SDK и runtime.
2. `dotnet new console -n Hello` и запустите `dotnet run`.
3. Откройте `Hello.csproj` и `Program.cs`. Перепишите программу так, чтобы она:
   - спрашивала имя и выводила `Привет, <имя>!` (если имя пустое — `Привет, незнакомец!`);
   - спрашивала год рождения и выводила возраст в текущем году (`DateTime.Now.Year`); если ввели не число — сообщение об ошибке в `Console.Error` и код возврата `1`;
   - печатала количество аргументов командной строки и сами аргументы (`dotnet run -- one two`).
4. Перепишите ту же программу в «классическом» виде: `namespace`, класс `Program`, `static int Main(string[] args)`. Убедитесь, что поведение не изменилось.
5. Выполните `dotnet build -c Release` и найдите получившийся `Hello.dll` в `bin/`. Запустите его командой `dotnet bin/Release/net10.0/Hello.dll`.
6. Узнайте код возврата последней команды: PowerShell — `$LASTEXITCODE`, bash — `echo $?`.

**Зачем:** на собеседовании и в работе нужно уверенно собрать и запустить проект без «магической кнопки» IDE — так работают CI-серверы. Плюс вы увидите, что top-level statements — это просто сахар над `Main`.

**Подумай / ответь письменно:**
- Почему `Console.ReadLine()` возвращает `string?`, а не `string`? Что будет, если запустить программу с вводом из пустого файла?
- Что лежит в `Hello.dll` — машинный код или что-то другое? Почему его можно скопировать на Linux-машину с .NET 10 runtime и запустить?

## Задача 6. Под капотом: отладчик и IL  ·  ⏱ ~40 мин  ·  🧪 исследование

**Что сделать:**

**Часть A — отладчик.**
1. Откройте `starter/Module01.slnx` в IDE. Поставьте breakpoint в первой строке `FizzBuzz.ForNumber`.
2. Запустите тест `ForNumber_PositiveNumber_ReturnsExpectedWord` **в режиме отладки** (Debug Test).
3. Пройдите метод по шагам (Step Over), посмотрите значения переменных в Locals, откройте Call Stack — найдите там метод теста.
4. Сделайте breakpoint условным: останов только при `n == 105`.

**Часть B — IL на https://sharplab.io** (справа выберите `IL`):
1. Вставьте метод `static int Add(int a, int b) => a + b;` — найдите инструкции `ldarg`, `add`, `ret`.
2. Вставьте `Console.WriteLine("Hi");` как top-level statement и переключитесь на `C#` в правой панели: какой класс и метод сгенерировал компилятор?
3. Сравните IL для `int x = 5; object o = x;` и `int x = 5; long y = x;`. Какая инструкция есть в первом случае и нет во втором? (Подсказка: об этом весь модуль 02.)
4. Сравните IL для `$"Hello, {name}!"` и `"Hello, " + name + "!"`.

**Зачем:** отладчик — ежедневный инструмент, а на испытательном сроке джуна часто оценивают по тому, как быстро он сам находит баги. SharpLab учит отвечать на вопрос «во что это компилируется?» фактами, а не догадками — на собеседовании это сильный сигнал.

**Подумай / ответь письменно:**
- Почему отладчик может не показать значение переменной в Release-сборке?
- Почему IL одинаков для Windows и Linux, а машинный код — нет? Кто и когда создаёт машинный код?
