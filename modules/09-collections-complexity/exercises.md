## Задача 1. Частота слов  ·  ⏱ ~35 мин  ·  🟢 базовая

**Что сделать:** реализуй `WordFrequency.Count(text)` — словарь «слово → сколько раз встретилось» (без учёта регистра, слова — последовательности букв/цифр) и `WordFrequency.Top(text, n)` — n самых частых слов (по убыванию частоты, при равенстве — по алфавиту).

**Зачем:** `Dictionary` как счётчик — один из самых частых приёмов в реальном коде (статистика, аналитика логов, группировки) и в задачах на собеседовании. Заодно потренируешь `TryGetValue` и сортировку с несколькими ключами.

**Файл:** `Module09.Tasks/WordFrequency.cs`
**Тесты:** `dotnet test --filter "FullyQualifiedName~WordFrequencyTests"`

**Подумай / ответь письменно:**

## Задача 2. Удаление дубликатов с сохранением порядка  ·  ⏱ ~25 мин  ·  🟢 базовая

**Что сделать:** реализуй `Deduplicator.RemoveDuplicates` (оставить первые вхождения в исходном порядке, с опциональным `IEqualityComparer<T>`) и `Deduplicator.FindDuplicates` (элементы, которые повторяются, — каждый один раз). Без LINQ, за O(n).

**Файл:** `Module09.Tasks/Deduplicator.cs`
**Тесты:** `dotnet test --filter "FullyQualifiedName~DeduplicatorTests"`

**Подумай / ответь письменно:**

2. Как передача `StringComparer.OrdinalIgnoreCase` меняет поведение `HashSet`? Какие методы компаратора он вызывает?

## Задача 6. Замеры: List vs HashSet и рост capacity  ·  ⏱ ~25 мин  ·  🧪 исследование

**Что сделать:** создай консольное приложение вне `starter` (`dotnet new console -n CollectionsLab`, запуск `dotnet run -c Release`):
1. Заполни `List<int>` и `HashSet<int>` числами 0..N–1 для N = 1 000, 10 000, 100 000. Через `System.Diagnostics.Stopwatch` замерь 10 000 вызовов `Contains` со случайными числами. Выведи таблицу.
2. Добавляй элементы в пустой `List<int>` и печатай `Capacity` каждый раз, когда она меняется. Затем повтори с `new List<int>(1000)`.
3. Создай класс-ключ с `Equals`, но без `GetHashCode`, положи экземпляр в `HashSet` и проверь `Contains` с «равным» объектом. Потом добавь `GetHashCode`, который всегда возвращает `0`, и замерь `Contains` на 10 000 элементах.

**Зачем:** увидеть Big-O на своих цифрах. Таблица «List растёт линейно, HashSet — почти константа» запоминается навсегда, а эксперимент с `GetHashCode() => 0` наглядно показывает деградацию хэш-таблицы до O(n).

**Подумай / ответь письменно:**
1. Во сколько раз выросло время `List.Contains` при росте N в 10 раз? А у `HashSet`?
2. Почему `GetHashCode() => 0` формально корректен (контракт не нарушен), но катастрофичен для производительности?

**Что сделать:** реализуй `LruCache<TKey, TValue>` фиксированной ёмкости: `TryGet` (освежает элемент), `Put` (добавляет/обновляет; при переполнении вытесняет самый давно использованный), `ContainsKey` (не освежает), `KeysByRecency`. Все основные операции — O(1).

**Тесты:** `dotnet test --filter "FullyQualifiedName~LruCacheTests"`

**Подумай / ответь письменно:**
