## 1. Ветвления: `if`, `switch` statement, switch expression

```csharp
int temperature = 23;

if (temperature < 0)
{
    Console.WriteLine("Мороз");
}
else if (temperature < 20)
{
    Console.WriteLine("Прохладно");
}
else
{
    Console.WriteLine("Тепло");      // вывод: Тепло
}

var label = temperature > 25 ? "жарко" : "нормально";   // тернарный оператор для простых случаев
```

**`switch` statement** (оператор) — классика, выполняет блоки кода:

```csharp
switch (DateTime.Today.DayOfWeek)
{
    case DayOfWeek.Saturday:
    case DayOfWeek.Sunday:           // несколько case подряд — общая ветка
        Console.WriteLine("Выходной");
        break;                       // break обязателен: «проваливания» (fall-through) как в C нет
    default:
        Console.WriteLine("Будни");
        break;
}
```

**Switch expression** (выражение, C# 8) — **возвращает значение**, короче и безопаснее:

```csharp
string GetSeason(int month) => month switch
{
    12 or 1 or 2 => "Winter",
    >= 3 and <= 5 => "Spring",
    >= 6 and <= 8 => "Summer",
    >= 9 and <= 11 => "Autumn",
    _ => throw new ArgumentOutOfRangeException(nameof(month)),   // _ — discard, «всё остальное»
};
Console.WriteLine(GetSeason(4));     // вывод: Spring
```

Компилятор проверяет switch expression на **полноту** (exhaustiveness): если какие-то значения не покрыты, будет предупреждение CS8509, а в runtime — `SwitchExpressionException`. Недостижимую ветку (стоящую после более общей) компилятор отклонит с ошибкой.

> **Почему так?** В C/C++ забытый `break` в `switch` — классический баг («проваливание» в следующий case). C# запретил неявный fall-through: каждая непустая секция должна заканчиваться `break`, `return` или `throw`. Switch expression пошёл дальше: это **выражение**, а не набор инструкций — каждая ветка обязана вернуть значение, нельзя «забыть присвоить переменную в одной из веток», а проверка полноты ловит необработанные случаи при компиляции.

> 💼 **На собеседовании:** «Switch expression возвращает значение, компактнее, поддерживает все паттерны и проверяется на полноту. Switch statement — когда в ветках нужно выполнить несколько действий, а не вычислить значение».

## 2. Pattern matching

**Pattern matching** (сопоставление с образцом) — проверка «формы» значения с одновременным извлечением данных. Работает в `is`, `switch` statement и switch expression.

| Паттерн | Пример | Смысл |
|---------|--------|-------|
| constant | `x is 0`, `x is null` | равно константе |
| type / declaration | `o is string s` | тип + новая переменная |
| relational (C# 9) | `x is > 0` | сравнение `<`, `<=`, `>`, `>=` |
| logical (C# 9) | `x is >= 1 and <= 9`, `x is not null`, `a or b` | `and`, `or`, `not` |
| property | `p is { Age: >= 18, Name: "Anna" }` | проверка свойств |
| positional | `point is (0, 0)` | через `Deconstruct` (кортежи, record) |
| list (C# 11) | `arr is [1, .., var last]` | структура массива/списка |
| discard / var | `_`, `var x` | «что угодно» |

```csharp
object value = "hello";

if (value is string { Length: > 3 } text)          // type + property pattern + переменная
{
    Console.WriteLine(text.ToUpper());             // вывод: HELLO
}

string Classify(object? o) => o switch
{
    null => "null",
    int n when n % 2 == 0 => "чётное",             // when — дополнительное условие (case guard)
    int => "нечётное",
    string { Length: 0 } => "пустая строка",
    int[] and [] => "пустой массив",
    int[] and [var first, ..] => $"массив, начинается с {first}",   // .. — slice pattern, «сколько угодно»
    _ => "что-то другое",
};
Console.WriteLine(Classify(new[] { 5, 6 }));       // вывод: массив, начинается с 5

if (value is not null) { }                         // идиоматичная проверка на null (не зависит от перегрузки ==)
```

Важно: **type pattern проверяет точный тип значения**, числовых преобразований нет: `5L is int` — `false`, ведь в `object` упакован `long`.

> **Почему так?** Раньше та же логика писалась цепочками `if (o is string) { var s = (string)o; if (s.Length > 3) ... }` — двойная проверка типа и много шума. Pattern matching пришёл из функциональных языков (F#, Haskell): условие описывает **форму данных декларативно**, а компилятор проверяет полноту и недостижимость веток. `is not null` предпочтительнее `!= null`, потому что оператор `!=` класс может перегрузить как угодно, а паттерн — нет.

> 💼 **На собеседовании:** «Pattern matching — проверка значения по образцу с извлечением данных: тип, константа, сравнения, свойства, позиции, списки. Делает ветвления декларативными, а компилятор проверяет полноту switch expression».

## 3. Циклы, `break`, `continue`

```csharp
for (var i = 0; i < 3; i++)            // счётчик: когда нужен индекс
{
    Console.Write(i);                  // вывод: 012
}

int[] prices = [100, 250, 80];
foreach (var price in prices)          // перебор коллекции: когда индекс не нужен
{
    if (price < 100) continue;         // continue — к следующей итерации
    Console.Write($"{price} ");        // вывод: 100 250
}

var attempts = 0;
while (attempts < 5)                   // пока условие истинно; может не выполниться ни разу
{
    attempts++;
    if (attempts == 3) break;          // break — выход из ближайшего цикла
}

string? input;
do                                     // do-while: тело выполнится ХОТЯ БЫ ОДИН раз
{
    Console.Write("Введите 'q': ");
    input = Console.ReadLine();
} while (input is not null && input != "q");
```

- `foreach` работает с любым типом, у которого есть `GetEnumerator()` (массивы, `List<T>`, строки…). Переменная цикла **только для чтения**, и изменять саму коллекцию (`Add`/`Remove`) во время `foreach` нельзя — `InvalidOperationException` (модуль 09).
- `break` выходит только из **одного** (ближайшего) цикла. Чтобы выйти из вложенных — `return` из метода (вынесите циклы в метод) или флаг.
- Бесконечный цикл — `while (true) { ... break; }`; `goto` в C# существует, но почти не используется.

> **Почему так?** Разные циклы выражают разное **намерение**: `foreach` — «для каждого элемента», нет индексов, нет off-by-one ошибок; `for` — когда важен индекс или шаг; `while` — когда число итераций заранее неизвестно; `do-while` — когда тело нужно выполнить хотя бы раз (меню, повтор ввода). Выбор правильного цикла — это читаемость: ревьюер сразу понимает, что происходит.

## 4. Методы и передача параметров: по значению, `ref`, `out`, `in`

По умолчанию **все** параметры в C# передаются **по значению** (by value) — метод получает копию. Для value type копируется значение, для reference type — **ссылка** (объект один и тот же!).

```csharp
void Increment(int x) => x++;                 // меняем копию
void Rename(List<string> list) => list.Add("Bob");   // меняем ОБЪЕКТ через копию ссылки
void Replace(List<string> list) => list = new List<string>();   // меняем только копию ссылки

var n = 1;
Increment(n);
Console.WriteLine(n);                          // вывод: 1

var names = new List<string>();
Rename(names);
Replace(names);
Console.WriteLine(names.Count);                // вывод: 1 — Add виден, а замена ссылки — нет
```

Модификаторы передачи **по ссылке**:

| Модификатор | До вызова | Внутри метода | Зачем |
|-------------|-----------|---------------|-------|
| `ref` | переменная **должна** быть инициализирована | можно читать и менять | метод меняет переменную вызывающего |
| `out` | можно не инициализировать | **обязан** присвоить до выхода | дополнительный результат (`TryParse`) |
| `in` | должна быть инициализирована | только чтение | передать большой struct без копирования |

```csharp
void Swap(ref int a, ref int b) => (a, b) = (b, a);

int x = 1, y = 2;
Swap(ref x, ref y);                            // ref обязателен и при вызове — это видно читателю
Console.WriteLine($"{x} {y}");                 // вывод: 2 1

if (int.TryParse("42", out var number))        // out var — объявление прямо в вызове
{
    Console.WriteLine(number);                 // вывод: 42
}

double Length(in Vector3 v) => Math.Sqrt(v.X * v.X + v.Y * v.Y + v.Z * v.Z);   // in: без копии 12+ байт
```

Сегодня вместо нескольких `out` часто возвращают **кортеж** (tuple): `(int Min, int Max) GetRange(...)`. `out` остаётся стандартом для Try-паттерна: `bool TryXxx(..., out T result)`.

> **Почему так?** Передача по значению по умолчанию — **безопасность**: вызванный метод не может неожиданно поменять ваши переменные. Если это нужно — `ref` пишется **и в объявлении, и при вызове**, так что побочный эффект виден в месте вызова. `out` отличается от `ref` контрактом: компилятор гарантирует, что метод присвоит значение, поэтому вызывающему не нужно инициализировать переменную. `in` появился ради производительности: большие struct копируются дорого, а `in` даёт ссылку с гарантией «только чтение».

> 💼 **На собеседовании:** «Reference type передаётся по ссылке?» — «Нет: по умолчанию всё передаётся по значению; для reference type копируется ссылка, поэтому изменения объекта видны снаружи, а присваивание параметру нового объекта — нет. `ref` передаёт саму переменную. `out` — как `ref`, но метод обязан присвоить значение, а вызывающему не нужно её инициализировать. `in` — readonly ссылка».

## 5. `params`, optional и named параметры, overloading

```csharp
int Sum(params int[] numbers)                  // произвольное число аргументов
{
    var total = 0;
    foreach (var n in numbers) total += n;
    return total;
}
Console.WriteLine(Sum());                       // вывод: 0  — компилятор передаст пустой массив
Console.WriteLine(Sum(1, 2, 3));                // вывод: 6  — компилятор создаст new[] { 1, 2, 3 }

string Greet(string name, string greeting = "Hello", bool shout = false)   // optional parameters
{
    var text = $"{greeting}, {name}!";
    return shout ? text.ToUpper() : text;
}
Console.WriteLine(Greet("Anna"));                       // вывод: Hello, Anna!
Console.WriteLine(Greet("Anna", shout: true));          // named argument: пропускаем greeting
Console.WriteLine(Greet(shout: false, name: "Bob"));    // named — в любом порядке
```

- `params` — только последний параметр и только один. С C# 13 можно `params ReadOnlySpan<int>` / `params List<int>` (params collections) — меньше аллокаций.
- Значения по умолчанию — **константы времени компиляции** и подставляются **в месте вызова**.
- Optional параметры идут после обязательных.

**Overloading** (перегрузка) — несколько методов с одним именем и разными **сигнатурами** (количество, типы, порядок, модификаторы `ref`/`out` параметров):

```csharp
double Area(double radius) => Math.PI * radius * radius;
double Area(double width, double height) => width * height;
// int Area(double radius) => ...;   // ошибка: отличие только в возвращаемом типе — это не перегрузка

Console.WriteLine(Area(2, 3));       // вывод: 6 — выбрано на этапе КОМПИЛЯЦИИ по аргументам
```

**Expression-bodied** члены — однострочные методы и свойства через `=>`: `int Square(int x) => x * x;`.

> **Почему так?** `params` — удобство для вызывающего кода (`string.Format`, `Console.WriteLine(format, args)`), но за него платят созданием массива при каждом вызове. Optional/named параметры заменяют «лестницу» перегрузок `Greet(name)`, `Greet(name, greeting)`, `Greet(name, greeting, shout)`. Ловушка версионирования: значение по умолчанию **вшивается в вызывающую сборку**; если библиотека поменяет `"Hello"` на `"Hi"`, старый скомпилированный код продолжит передавать `"Hello"`. Перегрузки по возвращаемому типу запрещены, потому что результат можно и не использовать — тогда компилятор не смог бы выбрать метод.

> 💼 **На собеседовании:** «Чем перегрузка отличается от переопределения (override)?» — «Overloading — несколько методов с одним именем и разными параметрами, выбор при компиляции. Overriding — замена реализации виртуального метода в наследнике, выбор в runtime по реальному типу объекта (модуль 05)».

## 6. Local functions

**Local function** (локальная функция, C# 7) — метод, объявленный внутри другого метода:

```csharp
int CountVowels(string text)
{
    var count = 0;
    foreach (var c in text)
    {
        if (IsVowel(c)) count++;
    }
    return count;

    // Видна только внутри CountVowels. static — запрещает захват переменных внешнего метода.
    static bool IsVowel(char c) => "aeiouаеёиоуыэюя".Contains(char.ToLowerInvariant(c));
}
Console.WriteLine(CountVowels("Hello, Мир"));   // вывод: 3
```

Локальная функция может **захватывать** переменные внешнего метода (как в задаче про Ханойские башни: рекурсивная `Move` добавляет ходы в общий список).

> **Почему так?** Вспомогательный метод, нужный только одному методу, засоряет класс и создаёт соблазн вызвать его откуда-то ещё. Локальная функция ограничивает область видимости. По сравнению с лямбдой она может быть рекурсивной без трюков, иметь `ref`/`out`/`params` и чаще обходится без аллокации делегата.

## 7. Рекурсия и стек вызовов

**Рекурсия** — метод вызывает сам себя. Нужны **базовый случай** (base case — когда остановиться) и **шаг**, приближающий к нему.

```csharp
long Factorial(int n) => n <= 1 ? 1 : n * Factorial(n - 1);
Console.WriteLine(Factorial(5));     // вывод: 120 = 5 * 4 * 3 * 2 * 1
```

Каждый вызов метода кладёт в **stack** потока **кадр** (stack frame): параметры, локальные переменные, адрес возврата. Размер стека ограничен (по умолчанию ~1 МБ для основного потока в Windows, 8 МБ в Linux), поэтому слишком глубокая рекурсия (обычно десятки тысяч вызовов, точное число зависит от размера кадра) приводит к **`StackOverflowException`**. Его **нельзя поймать** `catch` — процесс аварийно завершается.

```
Factorial(3)
 └─ Factorial(2)          ← каждый уровень — отдельный кадр в стеке
     └─ Factorial(1)      ← базовый случай: стек начинает «сворачиваться»
```

Вторая проблема — **экспоненциальная сложность**: наивный `Fib(n) = Fib(n-1) + Fib(n-2)` вычисляет одни и те же значения миллионы раз (O(2ⁿ)). Решения: цикл (O(n)) или **мемоизация** (memoization — кэширование уже посчитанных результатов).

Когда рекурсия уместна: деревья (обход папок, JSON, DOM), «разделяй и властвуй» (быстрая сортировка, Ханойские башни), перебор вариантов. Когда нет: линейные задачи (сумма, факториал на проде) — цикл проще и не рискует стеком.

> **Почему так?** Рекурсия часто повторяет математическое определение задачи — код короче и очевиднее. Но каждый вызов стоит памяти в стеке и времени. C# (в отличие от F#) **не гарантирует** tail call optimization (оптимизацию хвостовой рекурсии), поэтому глубокую рекурсию переписывают в цикл или используют явный `Stack<T>` в heap. А `StackOverflowException` не ловится, потому что после переполнения стека у потока нет места даже для выполнения обработчика — восстановить состояние надёжно невозможно.

> 💼 **На собеседовании:** «Что произойдёт при бесконечной рекурсии?» — «Каждый вызов добавляет кадр в стек потока; стек ограничен, и будет `StackOverflowException`, который нельзя перехватить — процесс упадёт. Поэтому нужен базовый случай, а глубокую рекурсию заменяют циклом или явным стеком».

## 8. Массивы: одномерные, многомерные, jagged

Массив — reference type фиксированной длины; элементы инициализируются значениями по умолчанию; индексы с 0; выход за границы — `IndexOutOfRangeException`.

```csharp
int[] numbers = new int[3];                    // [0, 0, 0]
int[] primes = { 2, 3, 5, 7 };
int[] evens = [2, 4, 6];                        // collection expression (C# 12)
Console.WriteLine(primes[^1]);                  // вывод: 7 — индекс с конца (C# 8)
Console.WriteLine(string.Join(",", primes[1..3]));   // вывод: 3,5 — диапазон (range), создаёт КОПИЮ

int[,] grid = new int[2, 3];                    // многомерный (rectangular): 2 строки × 3 столбца
grid[1, 2] = 9;
Console.WriteLine(grid.GetLength(0));           // вывод: 2 — строк
Console.WriteLine(grid.Length);                 // вывод: 6 — всего элементов

int[][] jagged = new int[3][];                  // jagged (зубчатый): массив массивов
jagged[0] = [1];
jagged[1] = [1, 1];
jagged[2] = [1, 2, 1];                          // строки разной длины
Console.WriteLine(jagged[2].Length);            // вывод: 3
```

| | `int[,]` (многомерный) | `int[][]` (jagged) |
|---|---|---|
| Строки | одинаковой длины | любой длины |
| В памяти | один непрерывный блок | массив ссылок + отдельные массивы |
| Доступ | `a[i, j]` | `a[i][j]` |
| Скорость | обычно чуть медленнее (вызов метода для индексации) | обычно быстрее — JIT лучше оптимизирует одномерные |

**Полезные методы `Array`:**

```csharp
int[] data = [5, 2, 9, 1];
Array.Sort(data);                                // сортировка на месте: [1, 2, 5, 9]
Console.WriteLine(Array.BinarySearch(data, 5));  // вывод: 2 (только для отсортированного!)
Console.WriteLine(Array.IndexOf(data, 9));       // вывод: 3
Array.Reverse(data);                             // [9, 5, 2, 1]
var copy = (int[])data.Clone();                  // поверхностная копия (shallow copy)
Array.Resize(ref data, 6);                       // создаёт НОВЫЙ массив и копирует — длина массива неизменна
Console.WriteLine(Array.Exists(data, x => x > 8));   // вывод: True
```

**`Span<T>`** — «окно» на непрерывный участок памяти (массив, часть строки, стек) без копирования: `data.AsSpan(1, 2)`. Позволяет писать быстрый код без аллокаций; подробно — в модуле 12.

> **Почему так?** Массив — самая «низкоуровневая» коллекция: непрерывный блок памяти, доступ по индексу за O(1), проверка границ на каждом обращении (вместо порчи памяти, как в C). Фиксированная длина — следствие непрерывности: чтобы «вырасти», нужно выделить новый блок и скопировать — это и делает `List<T>` за вас (модуль 09). Jagged массивы появились, потому что строки разной длины встречаются часто (треугольник Паскаля, расписание по дням), а прямоугольный массив тратил бы память на «пустые» ячейки.

> 💼 **На собеседовании:** «Чем `int[,]` отличается от `int[][]`?» — «Первый — прямоугольный, один блок памяти, все строки одной длины. Второй — массив ссылок на отдельные массивы, строки могут быть разной длины».

## Типичные ошибки

1. **Off-by-one**: `for (i = 0; i <= arr.Length; i++)` → `IndexOutOfRangeException`. Граница — `< Length`.
2. **`(low + high) / 2`** в бинарном поиске → переполнение. `low + (high - low) / 2`.
3. **`low = mid` вместо `mid + 1`** → бесконечный цикл на двух элементах.
4. **Рекурсия без базового случая** или с шагом, который к нему не приближает → `StackOverflowException`.
5. **Наивный рекурсивный Фибоначчи на больших n** → O(2ⁿ), программа «зависает».
6. **Ожидание, что метод изменит переданный int** без `ref`.
7. **«Reference types передаются по ссылке»** — нет, передаётся копия ссылки.
8. **Неприсвоенный `out` на одной из веток** → ошибка компиляции CS0177.
9. **Порядок веток в switch**: общий паттерн (`int`) выше частного (`0`) → ошибка CS8510 (ветка недостижима). Читайте сообщения компилятора!
10. **`Math.Abs(int.MinValue)`** → `OverflowException`.
11. **Изменение коллекции внутри `foreach`** → `InvalidOperationException`.
12. **`switch` по типу вместо полиморфизма** в больших иерархиях — обсудим в модуле 05.

## Глоссарий

| Термин | Что значит |
|--------|-----------|
| Switch expression | `switch`, возвращающий значение; ветки `pattern => result` |

| Exhaustiveness | полнота: все возможные значения покрыты ветками |

| Pass by value | передача копии значения (или копии ссылки) |
| `ref` / `out` / `in` | передача по ссылке: чтение-запись / обязательный результат / только чтение |

| Expression-bodied member | член, записанный через `=>` |
| Local function | метод, объявленный внутри другого метода |

## Вопросы на собеседовании

<details><summary><b>Чем ref отличается от out и in?</b></summary>

Все три передают аргумент по ссылке — метод работает с самой переменной вызывающего кода. `ref` требует, чтобы переменная была инициализирована до вызова; метод может читать и менять её. `out` не требует инициализации, но метод обязан присвоить значение до выхода (типичный пример — `int.TryParse`). `in` — ссылка только для чтения, используется для передачи больших struct без копирования.
</details>

<details><summary><b>Объекты (reference types) передаются в метод по ссылке?</b></summary>

Нет, по умолчанию всё передаётся по значению. Для reference type копируется ссылка: метод работает с тем же объектом, поэтому изменения его состояния видны снаружи. Но если внутри метода присвоить параметру новый объект, исходная переменная не изменится — изменилась только копия ссылки. Чтобы заменить сам объект у вызывающего, нужен `ref`.
</details>

<details><summary><b>Что такое pattern matching? Какие паттерны вы знаете?</b></summary>

Проверка значения на соответствие образцу с одновременным извлечением данных — в `is`, `switch` и switch expression. Паттерны: constant, type/declaration (`o is string s`), relational (`> 0`), logical (`and`/`or`/`not`), property (`{ Age: > 18 }`), positional (`(0, 0)` через Deconstruct), list (`[1, .., var last]`), var и discard. Делает код декларативнее, а компилятор проверяет полноту и недостижимые ветки.
</details>

<details><summary><b>Чем switch expression отличается от switch statement?</b></summary>

Statement выполняет блоки инструкций, требует `break`/`return` в конце секции. Expression возвращает значение: каждая ветка — `pattern => выражение`, нет `case`/`break`, компактнее, проверяется на полноту (предупреждение компилятора и `SwitchExpressionException` в runtime для непокрытых значений). Expression выбирают, когда нужно вычислить значение; statement — когда в ветках несколько действий.
</details>

<details><summary><b>Что такое перегрузка методов? Можно ли перегрузить только по возвращаемому типу?</b></summary>

Overloading — несколько методов с одним именем и разными сигнатурами: количество, типы, порядок параметров, модификаторы `ref`/`out`/`in`. Выбор перегрузки — на этапе компиляции по типам аргументов. Только по возвращаемому типу нельзя: возвращаемый тип не входит в сигнатуру, а результат вызова можно и не использовать, поэтому компилятор не смог бы выбрать метод.
</details>

<details><summary><b>Что такое params? Какие ограничения?</b></summary>

Позволяет передать переменное число аргументов, которые компилятор соберёт в массив (`Sum(1, 2, 3)` → `Sum(new[] {1, 2, 3})`). Может быть только один `params` и только последним параметром. Можно передать и готовый массив. Минус — аллокация массива при каждом вызове; с C# 13 можно объявить `params ReadOnlySpan<T>` и избежать её.
</details>

<details><summary><b>Какие подводные камни у optional параметров?</b></summary>

Значения по умолчанию — константы времени компиляции, и компилятор подставляет их в место вызова. Если библиотека поменяет значение по умолчанию, уже скомпилированные клиенты продолжат передавать старое, пока их не пересоберут. Также optional параметры плохо сочетаются с перегрузками (неоднозначность) и должны стоять после обязательных. Named arguments позволяют пропускать часть optional параметров и делают вызов читаемее.
</details>

<details><summary><b>Что произойдёт при бесконечной рекурсии? Можно ли поймать это исключение?</b></summary>

Каждый вызов добавляет кадр в stack потока, стек ограничен (порядка 1 МБ), поэтому возникнет `StackOverflowException`. Поймать его нельзя — CLR завершает процесс, потому что для выполнения обработчика тоже нужен стек. Защита: корректный базовый случай, ограничение глубины, замена рекурсии циклом или явным `Stack<T>`.
</details>

<details><summary><b>Чем int[,] отличается от int[][]?</b></summary>

`int[,]` — многомерный (прямоугольный) массив: один блок памяти, все строки одинаковой длины, доступ `a[i, j]`, размеры через `GetLength`. `int[][]` — jagged: массив ссылок на отдельные одномерные массивы, строки могут быть разной длины, доступ `a[i][j]`. Jagged обычно быстрее на практике, потому что JIT лучше оптимизирует одномерные массивы.
</details>

<details><summary><b>Как работает бинарный поиск и какова его сложность?</b></summary>

Работает только на отсортированных данных: сравниваем искомое со средним элементом и отбрасываем половину, где его точно нет. Сложность O(log n) — для миллиона элементов около 20 сравнений. Классические ошибки: переполнение в `(low + high) / 2` (правильно `low + (high - low) / 2`), неверные границы (`<` vs `<=`, `mid` vs `mid ± 1`), из-за которых цикл зацикливается или пропускает элемент.
</details>

<details><summary><b>Что выведет код?</b></summary>

```csharp
void Change(int[] arr, int x)
{
    arr[0] = 100;
    arr = new int[] { 7 };
    x = 100;
}
int[] data = { 1, 2 };
int value = 1;
Change(data, value);
Console.WriteLine($"{data[0]} {data.Length} {value}");
```

`100 2 1`. Массив передан копией ссылки: изменение элемента видно снаружи. Присваивание `arr = new ...` меняет только локальную копию ссылки — `data` по-прежнему указывает на исходный массив длины 2. `int` скопирован — `value` не изменилась.
</details>

<details><summary><b>Что такое local function и чем она лучше private метода или лямбды?</b></summary>

Метод, объявленный внутри другого метода и видимый только в нём. По сравнению с private методом — не засоряет класс и явно показывает, что это вспомогательная логика одного метода. По сравнению с лямбдой — может быть рекурсивной, иметь `ref`/`out`/`params`, generic-параметры, и обычно не требует аллокации делегата. `static` local function запрещает захват внешних переменных — защита от случайных замыканий.
</details>
