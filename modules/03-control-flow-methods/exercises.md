## Задача 3. Свой TryParse  ·  ⏱ ~35 мин  ·  🟡 средняя

**Что сделать:** реализуйте `DurationParser.TryParse("1h30m", out var minutes)` → `true`, `90`. Форматы `"2h"`, `"45m"`, `"1H30M"`; ошибки (`"1h70m"`, `"30m1h"`, `"1h 30m"`, переполнение int) → `false` и `minutes = 0`.

**Зачем:** Try-паттерн (`bool TryXxx(..., out T result)`) — стандарт .NET для операций, которые могут «не получиться» без исключения. Вы научитесь писать `out`-методы, соблюдать их контракт и аккуратно разбирать строку.

**Файл:** `Module03.Tasks/DurationParser.cs`
**Тесты:** `dotnet test --filter "FullyQualifiedName~DurationParserTests"`

**Подумай / ответь письменно:**
- Чем `out` отличается от `ref`? Почему компилятор требует присвоить `out`-параметр на каждом пути выхода?
- Почему Try-метод лучше, чем метод, бросающий `FormatException`, для разбора пользовательского ввода? А когда лучше исключение?

## Задача 7. Бинарный поиск  ·  ⏱ ~60 мин  ·  🔴 сложная  ·  ⭐ со звёздочкой

**Что сделать:** без `Array.BinarySearch` и LINQ реализуйте в `BinarySearch`: `IndexOf` (итеративно, O(log n)), `LowerBound` (первый элемент ≥ target), `CountOccurrences` за O(log n) (осторожно с `int.MaxValue`!), `IntegerSqrt` — бинарный поиск «по ответу» без `Math.Sqrt` и без переполнения.

**Зачем:** «напишите бинарный поиск» — один из самых частых вопросов live coding, и его на удивление легко написать с ошибкой: переполнение в `(low + high) / 2`, бесконечный цикл из-за `low = mid`, off-by-one в границах. Интервьюер смотрит, как вы формулируете **инвариант** цикла и проверяете граничные случаи.

**Файл:** `Module03.Tasks/BinarySearch.cs`
**Тесты:** `dotnet test --filter "FullyQualifiedName~BinarySearchTests"`

**Подумай / ответь письменно:**
- Сформулируйте инвариант вашего цикла в `IndexOf`: что всегда верно для `low` и `high`?
- Почему `CountOccurrences` через `LowerBound(target + 1)` ломается на `int.MaxValue`?
- Сколько итераций нужно для массива из миллиона элементов? А из миллиарда?
